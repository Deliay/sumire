# 后台系统设计（V1）

本文档描述后台系统 V1 全部页面的界面细节：登录页 `/backdoor/login`、修改密码页 `/backdoor/change-password`、仪表盘 `/backdoor`、用户管理 `/backdoor/users`（内含增加用户 dialog）。视觉规则遵循 [[01-visual-identity.md]]，后台与书店共享同一套色彩/字体 token，但**不使用书店的氛围装饰**（雾气、藤蔓生长动画等环境动效）——后台是"店主的工作台"，气质从"雨夜氛围"转为"深夜灯下办公"，装饰克制、效率优先。

## 1. 设计定位

- 与书店同一世界观的另一面：书店是"给客人的店面"，后台是"店主自己的里屋"；
- 深色底延续（`--color-bg`），应援色点缀延续（`--color-primary`），蕾丝/藤蔓元素只保留**极少量静态点缀**（分隔细线、选中态描边），不使用动效；
- 信息密度高于书店：字号以 `--text-body` / `--text-small` 为主，控件紧凑；
- 全站（书店公开页 + 后台）共享的设计 token 抽到公共样式源，后台页面作为 `apps/bookstore` 的 `/backdoor` 路由区实现，直接引用同一份 token 与组件体系，保证 AC-11「视觉语言一致」可机械校验；
- 后台页面为静态页（SSG）+ 客户端守卫：任何受保护页面在会话/权限校验完成前只渲染**加载态**（居中紫花微光点 + "正在确认身份…"小字，`--color-ink-dim`），不闪烁内容。

## 2. 登录页 `/backdoor/login`

**目标**：一眼可识别是枝堇站的后台入口，同时明确"这不是公开页面"。

```mermaid
flowchart TD
    A[居中卡片] --> B[站点标识]
    B --> C[用户名输入框]
    C --> D[密码输入框]
    D --> E[登录按钮]
    E --> F[错误提示区]
```

### 2.1 布局

- 全屏 `100svh` 居中卡片，卡片宽 `22rem`（移动横向留白 `1.25rem`）；
- 背景：`--color-bg` 纯色 + 极淡的 `--color-flower` 径向微光（固定不动，非动效），呼应"头花的微光"；
- 卡片：`--color-bg-raised` 底 + `1px` `--color-vine` 细描边 + 圆角 `0.75rem`，顶部一条 `2px` 应援色 `#b4a6bf` 色带（对应书店页脚的应援色条）。

### 2.2 内容元素

| 元素 | 规格 |
|------|------|
| 站点标识 | 「枝堇」Noto Serif SC `--text-h1` + 花体 `Backdoor`（Cormorant Garamond，`--color-primary`），下方一行 `--color-ink-dim` 小字"老书屋的里屋 · 仅店主与伙计" |
| 用户名输入框 | 标签"用户名"，深色输入面 `--color-bg-soft`，`--text-body` |
| 密码输入框 | 标签"密码"，`type="password"`，其余同上 |
| 登录按钮 | 主按钮：`--color-primary` 填充 + `--color-ink-on-paper` 文字；提交中置灰禁用并显示"登录中…" |
| 错误提示区 | 按钮下方固定高度（防布局跳动），`--color-flower` 文字，内容固定为"账号或密码错误" |

### 2.3 状态

- **默认**：两个输入框空，按钮可用；
- **提交中**：按钮禁用、输入框只读，防止重复提交；
- **失败**：错误提示区显示"账号或密码错误"，密码框清空并聚焦，用户名保留；
- **成功**：按会话状态分流——`mustChangePassword: true` 跳转 `/backdoor/change-password`，否则跳转 `/backdoor`。

### 2.4 交互与无障碍

- 表单为原生 `<form>`，Enter 提交；输入框有 `label` 关联与 `autocomplete="username"` / `current-password`；
- 错误提示带 `role="alert"`，屏幕阅读器可感知；
- 焦点环使用 `--color-flower`；
- 页面上**不出现**任何注册、找回密码入口（AC-4）。

## 3. 修改密码页 `/backdoor/change-password`

**目标**：首次登录（或持初始密码）的账号在这里完成密码私有化；也是日常自助改密的入口。

### 3.1 布局与元素

- 与登录页同款居中卡片（宽 `24rem`），卡片标题「修改密码」；
- 强制改密场景顶部一条提示条（`--color-paper` 纸页底 + `--color-ink-on-paper` 文字）："首次进入里屋，请先换一把自己的钥匙"；
- 表单字段：
  - 原密码（`autocomplete="current-password"`）；
  - 新密码（`autocomplete="new-password"`）；
  - 确认新密码；
- **强度规则提示**：新密码框下方常驻一行 `--text-small` `--color-ink-dim`："至少 12 位，需同时包含字母、数字和符号"；输入过程中按满足项逐一点亮为 `--color-flower`（实时校验仅作提示，最终以后端校验为准）；
- 主按钮「确认修改」，提交中禁用；
- 错误提示区同登录页：强度不达标 / 两次输入不一致 / "新密码不能与原密码相同" / "原密码错误"，按后端 `{ error }` 文案展示。

### 3.2 状态与流转

- 强制改密会话到达此页时**不渲染后台布局**（无顶栏/侧栏），页面独立呈现，改密完成前无路可去；
- 改密成功：跳转 `/backdoor`，会话保持；
- 日常自助改密（从顶栏进入）：渲染在后台布局内，成功后回原页并提示"密码已更新"。

## 4. 后台布局 `/backdoor`

**目标**：标准管理界面骨架，为后续管理功能预留统一的导航与内容区；导航按角色渲染。

```mermaid
flowchart TD
    A[顶部栏 TopBar] --> B[主体区]
    B --> C[左侧导航 SideNav·按角色]
    B --> D[内容区 Content]
```

### 4.1 页面骨架

- **顶部栏**（固定，高 `3.5rem`）：`--color-bg-raised` 底 + 底部 `1px` `--color-vine` 细线。左侧「枝堇 · 后台」（Noto Serif SC 标题 + 花体 `Backdoor` 小字）；右侧依次：当前用户名 + 角色小字（`--color-ink-dim`，如"supersumire · 超管"）、「修改密码」文字链接、「登出」按钮；
- **左侧导航**（桌面宽 `12rem`）：`--color-bg` 底，与内容区以 `1px` `--color-vine` 分隔。选中态为 `--color-bg-soft` 填充 + 左侧 `3px` `--color-primary` 竖条。**导航项按角色渲染**：
  - 全部角色：「仪表盘」；
  - 仅超管：「用户管理」（增加用户入口内嵌于该页 dialog，不作为独立导航项）；
  - **不渲染任何未上线功能的占位项，不渲染当前角色无权使用的入口**（入口隐藏只是体验层，接口独立鉴权）；
- **内容区**：`--color-bg` 底，最大宽度 `64rem`，内边距 `2rem`（移动 `1.25rem`）。

### 4.2 响应式

| 断点 | 宽度 | 关键变化 |
|------|------|---------|
| 移动 | < 640px | 侧栏收起为顶部栏内菜单按钮，点击抽屉式展开；登出仍在顶部栏 |
| 桌面 | ≥ 640px | 侧栏常驻 |

后台为管理工具，桌面优先；移动端只需保证登录、改密、登出、查看仪表盘可用（PRD §4.3）。

### 4.3 仪表盘（默认内容页）

- 欢迎区：Noto Serif SC `--text-h1`「欢迎回来，老书屋的店主」+ `--color-ink-dim` 一行提示"这里还没有打理的事务——管理功能会陆续搬进来"；
- 欢迎区下方一条静态藤蔓细线（SVG，无生长动画，呼应书店 `VineDivider` 的静态形态）；
- 会话信息小块（`--text-small`，`--color-ink-dim`）：如"本次登录有效期至 <日期>"，让 7 天会话可感知；
- **无其他卡片、无占位功能**（AC-10）。

### 4.4 用户管理 `/backdoor/users`（仅超管）

- 页头：Noto Serif SC `--text-h2`「用户管理」+ 一行 `--color-ink-dim` 小字"里屋的钥匙登记册"；
- 主体为一张账号表（深色抬升面 `--color-bg-raised` + `--color-vine` 细描边）：
  - 列：用户名 / 角色 / 创建时间；
  - 角色列用胶囊标签呈现：超管 `--color-flower` 描边、管理员 `--color-primary` 描边、成员 `--color-vine` 描边（层级一目了然，不铺色）；
  - 创建时间用 `--text-small` `--color-ink-dim`，格式 `YYYY-MM-DD`；
- 表格右上放「增加用户 →」文字按钮，点击弹出创建用户 dialog（见 §4.5），不再跳转独立页面；
- 非超管访问此页：权限守卫引导回仪表盘（页面层），不渲染表格骨架。

### 4.5 增加用户 dialog（内嵌于 `/backdoor/users`）

- 触发：用户管理页「增加用户 →」按钮 → 弹出居中 modal（`--color-bg-raised` 底 + `--color-vine` 描边，宽 `24rem`，深色遮罩，点击遮罩/关闭按钮可收起）；
- dialog 标题「增加用户」+ 小字"新钥匙由你发放，请让对方首次进入时自行更换"；
- 表单字段（同登录页卡片语言）：
  - 用户名输入框；
  - 初始密码输入框 + 强度规则提示（同 §3.1 的常驻提示与逐项点亮）；
  - 角色选择：分段控件/单选组，**选项按当前用户角色限定**——超管见「成员 / 管理员 / 超级管理员」；
- 主按钮「创建用户」；成功后 dialog 内提示"已创建 <用户名>（<角色>），请告知其初始密码并提醒首次登录改密"，表单清空可继续创建，并刷新账号列表；
- 错误提示：用户名已存在 / 强度不达标 / 越权（接口 403 时提示"没有创建该角色的权限"）。

### 4.6 登出

- 顶部栏右侧文字按钮「登出」（`--color-ink-dim`，hover 变 `--color-ink`）；
- 点击后调用登出接口，成功即跳转登录页；无二次确认（会话可低成本重建，确认弹窗是噪音）；
- 登出仅失效当前端会话（AC-8），界面上无需体现多端状态。

## 5. 组件清单

| 组件 | 说明 | 关键状态 |
|------|------|---------|
| `LoginCard` | 登录卡片（标识 + 表单 + 错误区） | 默认 / 提交中 / 失败 |
| `ChangePasswordCard` | 改密卡片（含强度提示） | 强制改密（独立页）/ 日常改密（布局内）/ 提交中 / 失败 |
| `PasswordRulesHint` | 强度规则常驻提示（逐条点亮） | 未满足 / 部分满足 / 全部满足 |
| `TextField` | 带标签输入框 | 默认 / 聚焦 / 只读（提交中） |
| `PrimaryButton` | 主按钮（应援色填充） | 默认 / hover / 禁用 |
| `TopBar` | 后台顶部栏（含用户名与角色、改密、登出） | 桌面 / 移动（含菜单按钮） |
| `SideNav` | 左侧导航（按角色渲染） | 选中态；移动抽屉展开/收起 |
| `RoleBadge` | 角色胶囊标签 | 超管 / 管理员 / 成员 |
| `UserTable` | 用户管理账号表 | 加载 / 空 / 有数据 |
| `RoleSelect` | 角色选择（按权限限定选项） | 超管三选 / 管理员单项 |
| `CreateUserDialog` | 增加用户 modal（内嵌用户管理页） | 关闭 / 打开 / 提交中 / 失败 |
| `VineDivider`（静态复用） | 藤蔓分隔细线 | 静态，无动画 |
| `SessionNote` | 会话有效期小字块 | — |
| `GuardLoading` | 守卫加载态（紫花微光点 + 提示小字） | 校验中 |

图标沿用视觉识别的细线风格（Lucide，1.5px 描边）；V1 仅菜单按钮、登出需要图标。

## 6. 与书店的关系

| 维度 | 约定 |
|------|------|
| 设计 token | 共享同一份色彩/字体 token（单一来源），后台不自定义新色 |
| 装饰元素 | 书店：雾气/生长动画/蕾丝全量；后台：仅静态藤蔓细线与描边，无环境动效 |
| 互相引用 | 书店页脚「管理 →」为唯一入口（同站 `/backdoor` 路由）；后台不提供"返回书店"链接（浏览器回退即可，避免混淆公开/受保护边界） |
| 动效规范 | 后台仅保留控件级过渡（hover、禁用，≤ 200ms），同样尊重 `prefers-reduced-motion` |
