# 弹幕后台

**功能名称**: 弹幕后台（Danmaku Backdoor）
**PRD 版本**: v1.0
**创建日期**: 2026-08-16
**作者**: sumire workflow

## 一、背景与目标

### 1.1 背景

后台管理（`/backdoor`）目前已有登录、直播计划、用户管理等模块。运营/管理侧需要一个实时掌握直播间动态的工具：弹幕、醒目留言（SC）、礼物、上船（舰长/提督/总督）事件分散且时效性强，尤其是 SC 与上船需要逐条确认处理（已读管理）。

内网服务已提供直播事件数据：

- 历史事件检索：`http://vtuber.internal.fffdan.com/api/b/live/1727076670/event/range`（分页，支持多个 `type=` 筛选，如 `?type=danmaku&type=super_chat&type=gift&page=1&pageSize=50`）
- 实时事件推送：`http://vtuber.internal.fffdan.com/api/b/live/1727076670/event/subscribe`（SSE，支持多个 `type=` 筛选）

事件类型实测为 `danmaku`、`super_chat`、`gift`、`guard_buy`（上船）。数据本身不需要持久化，但已读状态等周边数据需要在后台 API 持久化。

### 1.2 目标

- 在后台管理页面新增「弹幕后台」模块，一站式查看直播间弹幕/SC/礼物/上船事件；
- 实时事件由内网 SSE 经后台 API 组合后鉴权对外提供，前端不直连内网服务；
- SC 与上船支持单条已读/取消已读与全部已读，已读状态持久化到后台 API；
- 信息流滚动稳定（新内容到达不打断当前阅读位置），支持回到顶部。

### 1.3 成功标准

- [ ] 后台侧边导航出现「弹幕后台」入口，未认证用户不可访问；
- [ ] 默认 3 栏展示：弹幕+礼物（弹幕在上、礼物在下上下分栏）、SC 一栏、上船一栏，栏位可配置；
- [ ] 实时事件经 SSE 推送后 1 秒内出现在对应信息流顶部；
- [ ] 双击 SC/上船单条记录可标记已读并同步后台，再次双击取消已读；「标记全部已读」一键生效；已读记录有置灰层；
- [ ] 用户向下滚动阅读时，新事件到达不导致滚动位置跳动；非顶部时显示「回到顶部」按钮；
- [ ] 所有信息流虚拟化渲染，万级历史数据加载不卡顿；
- [ ] 已读状态在刷新页面、更换浏览器会话后仍然保留（服务端持久化）。

## 二、用户分析

### 2.1 目标用户

- 后台管理员（admin / superadmin）：需要实时跟进直播间互动、确认 SC 与上船答谢事项的运营人员；
- member 角色：只读查看，不参与已读管理。

### 2.2 用户场景

| 场景 | 用户角色 | 目标 | 痛点 |
|------|----------|------|------|
| 直播进行中盯弹幕氛围 | admin | 实时看到最新弹幕 | 多平台切换、无聚合视图 |
| 答谢 SC 与上船 | admin | 逐条确认 SC/上船并标记已读 | 容易漏谢、重复谢 |
| 下播后回顾互动记录 | admin / member | 分页检索历史事件 | 无历史检索入口 |
| 高负载时段持续阅读 | admin | 滚动阅读历史时位置不被新事件顶乱 | 信息流跳动、找不到阅读位置 |

## 三、功能需求

### 3.1 功能概述

后台新增「弹幕后台」页面（`/backdoor/danmaku`），由后台 API 代理内网事件服务并鉴权对外提供：历史事件走分页检索，实时事件走 SSE 组合推送。前端按栏展示四类事件信息流，支持已读管理、栏位配置、虚拟化滚动与回到顶部。

### 3.2 功能列表

#### F1 后台 API：事件检索代理（鉴权）

**描述**: 后台 API 新增事件检索接口，代理内网 `event/range`，支持多 `type` 筛选与分页；响应中将上游原始 payload 归一化为稳定的事件模型，并合并服务端已读状态。接口需登录鉴权，不对公网匿名开放。

**用户价值**: 前端只面对一份稳定契约，不感知 B 站原始 payload 的混乱结构；历史数据可追溯。

**验收标准**:

- [ ] 未携带会话 Cookie 请求返回 401；
- [ ] 支持 `type=danmaku&type=super_chat&type=gift&type=guard_buy` 任意组合与 `page`/`pageSize` 分页；
- [ ] 每条事件包含：事件 ID、类型、发生时间、发送者（uid/昵称/头像/粉丝团牌子）、类型特有数据（弹幕内容 / SC 金额与颜色 / 礼物名称与价值 / 上船类型与金额数量）、`read` 标记；
- [ ] 上游不可用时返回统一中文错误结构 `{ error: string }`。

#### F2 后台 API：实时事件流（SSE 组合，鉴权）

**描述**: 后台 API 新增 SSE 接口，按请求 `type` 组合订阅内网 `event/subscribe`，将多类事件合并为一条事件流推送给前端，事件同样归一化并附带已读状态。需登录鉴权。

**用户价值**: 一个连接即可接收所需全部事件类型，前端不直连内网服务，权限可控。

**验收标准**:

- [ ] 未认证连接返回 401；
- [ ] 单连接支持多 `type` 组合订阅；
- [ ] 上游事件到达后实时转发，格式与 F1 单条事件模型一致；
- [ ] 连接断开由前端自动重连，重连后不重复推送已收事件（前端按事件 ID 去重）。

#### F3 后台 API：已读状态持久化

**描述**: 后台 API 持久化 SC 与上船事件的已读状态（MongoDB），提供单条标记已读、单条取消已读、按类型全部标记已读三个写接口；已读状态在 F1/F2 响应中合并返回。事件数据本身不持久化。

**用户价值**: 已读进度跨会话、跨设备保留，答谢管理可靠；误标已读可撤销。

**验收标准**:

- [ ] 单条标记已读接口幂等（重复标记不报错）；
- [ ] 单条取消已读接口幂等，可撤销单条标记，也可单独撤销「全部已读」覆盖的条目；
- [ ] 全部已读接口按类型生效（SC / 上船各自独立）；
- [ ] 写接口 admin 及以上角色可用，member 403；
- [ ] 已读记录仅存事件 ID 与元信息，不存事件内容。

#### F4 展示组件：公共发送者组件

**描述**: 抽取公共「发送者」组件：头像 + 昵称 + 粉丝团牌子（牌名、等级、按牌子颜色渲染），点击头像或昵称跳转 `https://space.bilibili.com/{uid}`（新标签页）。四类事件条目统一复用。

**验收标准**:

- [ ] 点击头像/昵称新开标签页跳转对应 B 站空间；
- [ ] 无粉丝团牌子时不渲染牌子占位；
- [ ] 上游缺失头像（如上船事件）时展示兜底头像，不出现破图。

#### F5 展示组件：弹幕信息流

**描述**: 倒序信息流，新弹幕在第一条。每条包含发送者组件 + 弹幕内容。

**验收标准**:

- [ ] 新弹幕实时插入列表顶部；
- [ ] 用户向下滚动阅读时，新弹幕插入不影响当前可视内容（滚动条不跳）；
- [ ] 离开顶部后出现「回到顶部」按钮，点击回到最新；
- [ ] 列表虚拟化渲染。

#### F6 展示组件：SC 信息流

**描述**: 倒序信息流，两行结构：第一行发送者组件 + 金额；第二行 SC 内容。整条按数据中携带的颜色（背景渐变、文字色）渲染。支持双击单条标记已读、已读条目再次双击取消已读、「标记全部已读」按钮；已读条目加灰色置灰层。

**验收标准**:

- [ ] 颜色渲染取自事件数据（背景起始/结束色、文字色），不硬编码；
- [ ] 双击未读条目后条目立即置灰并同步后台，刷新后仍为已读；
- [ ] 再次双击已读条目取消已读（去除置灰）并同步后台，刷新后仍为未读；
- [ ] 对「全部已读」置灰的条目同样可双击单独取消已读；
- [ ] 「标记全部已读」后当前类型全部置灰；
- [ ] 列表虚拟化渲染，滚动稳定（同 F5）。

#### F7 展示组件：礼物信息流

**描述**: 倒序信息流，每条包含发送者组件 + 礼物名称 + 礼物价值（金额）。

**验收标准**:

- [ ] 新礼物实时插入列表顶部；
- [ ] 滚动稳定与「回到顶部」同 F5；
- [ ] 列表虚拟化渲染。

#### F8 展示组件：上船信息流

**描述**: 倒序信息流，每条包含发送者组件 + 船型（舰长/提督/总督）+ 金额 + 数量。已读交互同 F6（双击单条、全部已读、置灰层）。

**验收标准**:

- [ ] 船型按 `guard_level` 正确映射（3=舰长 / 2=提督 / 1=总督）；
- [ ] 已读交互与持久化行为同 F6；
- [ ] 列表虚拟化渲染。

#### F9 分栏布局与配置

**描述**: 页面为分栏布局，默认 3 栏：弹幕+礼物（弹幕在上、礼物在下上下分栏）、SC 一栏、上船一栏。栏位可配置（每栏展示的事件类型组合可调整），配置持久化在浏览器本地（localStorage）。

**验收标准**:

- [ ] 首次进入默认 3 栏：弹幕+礼物（上下分栏）| SC | 上船；
- [ ] 调整栏位配置后刷新页面保留；
- [ ] 窄屏（<1024px）下栏位纵向堆叠，不横向挤压。

### 3.3 用户操作流程

```mermaid
flowchart TD
    A[登录后台] --> B[侧边导航进入 弹幕后台]
    B --> C[页面加载: 拉取各类型历史事件 + 建立 SSE 连接]
    C --> D{实时事件到达}
    D -->|弹幕/礼物| E[插入对应信息流顶部, 滚动位置保持]
    D -->|SC/上船| F[插入对应信息流顶部, 未读高亮]
    F --> G{用户处理}
    G -->|双击单条(未读)| H[标记已读 -> 同步后台 -> 置灰]
    G -->|双击单条(已读)| H2[取消已读 -> 同步后台 -> 去除置灰]
    G -->|点击全部已读| I[该类型全部标记已读 -> 置灰]
    E --> J[向下滚动阅读历史]
    J --> K[回到顶部按钮 -> 回到最新]
```

### 3.4 页面/界面描述

| 页面 | 描述 | 关键元素 |
|------|------|----------|
| `/backdoor/danmaku` | 弹幕后台主页面，分栏信息流 | 栏容器（可配置）、弹幕+礼物列（上下分栏）、SC 列、上船列、每列「标记全部已读」（SC/上船列）、「回到顶部」悬浮按钮、栏位配置入口 |

### 3.5 异常与边界情况

| 情况 | 预期行为 |
|------|----------|
| 内网事件服务不可用 | 历史检索显示错误提示，可重试；SSE 自动重连，页面提示连接状态 |
| SSE 断连 | EventSource 自动重连；重连期间到过的历史事件可通过下拉刷新/重新加载补齐 |
| 上游 payload 缺字段（如上船无头像/牌子） | 兜底头像、不渲染牌子，不报错 |
| 重复事件（重连/历史与实时重叠） | 前端按事件 ID 去重 |
| 非金瓜子礼物（银瓜子） | 价值显示为 0 或不计金额，不误导 |
| 未配置 `NEXT_PUBLIC_API_BASE_URL` | 沿用后台既有口径：整个 `/backdoor` 404 |
| member 角色 | 可查看信息流，已读写操作 403 且前端不展示对应交互 |

## 四、非功能需求

### 4.1 性能

- 信息流全部虚拟化渲染，单类型万级历史事件滚动流畅（帧率不低于 30fps）；
- SSE 事件到达到渲染延迟 < 1s；
- 历史检索单页加载 < 2s（内网前提下）。

### 4.2 安全性

- 所有事件 API 需登录鉴权（Session-Cookie），未认证 401；已读写操作需 admin 及以上角色；
- 内网上游地址仅存在于服务端配置，不下发前端；
- CORS 沿用既有白名单 + credentials 口径。

### 4.3 兼容性

- 桌面现代浏览器（Chrome / Edge / Firefox 最近两个大版本）；
- 窄屏降级为纵向堆叠布局，不强制移动端完整体验。

## 五、依赖与约束

### 5.1 依赖

- 内网事件服务 `vtuber.internal.fffdan.com` 持续可用（仅服务端可访问）；
- 既有后台鉴权体系（Session-Cookie + Redis 会话 + RBAC）；
- 既有 MongoDB（已读状态持久化）。

### 5.2 约束

- 不持久化事件数据本身，仅持久化已读状态等周边数据；
- 站点为纯静态 SSG，后台守卫维持客户端会话守卫模式，不引入服务端渲染；
- 档案与展示信息以官方公开信息为准，禁止二次设定；
- 未上线功能不得在 UI 显示占位入口。
