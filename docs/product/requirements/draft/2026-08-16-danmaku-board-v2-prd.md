# 弹幕看板二期

**功能名称**: 弹幕看板二期（Danmaku Board v2）
**PRD 版本**: v1.0
**创建日期**: 2026-08-16
**作者**: sumire workflow

## 一、背景与目标

### 1.1 背景

「弹幕后台」一期（[[2026-08-16-danmaku-backdoor-prd]]）已上线：后台 `/backdoor/danmaku` 聚合直播间弹幕/SC/礼物/上船事件，支持分栏配置、混排/分节布局、已读管理与视口自适应，现态以 `docs/product/spec/danmaku.md` 为准。

一期投入使用后，运营侧提出四点改进：

1. 模块定位是「监控看板」而非「管理后台」，现名「弹幕后台」易与后台管理系统混淆，文案应改为「弹幕看板」；
2. 默认分栏信息密度与处理动线不合理：SC 与上船同属「需答谢处理」的已读管理类事件，应分节聚合在一栏并置于视线焦点；弹幕与礼物属氛围类事件；
3. 礼物条目仅有文字（名称+数量+价值），扫读时难以快速识别具体礼物，需要渲染礼物图标；
4. 上船事件中舰长/提督/总督三档身份差异大（价格差一个数量级），需要在条目上有可区分的视觉特写，但不能喧宾夺主。

### 1.2 目标

- 后台全部展示文案由「弹幕后台」更名「弹幕看板」（路由不变）；
- 默认分栏按二期口径调整：三栏「礼物 | 上船+SC（分节） | 弹幕」，两栏「上船+SC（分节） | 礼物+弹幕（混排）」，单栏不变；
- 礼物条目渲染礼物图标，缺图时不破图、不占位错乱；
- 上船条目按船型（舰长/提督/总督）做克制的视觉特写，等级一眼可辨。

### 1.3 成功标准

- [ ] 侧边导航、页面标题等全部展示文案为「弹幕看板」，不再出现「弹幕后台」字样（代码注释、历史文档除外）；
- [ ] 无存量栏位配置（或配置损坏回退）的用户：桌面三栏为「礼物 | 上船+SC（分节） | 弹幕」；平板选择 2 栏时为「上船+SC（分节） | 礼物+弹幕（混排）」；单栏布局不变；
- [ ] 礼物条目在图标可用时渲染礼物图标，加载失败或上游缺图时条目布局不破；
- [ ] 舰长/提督/总督条目有逐级区分的船型特写（如徽章+船型名强调），无动画、无高饱和大面积色块等夸张效果；
- [ ] 一期既有能力零回归：已读管理、虚拟化滚动、视口自适应、栏位配置持久化。

## 二、用户分析

### 2.1 目标用户

- 后台管理员（admin / superadmin）：直播盯屏与答谢处理的主要使用者；
- member 角色：只读查看。

### 2.2 用户场景

| 场景 | 用户角色 | 目标 | 痛点（一期） |
|------|----------|------|------|
| 直播盯屏总览 | admin | 一眼区分「需处理」（SC/上船）与「氛围」（弹幕/礼物） | SC 与上船混排难扫读；默认栏序不符合处理动线 |
| 答谢处理 | admin | 按船型区分答谢优先级（总督 > 提督 > 舰长） | 船型仅文字 chip，等级差异不直观 |
| 礼物致谢 | admin | 快速识别具体礼物（如认出高价礼物） | 礼物只有名称文字，扫读慢 |
| 模块认知 | 全部 | 理解该模块是直播监控看板 | 「弹幕后台」命名易误解为配置后台 |

## 三、功能需求

### 3.1 功能概述

本期为弹幕看板的展示层增强：文案更名、默认分栏调整、礼物图标渲染、上船船型特写。除礼物图标需在契约中补充字段外，其余均为前端改造；事件检索/SSE/已读接口不变。

### 3.2 功能列表

#### F1 文案更名：弹幕后台 → 弹幕看板

**描述**: 后台管理内该模块的全部用户可见文案由「弹幕后台」改为「弹幕看板」，包括侧边导航项、页面标题（含全屏模式页头）、浏览器标签页标题（如有）。路由保持 `/backdoor/danmaku` 不变。

**验收标准**:

- [ ] 侧边导航显示「弹幕看板」，点击进入 `/backdoor/danmaku`；
- [ ] 页面标题与全屏模式页头均为「弹幕看板」；
- [ ] 用户可见界面中不再有「弹幕后台」字样；
- [ ] 既有书签/链接（`/backdoor/danmaku`）不受影响。

#### F2 默认分栏二期

**描述**: 调整无配置/配置损坏时的默认栏位分布与「视图栏」选择器各栏数预设：

- 三栏（默认，桌面）：「礼物 | 上船+SC（分节） | 弹幕」——中间栏上船节在上、SC 节在下，上下分节而非混排；
- 两栏（平板可选）：「上船+SC（分节） | 礼物+弹幕（混排）」——第一栏上船节在上、SC 节在下分节，第二栏礼物与弹幕按时间混排；
- 单栏（窄屏/可选）：不变（全部四类混排）。

存量用户已保存的栏位配置属个人偏好，不受本期变更影响（不强制迁移）。

**验收标准**:

- [ ] 清除本地配置后首次进入：桌面（≥1024px）三栏为「礼物 | 上船+SC（分节） | 弹幕」；
- [ ] 平板（640–1023px）选择 2 栏：「上船+SC（分节） | 礼物+弹幕（混排）」；
- [ ] 单栏预设保持「全部四类混排」不变；
- [ ] 已有自定义栏位配置的用户刷新后配置保持原样；
- [ ] 「配置栏位」勾选面板与混排/分节切换对新预设同样生效。

#### F3 礼物图标渲染

**描述**: 礼物条目在礼物名前渲染礼物图标（来源为上游事件数据中携带的图标 URL）。图标尺寸固定、不参与布局挤压；上游缺图或加载失败时隐藏图标（不显示破图），条目其余内容不变。

**验收标准**:

- [ ] 上游事件携带图标 URL 时，礼物条目渲染对应图标；
- [ ] 图标加载失败或上游未携带时不渲染图标，无破图、无布局抖动；
- [ ] 虚拟化列表中图标尺寸固定，滚动位置锚定行为不受影响；
- [ ] 图标按需懒加载，不阻塞列表渲染。

#### F4 上船船型特写

**描述**: 上船条目按船型（舰长/提督/总督）做克制的视觉特写：船型标识（徽章 + 船型名）在一级视觉上可区分三档等级，沿用一期船型配色（舰长蓝/提督紫/总督红）与本地徽章素材，特写限于徽章图标与字级/字重强调，不引入动画、光效或大面积高饱和色块。

**验收标准**:

- [ ] 舰长/提督/总督条目在扫读时一眼可辨等级（徽章 + 船型名强调逐级区分）；
- [ ] 未知船型（上游等级缺失/非法）回退既有样式，不渲染徽章；
- [ ] 已读置灰、「New」标记、双击已读交互行为不变；
- [ ] 特写样式不影响虚拟化行高稳定性（无布局抖动）。

### 3.3 页面/界面描述

| 页面 | 描述 | 关键元素 |
|------|------|----------|
| `/backdoor/danmaku` | 弹幕看板主页面（文案更名） | 侧栏「弹幕看板」导航项、页头「弹幕看板」标题、默认三栏「礼物 | 上船+SC（分节） | 弹幕」、礼物条目图标、上船条目船型特写 |

### 3.4 异常与边界情况

| 情况 | 预期行为 |
|------|----------|
| 存量用户已存一期栏位配置 | 保持原样，不迁移不覆盖（个人偏好） |
| 上游礼物事件无图标 URL | 不渲染图标，条目布局不破 |
| 礼物图标加载失败/超时 | 隐藏图标，不显示破图 |
| 上游船型等级非法（非 1/2/3） | 回退既有样式（沿用上游名称），不渲染徽章 |
| 旧存储栏位配置缺 `mode` 字段 | 沿用一期兼容口径：缺省按分节处理 |

## 四、非功能需求

### 4.1 性能

- 礼物图标懒加载且尺寸固定，不影响信息流滚动帧率（不低于 30fps）与滚动锚定行为；
- 船型特写为静态样式，无每帧计算。

### 4.2 安全性

- 礼物图标 URL 由服务端归一化透传，前端仅作 `<img>` 渲染，不执行任何脚本；沿用既有鉴权口径（无新增接口权限变更）。

### 4.3 兼容性

- 同一期：桌面现代浏览器最近两个大版本；视口自适应断点不变（<640 / 640–1023 / ≥1024）。

## 五、依赖与约束

### 5.1 依赖

- 上游事件服务礼物 payload 携带图标字段（如缺失需以实测样本确认，缺图按 F3 兜底）；
- 一期弹幕看板全部既有能力（契约 `contract/live-events.openapi.yaml`、栏位配置、已读管理）。

### 5.2 约束

- 路由 `/backdoor/danmaku` 不变；已读管理、虚拟化滚动、视口自适应零回归；
- 上船特写「稍作特写，但不夸张」：不加动画、光效、大面积高饱和色块；
- 存量栏位配置不强制迁移；
- 未上线的功能不得在 UI 中显示占位入口。

## 六、后续可能（本期不做）

- 礼物图标本地化缓存/代理（防盗链与加载提速）；
- 上船续费/开通区分展示；
- 高价礼物特效提示。
