# 弹幕看板礼物金额筛选

**功能名称**: 弹幕看板礼物金额筛选（Danmaku Gift Min-Price Filter）
**PRD 版本**: v1.0
**创建日期**: 2026-08-17
**作者**: sumire workflow

## 一、背景与目标

### 1.1 背景

弹幕看板（`/backdoor/danmaku`）已上线两期，现态以 `docs/product/spec/danmaku.md` 为准：礼物事件与弹幕/SC/上船聚合展示，金额分档配色（<10 灰 / 10–99 蓝 / 100–500 金 / >500 红）。

运营盯屏时，低价小礼物（辣条、小心心等）在礼物栏中数量大、价值低，淹没了需要关注的中高价礼物。上游直播事件服务的检索接口已支持 `minPrice` 参数（如 `GET /api/b/live/1727076670/event/range?pageSize=1&type=gift&page=1&minPrice=1`），可在服务端过滤低于最低价值的礼物事件。

### 1.2 目标

- 弹幕看板提供「礼物筛选」入口，运营可设定最低礼物价值（元），礼物信息流只展示价值不低于该阈值的礼物事件；
- 阈值设定交互为「滑动条 + 输入框」双控件同步，范围 0–100，步进 0.1；
- 历史检索与实时推送两种来源的礼物事件均按阈值过滤；
- 阈值为 0 时不筛选（等同不过滤），看板其余类型事件（弹幕/SC/上船）不受任何影响。

### 1.3 成功标准

- [ ] 看板面板上可见「礼物筛选」按钮，点击弹出小窗口，内含「最低礼物价值」label、滑动条与输入框；
- [ ] 滑动条范围 0–100、步进 0.1，与输入框双向同步（任一侧修改另一侧即时跟随）；
- [ ] 设定阈值后，礼物栏历史事件重新检索且只含价值 ≥ 阈值的礼物；实时到达的低价礼物不再插入列表；
- [ ] 阈值为 0 时行为与现状完全一致（不筛选）；
- [ ] 弹幕/SC/上船事件的检索、展示、已读管理零回归。

## 二、用户分析

### 2.1 目标用户

- 后台管理员（admin / superadmin）：直播盯屏与答谢处理的主要使用者；
- member 角色：只读查看，同样受益于信息降噪。

### 2.2 用户场景

| 场景 | 用户角色 | 目标 | 痛点（现状） |
|------|----------|------|--------------|
| 直播盯屏 | admin | 关注有答谢价值的中高价礼物 | 低价小礼物刷屏，高价礼物被淹没 |
| 礼物致谢 | admin | 快速定位需要致谢的礼物 | 需在大量低价礼物中人工扫读 |
| 日常围观 | member | 浏览礼物动态 | 信息密度低、噪音大 |

## 三、功能需求

### 3.1 功能概述

在弹幕看板面板新增「礼物筛选」按钮，点击弹出小窗口（弹层），通过滑动条与输入框设定最低礼物价值。阈值作用于全部含礼物类型的栏：历史检索请求携带阈值（经服务端透传上游 `minPrice`），实时推送的低价礼物事件在前端过滤。阈值为 0 表示不筛选。

### 3.2 功能列表

#### F1 「礼物筛选」入口与弹层

**描述**: 弹幕看板面板上新增「礼物筛选」按钮（位于栏位区上方工具区，与连接状态提示同级）。点击按钮弹出一个小窗口（弹层），再次点击按钮或点击弹层外区域关闭。弹层内容：

- 一个 label：「最低礼物价值」；
- 一个滑动条（slider）：最小值 0，最大值 100，步进 0.1；
- 一个输入框：接受数值输入，与滑动条表示同一值。

滑动条与输入框双向同步：拖动滑动条输入框即时更新；输入框输入合法值时滑动条即时跟随。输入框失焦/提交时对非法输入（非数字、越界）夹取到 [0, 100] 并按 0.1 步进取齐。

**验收标准**:

- [ ] 面板可见「礼物筛选」按钮，点击弹出含「最低礼物价值」label、滑动条、输入框的小窗口；
- [ ] 滑动条 min=0、max=100、step=0.1；
- [ ] 滑动条与输入框值双向同步；
- [ ] 输入非法值（越界/非数字）时夹取到合法范围，不产生异常状态；
- [ ] 弹层可关闭（再点按钮或点击外部），关闭后阈值保持生效。

#### F2 礼物历史检索按阈值过滤

**描述**: 阈值大于 0 时，看板对所有「礼物」类型的历史检索请求（首屏与滚动加载更多）携带最低价值参数，服务端透传上游 `minPrice`，返回结果仅含价值 ≥ 阈值的礼物事件。阈值为 0 时不携带参数（与现状一致）。修改阈值后，各栏礼物分节按新阈值重新检索（页码重置到第 1 页）。

**验收标准**:

- [ ] 阈值 > 0 时礼物历史检索只返回价值 ≥ 阈值的礼物事件；
- [ ] 阈值 = 0 时检索行为与现状一致（不带筛选参数）；
- [ ] 修改阈值后礼物分节自动按新阈值重新加载，分页从第 1 页重新开始；
- [ ] 滚动加载更多沿用当前阈值。

#### F3 实时礼物事件按阈值过滤

**描述**: 实时推送（SSE）到达的礼物事件，价值低于当前阈值时不插入任何栏的列表；阈值变化前已展示的低价礼物不追溯移除（下次重新检索时自然收敛）。

**验收标准**:

- [ ] 阈值 > 0 时，实时到达的价值 < 阈值的礼物不出现在列表中；
- [ ] 价值 ≥ 阈值的实时礼物正常插入栏顶（含「回到顶部」锚定行为不变）；
- [ ] 调低阈值后新到达的低价礼物恢复展示。

#### F4 阈值持久化

**描述**: 最低礼物价值阈值持久化在浏览器 localStorage，刷新/重开页面后保持；存储损坏（非法值）时回退为 0（不筛选）。

**验收标准**:

- [ ] 设定阈值后刷新页面，阈值保持生效；
- [ ] 存储值非法时回退 0 不筛选，页面不报错。

### 3.3 页面/界面描述

| 页面 | 描述 | 关键元素 |
|------|------|----------|
| `/backdoor/danmaku` | 弹幕看板主页面 | 「礼物筛选」按钮 + 弹层（label「最低礼物价值」、滑动条 0–100 步进 0.1、数值输入框） |

### 3.4 异常与边界情况

| 情况 | 预期行为 |
|------|----------|
| 阈值为 0 | 不筛选，行为与现状完全一致 |
| 输入框输入非数字/越界值 | 夹取到 [0, 100] 并按 0.1 步进取齐，不报错 |
| localStorage 存储损坏 | 回退 0（不筛选） |
| 上游/服务端检索失败 | 沿用既有错误态与重试入口，不因筛选参数改变 |
| 无礼物类型的栏位配置 | 阈值可设定但无可见效果（不产生错误） |
| 阈值修改瞬间有在途检索请求 | 旧阈值结果作废（沿用既有检索代际机制），以新阈值结果为准 |

## 四、非功能需求

### 4.1 性能

- 滑动条拖动不逐帧触发检索：仅阈值最终落定（输入提交/弹层交互结束口径的实现细节以技术方案为准）后重新检索；
- 阈值状态为轻量客户端状态，不影响信息流滚动与虚拟化行高。

### 4.2 安全性

- 筛选参数经服务端校验（非法值 400），客户端不直接接触上游地址；沿用既有鉴权口径（检索 member+），无新增接口权限变更。

### 4.3 兼容性

- 同既有口径：桌面现代浏览器最近两个大版本；视口自适应断点不变，窄屏单栏布局下「礼物筛选」入口同样可用。

## 五、依赖与约束

### 5.1 依赖

- 上游直播事件服务检索接口支持 `minPrice` 参数（已确认：`GET /api/b/live/1727076670/event/range?...&type=gift&minPrice=1`）；
- 弹幕看板一期/二期全部既有能力（契约 `contract/live-events.openapi.yaml`、栏位配置、已读管理、SSE）。

### 5.2 约束

- 路由 `/backdoor/danmaku` 不变；弹幕/SC/上船事件行为零回归；
- 阈值上限 100（元），与滑动条范围一致；
- 筛选只作用于礼物类型，不影响其他类型事件的检索与展示；
- 未上线的功能不得在 UI 中显示占位入口。

## 六、后续可能（本期不做）
