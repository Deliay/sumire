# 弹幕检索

**功能名称**: 弹幕检索（Danmaku Search）
**PRD 版本**: v1.0
**创建日期**: 2026-08-20
**作者**: sumire workflow

## 一、背景与目标

### 1.1 背景

「弹幕看板」（`/backdoor/danmaku`）现态（`docs/product/spec/danmaku.md`）支持四类直播事件的聚合信息流、分栏、弹幕合并、已读管理等，但只能按时间倒序翻页浏览，**没有任何关键词检索能力**。运营在需要回溯「某人说过什么」「某话题什么时候被讨论」时，只能逐页翻找，效率极低。

上游直播事件服务已交付关键词搜索接口：

```
GET http://vtuber.internal.fffdan.com/api/b/live/1727076670/event/search?stringCriteria=<关键词>&page=1&pageSize=20
```

已实测确认的行为：

- 返回 `{ total, page, pageSize, items }` 分页信封，`items` 为与 `event/range` 相同形状的原始事件信封（`roomId/type/occurredAt/liveSessionId/payload`），可由服务端既有归一化逻辑直接复用；
- `stringCriteria` 必填、非空、最长 200 字符，否则返回 400 `{"error":"..."}`；
- `page` 从 1 开始，非法值（如 0）由上游钳制为 1；
- 实测检索命中的均为弹幕（`DANMU_MSG`）事件。

### 1.2 目标

- 后台新增「弹幕检索」模块：顶部为搜索输入框，输入关键词后调用搜索接口；
- 搜索结果以**卡片横向排布的换行瀑布流**呈现（一行放不下自动换行）；
- 结果按时间倒序分页呈现，支持「加载更多」翻页；
- 复用既有归一化事件模型与鉴权口径（member 及以上可读）。

### 1.3 成功标准

- [ ] 弹幕检索入口在后台导航可达，页面顶部为搜索输入框；
- [ ] 输入关键词（1–200 字符）后发起检索，结果卡片横向排布、自动换行；
- [ ] 卡片展示发送者（头像/昵称/牌子/船型徽章）、弹幕内容、发生时间；内容中命中关键词高亮；
- [ ] 空关键词不发起请求；无结果、加载中、加载失败（含上游不可用 502）均有明确界面反馈；
- [ ] 「加载更多」追加下一页结果，直至无更多（达到 total）；
- [ ] 未登录 401、member 可检索；与既有弹幕看板功能零回归。

## 二、用户分析

### 2.1 目标用户

- 后台管理员（admin / superadmin）：回溯弹幕内容的主要使用者；
- member 角色：只读查看，同样可检索。

### 2.2 用户场景

| 场景 | 用户角色 | 目标 | 痛点（现况） |
|------|----------|------|------|
| 内容回溯 | admin | 查找某关键词相关的历史弹幕 | 只能按时间倒序逐页翻找 |
| 话题复盘 | admin | 复盘某话题在直播中的讨论过程 | 无法定位讨论发生的时段 |
| 观众发言查证 | admin | 查证某类发言的出现频次与上下文 | 无检索手段 |

## 三、功能需求

### 3.1 功能概述

本期新增后台「弹幕检索」模块（独立页面）与服务端搜索代理端点。前端顶部输入框 + 卡片瀑布流结果区；服务端在 live-events 域新增 `GET /api/live-events/search`，代理上游 `event/search` 并归一化为 `LiveEvent` 模型、合并已读状态。契约变更为 `contract/live-events.openapi.yaml` 新增端点。

### 3.2 功能列表

#### F1 弹幕检索页面与输入框

**描述**: 后台新增「弹幕检索」模块，路由 `/backdoor/danmaku/search`（作为弹幕看板的子页面），弹幕看板页头提供入口链接（返回看板的链接对称提供）：

- 页面顶部为搜索输入框（全宽、带搜索图标与清除按钮），placeholder 提示输入关键词；
- 输入停止 300ms 后自动发起检索（防抖），也可回车立即触发；输入变化即重置结果与页码；
- 关键词 trim 后为空时不发起请求，结果区回到初始引导态（提示输入关键词）；
- 关键词超长（>200 字符）时输入框限制输入或不发起请求并提示；
- 进行中的请求在关键词变化/组件卸载时取消（AbortController），避免乱序覆盖。

**验收标准**:

- [ ] 看板页头可见「弹幕检索」入口，检索页可返回看板；
- [ ] 输入停止 300ms 自动检索，回车立即检索；空关键词不请求；
- [ ] 快速连续输入只触发最后一次关键词的请求，旧请求被丢弃；
- [ ] 未登录访问跳转登录（沿用 backdoor 既有口径）。

#### F2 搜索结果卡片瀑布流

**描述**: 结果区为卡片横向排布的换行瀑布流（flex wrap，卡片定宽、按视口一行排多张、放不下自动换行）：

- 卡片内容：发送者（头像、昵称含罗马音、牌子、船型徽章）、弹幕内容、发生时间（沿用看板的时间格式）；命中关键词的子串在内容中高亮（`<mark>` 语义，token 色，不做花哨样式）；
- 弹幕表情（`emote`）按图片渲染，与看板一致；
- 结果按时间倒序排列（沿用上游返回顺序，不重排）；
- 状态反馈：加载中（骨架/加载指示）、无结果（「无匹配弹幕」）、加载失败（错误文案 + 重试按钮，含上游 502 口径）；
- 检索结果为只读展示：不提供双击已读等已读交互（已读状态不参与检索结果渲染）。

**验收标准**:

- [ ] 卡片横向排布、一行排满自动换行，窄屏（<640）自动降为单列/更少列；
- [ ] 关键词命中子串高亮；表情弹幕渲染图片；
- [ ] 加载中/无结果/失败三态各有明确反馈，失败可重试；
- [ ] 结果卡片无双击已读交互。

#### F3 分页加载更多

**描述**: 结果区分页加载：

- 每页 20 条（pageSize=20）；结果不足一页或已达 total 时不显示「加载更多」；
- 「加载更多」按钮置于结果区末尾，点击追加下一页（append，不重排已有结果）；
- 加载更多进行中防重复点击；失败时保留已有结果并允许重试该页。

**验收标准**:

- [ ] 首屏返回 20 条（不足则全部），显示总数（如「共 N 条」）；
- [ ] 「加载更多」正确追加 page+1 的结果，直至累计达到 total 后按钮消失；
- [ ] 追加失败不丢已有结果，可重试。

### 3.3 页面/界面描述

| 页面 | 描述 | 关键元素 |
|------|------|----------|
| `/backdoor/danmaku/search` | 弹幕检索页 | 顶部搜索输入框（防抖自动检索 + 回车）、结果总数、卡片瀑布流、加载更多按钮、三态反馈 |
| `/backdoor/danmaku` | 弹幕看板 | 页头新增「弹幕检索」入口链接 |

### 3.4 异常与边界情况

| 情况 | 预期行为 |
|------|----------|
| 关键词为空/纯空白 | 不发起请求，显示初始引导态 |
| 关键词 >200 字符 | 不发起请求并提示超长（或服务端 400 兜底展示错误） |
| 上游不可用/超时/返回非法 | 服务端 502，前端显示「搜索服务不可用」+ 重试 |
| 检索到 0 条 | 显示「无匹配弹幕」，不显示加载更多 |
| 关键词变化时旧请求未返回 | 取消旧请求，旧结果不得覆盖新结果 |
| 连续快速翻页点击 | 防重复点击，同页不重复追加 |
| 结果含表情/罗马音/牌子缺失等字段缺失 | 按看板既有兜底口径渲染 |
| 检索结果中包含非弹幕类型事件 | 上游实测仅返回弹幕；若未来混入其他类型，按既有归一化模型渲染为对应卡片样式（本期 UI 只承诺弹幕样式） |

## 四、非功能需求

### 4.1 性能

- 输入防抖 300ms，避免逐字符请求；请求可取消；
- 单页 20 条，无虚拟化需求（结果量受分页约束）；
- 卡片为静态渲染，无每帧计算。

### 4.2 安全性

- 搜索端点需登录且 member 及以上；服务端对 `stringCriteria` 做非空/长度校验（≤200），非法 400；
- 上游地址不出现在客户端可见位置（服务端代理，沿用既有口径）。

### 4.3 兼容性

- 同弹幕看板：桌面现代浏览器最近两个大版本；视口断点不变（<640 / 640–1023 / ≥1024）；
- 纯客户端交互，兼容静态导出（GitHub Pages）。

### 4.4 可访问性

- 输入框有 `label`/`aria-label` 与搜索语义；高亮使用 `<mark>`；
- 「加载更多」为可聚焦按钮，键盘可操作。

## 五、依赖与约束

### 5.1 依赖

- 上游搜索接口 `event/search`（已交付，行为见 1.1）；
- 服务端 live-events 域既有归一化（`normalize.ts`）与鉴权（`requireRole`）；
- 前端弹幕看板既有展示组件与格式化工具（`features/danmaku/`）。

### 5.2 约束

- 契约先行：`contract/live-events.openapi.yaml` 为单一事实源，先改契约再实现；
- Tailwind v4 `@theme` token 色，禁止硬编码色值；
- 未上线功能不得在 UI 显示占位入口（入口随功能一并上线）；
- 分支命名 `<type>/<slug>`，禁 rebase/squash。

## 六、后续可能（本期不做）

- 检索结果高亮多关键词、大小写/简繁归一；
- 检索历史记录与热门关键词；
- 检索结果内跳转看板上下文。
