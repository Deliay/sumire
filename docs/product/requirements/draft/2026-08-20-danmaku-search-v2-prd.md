# 弹幕检索 v2

**功能名称**: 弹幕检索 v2（Danmaku Search v2：入口与分类型渲染）
**PRD 版本**: v1.0
**创建日期**: 2026-08-20
**作者**: sumire workflow
**前置版本**: `docs/product/requirements/draft/2026-08-20-danmaku-search-prd.md`（v1，已上线）

## 一、背景与目标

### 1.1 背景

弹幕检索 v1 已上线（现态见 `docs/product/spec/danmaku.md`「弹幕检索」一节）：路由 `/backdoor/danmaku/search`，作为弹幕看板的子页面，仅能从看板页头的「弹幕检索」链接进入；检索结果不论事件类型，一律按弹幕卡片样式渲染。

v1 上线后的使用反馈（本期初版需求输入）：

1. **入口层级过深**：弹幕检索藏在弹幕看板页头链接里，不是后台导航的一级入口，发现性与可达性差；
2. **结果样式不分类型**：检索结果中混入 SC / 礼物 / 上船事件时，仍按弹幕卡片渲染，金额、SC 配色、船型徽章等类型特征信息丢失，与看板阅读体验不一致。

### 1.2 目标

- 弹幕检索入口提升为后台左侧导航一级菜单项，与「弹幕看板」**同级**；
- 检索结果按事件 `type` 分类型渲染：SC 按 SC 样式、弹幕按弹幕样式、礼物 / 上船按对应样式，与弹幕看板的类型渲染口径一致；
- 检索交互（防抖、分页、高亮、三态）与服务端接口保持不变，本期为纯前端调整。

### 1.3 成功标准

- [ ] 后台左侧导航可见「弹幕检索」菜单项，与「弹幕看板」同级，member 及以上可见；
- [ ] 在检索页时，导航选中态高亮「弹幕检索」而非「弹幕看板」（二者不混淆）；
- [ ] 检索结果中 SC 事件按 SC 样式渲染（金额分档配色 / scColors / 留言罗马音），礼物按礼物样式、上船按上船样式渲染，弹幕保持 v1 卡片样式；
- [ ] 弹幕与 SC 的文字内容命中关键词仍以 `<mark>` 高亮；
- [ ] 检索结果保持只读：无双击已读、无「New」标记、无弹幕合并；
- [ ] 与既有弹幕看板、弹幕检索 v1 功能零回归。

## 二、用户分析

### 2.1 目标用户

同 v1：后台管理员（admin / superadmin）与 member 角色（只读检索）。

### 2.2 用户场景

| 场景 | 用户角色 | 目标 | 痛点（v1 现况） |
|------|----------|------|------|
| 直接进入检索 | admin | 登录后台后一步直达弹幕检索 | 需先进看板再点页头链接，入口不可发现 |
| 检索 SC 回溯 | admin | 查找某关键词相关的高价值留言 | SC 被渲染成普通弹幕卡片，金额与配色信息丢失 |
| 检索结果速览 | admin | 快速区分结果中的事件类型 | 所有结果同一弹幕样式，类型不可辨 |

## 三、功能需求

### 3.1 功能概述

本期为弹幕检索的前端体验迭代，含两块变更：①后台左侧导航（`SideNav`）新增「弹幕检索」一级菜单项；②检索结果卡片按事件类型分发渲染，复用弹幕看板既有的四类条目组件（只读口径）。无契约与服务端变更。

### 3.2 功能列表

#### F1 左侧导航一级入口

**描述**: 后台左侧导航在「弹幕看板」之后新增「弹幕检索」菜单项：

- 菜单项链接 `/backdoor/danmaku/search`，可见角色与弹幕看板一致（superadmin / admin / member）；
- 导航选中态以当前路径精确区分：访问 `/backdoor/danmaku/search` 时高亮「弹幕检索」，访问 `/backdoor/danmaku` 时高亮「弹幕看板」，不得出现两项同时高亮；
- 弹幕看板页头既有「弹幕检索」链接与检索页「返回看板」链接保留不变；
- 窄屏下导航形态（横向排列）不变，新菜单项随既有布局自适应。

**验收标准**:

- [ ] 左侧导航可见「弹幕检索」，顺序位于「弹幕看板」之后；
- [ ] 点击「弹幕检索」进入检索页，且仅「弹幕检索」呈选中态；
- [ ] 点击「弹幕看板」进入看板页，且仅「弹幕看板」呈选中态；
- [ ] member 角色同样可见该菜单项。

#### F2 检索结果按类型渲染

**描述**: 检索结果按事件 `type` 分发到对应类型的渲染样式，与弹幕看板一致：

- `danmaku`：保持 v1 检索卡片样式（发送者 + 内容 + 时间 + 表情图 + 关键词高亮 + 船型淡色背景）；
- `super_chat`：按看板 SC 条目样式渲染——金额分档配色 / `scColors` 渐变背景、金额展示、留言正文（含罗马音 `contentRomaji`），留言正文中命中关键词的子串以 `<mark>` 高亮；
- `gift`：按看板礼物条目样式渲染（礼物名 / 数量 / 图标 / 金额）；
- `guard_buy`：按看板上船条目样式渲染（船型徽章与强调样式、数量）；
- 礼物与上船无文字内容字段，不做关键词高亮；
- 结果保持只读：不渲染双击已读交互、「New」标记、弹幕合并计数；
- 卡片瀑布流布局（横向排布自动换行、响应式列数）、分页「加载更多」、三态反馈、结果总数展示均保持 v1 口径不变；
- 未来若出现新事件类型，兜底按弹幕卡片样式渲染，不报错、不崩溃。

**验收标准**:

- [ ] 同一关键词检索结果中，SC / 礼物 / 上船 / 弹幕各按其类型样式呈现，可直观区分；
- [ ] SC 留言正文命中关键词高亮；弹幕内容高亮保持 v1 行为；
- [ ] 检索结果条目均无双击已读等交互；
- [ ] 瀑布流布局、加载更多、三态反馈无回归。

### 3.3 页面/界面描述

| 页面 | 描述 | 关键元素 |
|------|------|----------|
| 后台左侧导航 | 新增一级菜单项 | 「弹幕检索」项，位于「弹幕看板」之后，独立选中态 |
| `/backdoor/danmaku/search` | 弹幕检索页 | 结构不变；结果区卡片按事件类型分发渲染 |

### 3.4 异常与边界情况

| 情况 | 预期行为 |
|------|----------|
| 检索结果混入非弹幕类型 | 按 F2 分类型渲染；未知类型兜底弹幕卡片样式 |
| SC 缺少 `scColors` / 罗马音等可选字段 | 按看板既有兜底口径渲染 |
| 礼物 `gift.iconUrl` 缺失或加载失败 | 隐藏图标（沿用看板口径） |
| 上船 `guard.level` 未知 | 回退上游名称、不显示徽章（沿用看板口径） |
| 当前路径为检索页 | 仅「弹幕检索」菜单项高亮，「弹幕看板」不高亮 |
| 表情弹幕 | 渲染表情图片，无文字高亮（同 v1） |

## 四、非功能需求

### 4.1 性能

- 分类型渲染为静态组件切换，无额外请求与每帧计算；
- 类型条目组件复用看板既有组件，包体不显著增加（同 chunk 内既有依赖）。

### 4.2 安全性

- 无鉴权口径变化：检索页仍由 `(dashboard)` 布局会话守卫保护，接口仍 member 及以上。

### 4.3 兼容性

- 同 v1：桌面现代浏览器最近两个大版本；视口断点不变（<640 / 640–1023 / ≥1024）；
- 纯客户端交互，兼容静态导出（GitHub Pages）。

### 4.4 可访问性

- 导航新增项为可聚焦链接，`aria-label="后台导航"` 语义不变；
- 高亮继续使用 `<mark>`；各类型条目可访问性口径与看板一致。

## 五、依赖与约束

### 5.1 依赖

- 弹幕检索 v1（已上线）：`features/danmaku/search/` 模块、检索页路由；
- 弹幕看板既有类型条目组件：`DanmakuItem` / `SuperChatItem` / `GiftItem` / `GuardItem` 与 `Sender`、格式化工具；
- 后台导航组件 `features/backdoor/components/SideNav.tsx`。

### 5.2 约束

- 本期纯前端变更：不改契约、不改服务端；
- Tailwind v4 `@theme` token 色，禁止硬编码色值；
- 分支命名 `<type>/<slug>`，禁 rebase/squash；
- Spec 同步：上线 PR 内更新 `docs/product/spec/danmaku.md` 对应小节。

## 六、后续可能（本期不做）
