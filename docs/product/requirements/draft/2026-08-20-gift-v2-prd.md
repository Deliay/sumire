# 礼物事件 gift_v2 支持

**功能名称**: 礼物事件 gift_v2 支持（Gift v2 Support）
**PRD 版本**: v1.0
**创建日期**: 2026-08-20
**作者**: sumire workflow

## 一、背景与目标

### 1.1 背景

弹幕看板已上线（现态以 `docs/product/spec/danmaku.md` 为准）：服务端 `servers/api` 代理内网直播事件服务（`http://vtuber.internal.fffdan.com`），将上游四类事件（弹幕/SC/礼物/上船）归一化为契约 `LiveEvent` 供后台弹幕看板消费。

内网上游事件服务新增了 `gift_v2` 类型的礼物事件（仍为同一内网服务、同一事件检索/订阅接口，可直接经 `vtuber.internal.fffdan.com` 获取，无新增数据源）。当前服务端归一化层仅识别 `gift` 类型信封，`gift_v2` 事件会被当作未知类型丢弃——上游一旦切换/增发 `gift_v2`，看板礼物栏将漏事件。

### 1.2 目标

- 服务端识别并归一化上游 `gift_v2` 类型事件，并入既有 `gift` 事件流（检索与 SSE 均覆盖）；
- 对外完全透明：API 契约、前端弹幕看板零改动，gift_v2 事件以普通礼物事件形态呈现；
- 已读管理、礼物金额筛选等既有 gift 行为对 gift_v2 来源事件同样生效。

### 1.3 成功标准

- [ ] 上游下发 `gift_v2` 事件时，弹幕看板礼物栏正常展示（昵称/头像/牌子/礼物名/数量/金额/图标，与既有礼物事件一致）；
- [ ] 历史事件检索（`GET /api/live-events?type=gift`）同时返回 `gift` 与 `gift_v2` 来源事件，SSE 实时流同理；
- [ ] gift_v2 来源事件支持双击已读、金额筛选、金额分档配色，行为与 `gift` 来源一致；
- [ ] 契约 `contract/live-events.openapi.yaml` 与前端代码零变更；
- [ ] 既有四类事件处理能力零回归。

## 二、用户分析

### 2.1 目标用户

- 后台管理员（admin / superadmin）：直播盯屏与礼物答谢；
- member 角色：只读查看。

### 2.2 用户场景

| 场景 | 用户角色 | 目标 | 痛点（现状） |
|------|----------|------|------|
| 直播盯屏 | admin | 实时看到全部礼物事件 | 上游发 gift_v2 时礼物栏漏事件 |
| 礼物答谢 | admin | 按金额/礼物识别答谢对象，读后标记 | 漏掉的礼物无法答谢、无法已读 |
| 历史回溯 | admin/member | 翻页回看直播礼物记录 | 历史检索同样缺 gift_v2 事件 |

## 三、功能需求

### 3.1 功能概述

纯服务端改造：归一化层新增 `gift_v2` 信封识别与字段映射，检索/订阅上游时在请求 `gift` 的同时请求 `gift_v2`，归一化输出沿用既有 `gift` LiveEvent 模型（`type: "gift"`、eventId `gift:` 前缀不变）。契约、前端、数据库零变更。

### 3.2 功能列表

#### F1 gift_v2 事件归一化

**描述**: 服务端将上游 `gift_v2` 类型信封（`{ roomId, type: "gift_v2", occurredAt, liveSessionId, payload }`）防御式归一化为既有 `gift` LiveEvent：发送者（uid/昵称/头像/牌子/上船等级）、礼物（名称/数量/图标）、金额（金瓜子折算，银瓜子记 0）字段口径与既有 `normalizeGift` 一致；无法识别或关键字段缺失时返回 null + console.warn，绝不中断事件流。

**验收标准**:

- [ ] 合法 gift_v2 样本归一化产出 `type: "gift"` 的 LiveEvent，字段口径与既有礼物事件一致；
- [ ] eventId 以 `gift:` 前缀派生且稳定（同一上游事件重复到达/翻页重取时 eventId 不变）；
- [ ] 畸形/缺字段 gift_v2 事件被跳过并告警，不影响同批其他事件；
- [ ] 归一化单测覆盖正常、缺图标、银瓜子、畸形样本等用例（实测样本夹具）。

#### F2 检索与 SSE 并入 gift 流

**描述**: 客户端请求 `type=gift`（或缺省全类型）时，服务端向上游同时请求 `gift` 与 `gift_v2` 两种类型，归一化后统一以 `gift` 事件下发。契约 `type` 枚举不变（不接受 `gift_v2` 作为查询参数）。

**验收标准**:

- [ ] `GET /api/live-events?type=gift` 返回的礼物事件同时涵盖 gift / gift_v2 来源；
- [ ] SSE 订阅缺省全类型或 `type=gift` 时，上游 gift_v2 事件实时推送为 `type: "gift"`；
- [ ] 请求其他类型（danmaku/super_chat/guard_buy）不受影响；非法 type 仍 400。

#### F3 既有 gift 行为兼容

**描述**: gift_v2 来源事件在已读管理（双击已读/未读）、礼物金额筛选（minPrice）、前端金额分档配色等链路上与 gift 来源行为一致。

**验收标准**:

- [ ] gift_v2 来源事件 eventId 前缀为 `gift:`，`POST /api/live-events/read` 正常接受；
- [ ] `minPrice` 筛选对 gift_v2 来源事件同样生效；
- [ ] 前端无任何针对 gift_v2 的特判代码。

### 3.3 页面/界面描述

无界面变更。弹幕看板 `/backdoor/danmaku` 礼物栏照常展示，用户无法感知事件来自 gift 还是 gift_v2。

### 3.4 异常与边界情况

| 情况 | 预期行为 |
|------|----------|
| 上游未发 gift_v2（仅有 gift） | 行为与现状完全一致 |
| 上游 gift_v2 payload 结构与预期不符 | 该事件跳过 + console.warn，不中断检索/SSE 流 |
| 同一礼物上游同时发 gift 与 gift_v2 | 以技术提案实测结论为准（优先保证不丢事件；若实测证实双发，按提案去重口径处理） |
| gift_v2 缺礼物图标字段 | 不下发 `gift.iconUrl`，前端走既有无图标兜底 |
| 上游整体不可用 | 沿用既有口径：检索 502，SSE 指数退避重连 |

## 四、非功能需求

### 4.1 性能

- 归一化为纯函数映射，单事件开销与既有四类相当；检索请求上游时 type 参数增加一个，无额外往返。

### 4.2 安全性

- 上游地址仍收敛在服务端 env 注入，不出现在客户端；无新增对外端点、无鉴权口径变更。

### 4.3 兼容性

- 契约与前端零变更，旧前端直接受益；eventId 前缀不变，历史已读记录与水位线不受影响。

## 五、依赖与约束

### 5.1 依赖

- 内网上游事件服务已提供 `gift_v2` 类型（同一 `vtuber.internal.fffdan.com` 检索/订阅接口，无新增数据源）；
- gift_v2 payload 字段结构需以实测样本确认（作为开发前置：抓取真实样本落 `tests/fixtures/live-events/`）。

### 5.2 约束

- 契约 `contract/live-events.openapi.yaml` 与前端零变更（对前端透明是硬约束）；
- 归一化防御式解析、绝不抛错中断流的既定口径不变；
- 未上线的功能不得在 UI 中显示占位入口（本期无 UI 变更）。

## 六、后续可能（本期不做）

- 若上游后续以 gift_v2 完全取代 gift，评估下线旧 gift 归一化路径；
- gift_v2 若携带更丰富的礼物元数据（如礼物等级/动效），评估是否增补契约字段（届时另行立项）。
