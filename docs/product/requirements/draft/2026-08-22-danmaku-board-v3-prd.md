# 弹幕看板三期

**功能名称**: 弹幕看板三期（Danmaku Board v3）
**PRD 版本**: v1.0
**创建日期**: 2026-08-22
**作者**: sumire workflow

## 一、背景与目标

### 1.1 背景

弹幕看板（原「弹幕后台」，一期 [[2026-08-16-danmaku-backdoor-prd]] → 二期 [[2026-08-16-danmaku-board-v2-prd]]）已上线：`/backdoor/danmaku` 聚合直播弹幕/SC/礼物/上船事件，支持分栏配置、混排/分节布局、已读管理与视口自适应，现态以 `docs/product/spec/danmaku.md` 为准。

运营投入使用后继续沉淀三点改进诉求：

1. **默认分栏动线与信息密度需再调整**：若直播间内容以氛围类事件（弹幕、礼物）为主、需答谢类事件（SC、上船）为辅，现默认三栏「礼物 | 上船+SC（分节） | 弹幕」中，SC 与上船同栏分节，两栏预设为「上船+SC（分节） | 礼物+弹幕（混排）」，处理动线与辨识度仍不理想；应让「需要答谢/核对」的类型（上船、SC）与「氛围」类型（礼物、弹幕）按更自然的混排组合分组；
2. **SC 低价噪音**：SC 中存在大量金额 <30 元的长留言，扫读时与重点 SC 混杂，运营希望可选地隐藏低价 SC，专注高价值留言；
3. **「全部已读」入口分散**：SC 全部已读、上船全部已读按钮当前分散在各栏栏头（`FeedColumn`），多栏时操作入口不集中；希望整合到顶部「视图栏」区域为统一按钮组，空间不足时折叠为下拉菜单。

### 1.2 目标

- 调整默认分栏布局：无配置/配置损坏时的默认三栏为「礼物+上船（混排） | SC | 弹幕」，两栏预设为「上船+SC（混排） | 弹幕+礼物（混排）」，单栏不变；
- 新增 SC「隐藏钢镚」开关：开启后所有展示 SC 的面板不显示金额 <30 元的 SC，≥30 元正常显示，开关持久化；
- 顶部「视图栏」左侧整合「标记已读」按钮组：集中 SC 全部已读、上船全部已读（自栏头移入）与「隐藏钢镚」，空间不足时折叠为 dropdown 按钮组；
- 存量栏位配置与既有能力零回归。

### 1.3 成功标准

- [ ] 清除本地配置后首次进入：桌面（≥1024px）三栏为「礼物+上船（混排） | SC | 弹幕」；平板选择 2 栏为「上船+SC（混排） | 弹幕+礼物（混排）」；单栏为全部四类混排；
- [ ] 已存自定义栏位配置的用户刷新后配置保持原样（不强制迁移）；
- [ ] 「隐藏钢镚」开启后，任意展示 SC 的面板中金额 <30 元的 SC 不显示、≥30 元正常显示；关闭后恢复全部显示；刷新保持开关状态；
- [ ] 顶部「视图栏」左侧出现「标记已读」按钮组，内含上船全部已读、SC 全部已读（仅 admin+）与「隐藏钢镚」；空间不足时折叠为 dropdown 按钮组；
- [ ] SC 全部已读 / 上船全部已读 具备二次确认语义，行为与现网一致；已读、New 标记、虚拟化滚动、视口自适应、栏位配置持久化零回归。

## 二、用户分析

### 2.1 目标用户

- 后台管理员（admin / superadmin）：直播盯屏与答谢处理的主要使用者；
- member 角色：只读查看，同样受益于「隐藏钢镚」的信息降噪（不涉及已读交互）。

### 2.2 用户场景

| 场景 | 用户角色 | 目标 | 痛点（现状） |
|------|----------|------|--------------|
| 直播盯屏总览 | admin | 快速区分氛围事件与需答谢事件 | 默认栏序/组合仍不符合处理动线；SC 与上船分节占用两栏让信息密度不均 |
| SC 高价值专注 | admin / member | 略过低价 SC 留言 | 大量 <30 元 SC 长留言淹没高价值 SC |
| 收工时清已读 | admin | 一键集中处理全部已读 | 上船/SC 已读按钮分散在各栏栏头，需逐栏寻找 |
| 多栏操作入口 | admin | 入口集中、窄屏不挤压 | 栏头按钮多时换行/挤压 |

## 三、功能需求

### 3.1 功能概述

本期为弹幕看板展示层与操作入口的改造，无契约/接口变更：调整柱位默认与预设；新增 SC 隐藏钢镚全局开关（前端展示过滤）；将上船/SC 全部已读与隐藏钢镚整合到顶部「视图栏」的「标记已读」按钮组，支持空间不足时折叠为 dropdown。

### 3.2 功能列表

#### F1 默认分栏布局调整

**描述**: 调整「无配置 / 配置损坏」时的默认栏位分布与「视图栏」选择器各栏数预设：

- 三栏（默认，桌面）：**左「礼物+上船（混排）」 | 中「SC」 | 右「弹幕」**——上船与礼物按时间混排聚合在左栏，SC 独占中栏，弹幕独占右栏；
- 两栏（平板可选）：**左「上船+SC（混排）」 | 右「弹幕+礼物（混排）」**——上船与 SC 按时间混排，弹幕与礼物按时间混排；
- 单栏（窄屏/可选）：不变（全部四类混排）。

存量用户已保存的栏位配置属个人偏好，不受本期变更影响（不强制迁移）。

**验收标准**:

- [ ] 清除本地配置后首次进入：桌面（≥1024px）三栏为「礼物+上船（混排） | SC | 弹幕」，左栏礼物与上船按时间混排、中栏仅 SC、右栏仅弹幕；
- [ ] 平板（640–1023px）选择 2 栏：「上船+SC（混排） | 弹幕+礼物（混排）」；
- [ ] 单栏预设保持「全部四类混排」不变；
- [ ] 已有自定义栏位配置的用户刷新后配置保持原样；
- [ ] 「配置栏位」勾选面板与混排/分节切换对新预设同样生效。

#### F2 SC「隐藏钢镚」开关

**描述**: 看板新增「隐藏钢镚」开关。开启后，**所有展示 SC 的面板**（任意栏/节的 SC 信息流）不显示金额 <30 元的 SC，金额 ≥30 元的 SC 正常显示；关闭后恢复正常显示（不隐藏）。开关全局生效，作用于全部 SC 面板。

- 阈值口径：`price < 30`（元）隐藏，`price >= 30` 显示；
- 纯前端展示过滤：历史 SC 已全量加载，切换即时生效、不重新检索；实时到达的低价 SC 在开启状态下同样不插入展示（前端过滤）；
- 隐藏只影响「展示」，不影响已读状态、New 标记、SC 留言检索页（检索页为只读口径，独立于本开关）；
- 开关状态持久化在浏览器 localStorage，刷新/重开页面保持；存储损坏回退关闭（全部显示）；
- 开关入口位于顶部「视图栏」的「标记已读」按钮组内（见 F3）。

**验收标准**:

- [ ] 存在展示 SC 的任意面板，「隐藏钢镚」开启后 <30 元 SC 不显示、≥30 元 SC 正常显示；关闭后 <30 元 SC 恢复显示；
- [ ] 开关对**所有** SC 面板统一生效（多处 SC 同时隐藏）；
- [ ] 开启状态下实时到达的 <30 元 SC 不出现在列表；
- [ ] 切换开关即时生效、不触发重新检索；已读状态与 New 标记不受影响；
- [ ] 刷新后开关状态保留；localStorage 损坏时回退关闭、页面不报错。

#### F3 视图栏「标记已读」按钮组整合

**描述**: 在顶部「视图栏」（栏数选择器）**左侧**新增「标记已读」按钮组，集中展示组内操作：

- **上船全部已读**、**SC 全部已读**：将原分散在各栏栏头（`FeedColumn`）的「上船 全部已读 / SC 全部已读」按钮移入本组；仅 admin 及以上角色显示（member 无已读管理交互）；保留既有「二次确认」语义（点击进入确认态，超时复位）。
- **隐藏钢镚**（F2）：开关一并位于本组内。

**空间不足时折叠为 dropdown 按钮组**：当可用宽度不足（窄视口或按钮组挤压换行）时，按钮组折叠为单个「标记已读」触发钮，点击展开下拉菜单（菜单内含上船全部已读、SC 全部已读、隐藏钢镚）；宽度恢复时还原为平铺按钮。

栏头（`FeedColumn`）不再单独渲染上船/SC 全部已读按钮（已上收至全局组），「配置栏位」等栏头功能保留。

**验收标准**:

- [ ] 顶部「视图栏」左侧出现「标记已读」按钮组，正常运行宽度下平铺显示上船全部已读、SC 全部已读、隐藏钢镚；
- [ ] admin+ 可见「标记已读」组（含上船/SC 全部已读 + 隐藏钢镚）；member 不显示上船/SC 全部已读操作（隐藏钢镚作为展示偏好对登录角色可用，按角色可见性正确处理）；
- [ ] 「全部已读」点击进入确认态、二次确认后清空对应类型的已读与 New，行为与现网一致；
- [ ] 空间不足时折叠为 dropdown 按钮组，点击展开下拉菜单可操作各项；宽度恢复还原平铺；
- [ ] 全屏模式与普通视图的页头均提供该按钮组（与「视图栏」选择器同排）；
- [ ] 栏头不再出现上船/SC 全部已读按钮；其余栏头功能（弹幕合并、礼物筛选、配置栏位）不受影响。

### 3.3 页面/界面描述

| 页面 | 描述 | 关键元素 |
|------|------|----------|
| `/backdoor/danmaku` | 弹幕看板主页面（普通 + 全屏页头） | 默认三栏「礼物+上船（混排） | SC | 弹幕」、两栏预设「上船+SC（混排） | 弹幕+礼物（混排）」；「视图栏」左侧「标记已读」按钮组（上船/SC 全部已读 + 隐藏钢镚，空间不足折 dropdown） |

### 3.4 异常与边界情况

| 情况 | 预期行为 |
|------|----------|
| 存量用户已存栏位配置 | 保持原样，不迁移不覆盖（个人偏好） |
| localStorage 隐藏钢镚存储损坏 | 回退关闭（全部显示），页面不报错 |
| 金额等于 30 元 | 属于「≥30 元」，显示（不隐藏） |
| SC 事件缺金额字段（price 无/非法） | 按未知金额处理：不命中「<30 隐藏」判定，正常显示（保守展示） |
| 隐藏钢镚与礼物筛选（gift-min-price）叠加 | 两者彼此独立：礼物筛选作用于礼物类型；隐藏钢镚作用于 SC 类型；互不影响 |
| 无 SC 类型的栏位配置 | 隐藏钢镚可切换但无可见效果（不产生错误） |
| member 角色 | 无上船/SC 全部已读操作（不显示）；隐藏钢镚作为展示偏好按其角色可见性处理 |
| 极窄视口 | 「标记已读」按钮组折叠为 dropdown，不换行挤压布局 |

## 四、非功能需求

### 4.1 性能

- 隐藏钢镚为纯前端展示过滤（内存数组过滤），切换即时、无网络请求，不影响虚拟化滚动帧率（≥30fps）；
- dropdown 折叠/展开为轻量客户端状态，无额外监听开销。

### 4.2 安全性

- 无新增接口，沿用既有鉴权口径（检索/已读 member+、管理 admin+）；隐藏钢镚为纯客户端偏好，不新增服务端暴露。

### 4.3 兼容性

- 同既有口径：桌面现代浏览器最近两个大版本；视口自适应断点不变（<640 / 640–1023 / ≥1024）；SSG（GitHub Pages）全部客户端行为。

## 五、依赖与约束

### 5.1 依赖

- 弹幕看板一期/二期/礼物筛选全部既有能力（契约 `contract/live-events.openapi.yaml`、栏位配置、已读管理、SSE、gift-min-price）；
- SC 事件金额字段（`price`）为既有契约字段，可直接消费。

### 5.2 约束

- 路由 `/backdoor/danmaku` 不变；不新增契约/接口；已读管理、虚拟化滚动、视口自适应零回归；
- 上船/SC 全部已读自栏头移入顶部组，行为与二次确认语义不变（仅入口迁移）；
- 「未上线的功能不得在 UI 中显示占位入口」。

## 六、需求澄清（评审确认）

初版需求原文在描述「全部已读」整合时写作「上船全部已读、弹幕全部已读」。现态产品（`docs/product/spec/danmaku.md`）中「全部已读」仅支持 SC 与上船两类（`super_chat` / `guard_buy`，见 `DanmakuDashboard` 的 `READ_ALL_TYPES`），不存在「弹幕全部已读」。本 PRD 按现态一致的「**上船全部已读、SC 全部已读**」落地整合，将「弹幕」视为对「SC」的口误。如评审确认应新增「弹幕全部已读」，请在评审时提出并回写本 PRD。
