# 弹幕看板「SC/上船 悬停胶囊栏」

**功能名称**: 弹幕看板 SC/上船 悬停胶囊栏（Danmaku Hover Top Bar）
**PRD 版本**: v1.0
**创建日期**: 2026-08-23
**作者**: sumire workflow

## 一、背景与目标

### 1.1 背景

弹幕看板（`/backdoor/danmaku`）已上线多期：实时聚合直播间弹幕 / SC / 礼物 / 上船事件，支持分栏混排、虚拟化滚动、已读管理与实时 SSE 推送。运营盯屏时，SC 与上船是最需第一时间关注的「答谢类」事件，但当前它们以普通信息流条目混在栏内，被大量氛围类（弹幕/礼物）条目冲刷，**高价值 SC/上船缺乏持续置顶的视觉锚点**，运营在滚动阅读弹幕时容易错过顶部的答谢事件。

直播平台（Bilibili 直播 App/网页端）普遍提供「醒目留言置顶横幅」：SC 发送后以渐变横幅置顶展示一段时间（时长与金额相关），上船（舰长/提督/总督）亦有对应时长的置顶展示。希望在看板中复刻这一交互——在弹幕（及弹幕混排）栏的内容区顶部提供一个持续可见的悬停带，把「当前有效」的 SC/上船以醒目胶囊置顶展示，随时间衰减退出，方便运营第一时间捕捉与答谢。

### 1.2 目标

- 在弹幕 / 弹幕混排栏的内容区顶部（栏头之下、信息流之上）新增一个 3–4rem 高（约 48px）的悬停栏；
- 有 SC / 上船实时事件时，悬停栏内以**宽胶囊**展示该事件，多事件并存时**按礼物金额降序**排列；
- 每个胶囊带**悬停时长**，倒计时到期后自动消失——SC 用其 `time` 属性（秒），上船用固定时长（舰长 60s、提督 5 分钟、总督 1 小时）；
- 胶囊视觉分型：SC 胶囊使用 SC 的 `background` 渐变配色，上船胶囊使用船型强调色（沿用「上船」组件渲染配色）；
- **点击胶囊定位**：点击任一胶囊，将信息流滚动定位到该 SC/上船对应的那条记录，并让该记录**闪光**一次做视觉提示；再次点击已定位的胶囊可复核；
- 悬停栏为**展示增强**，不改变信息流内容、已读状态、栏位配置与既有能力，零回归。

### 1.3 成功标准

- [ ] 弹幕 / 弹幕混排栏内容区顶部出现悬停栏（约 48px 高）；无 SC/上船事件时栏区不占可见空间（不挤压信息流）；
- [ ] SC / 上船实时到达后，其胶囊在悬停栏内出现并置顶，多个并存时按金额降序排列；
- [ ] SC 胶囊展示「头像 + 醒目留言 + 价格」（如「[头像] 醒目留言 ￥30」），底色为对应 SC 的 `background` 渐变；SC 悬停时长取该事件的 `time`（秒）；
- [ ] 上船胶囊展示「头像 + 上船类型」，配色为舰长/提督/总督对应强调色；悬停时长舰长 60s / 提督 5min / 总督 1h；
- [ ] 各胶囊倒计时到期后自动消失；全部消失后悬停栏不占位；
- [ ] 点击任一 SC/上船胶囊，信息流自动滚动定位到对应该 `eventId` 的记录，且该记录播放一次闪光视觉提示（醒目但不遮挡内容）；
- [ ] 信息流、已读、SSE、栏位配置、视口自适应等既有能力零回归。

## 二、用户分析

### 2.1 目标用户

- 后台管理员（admin / superadmin）：直播盯屏与答谢互动的主要使用者，需第一时间看到高价值 SC/上船并及时答谢；
- member 角色：只读查看，同样受益于「SC/上船置顶」的信息焦点（悬停栏为纯展示，不涉及已读交互）。

### 2.2 用户场景

| 场景 | 用户角色 | 目标 | 痛点（现状） |
|------|----------|------|--------------|
| 直播盯屏答谢 | admin | 第一时间捕捉最新高价值 SC/上船 | SC/上船混在大量弹幕/礼物中，被冲刷难发觉 |
| 多栏同时关注 | admin | 跨栏快速扫到答谢事件 | 新 SC/上船在各自栏内，滚动中易错过 |
| 复播盯屏持续关注 | admin / member | 高价值答谢保持置顶一段时间 | 事件只出现一次，很快被新条目推出视野 |

## 三、功能需求

### 3.1 功能概述

本期为弹幕看板展示层增强：在弹幕 / 弹幕混排栏的内容区顶部新增**悬停胶囊栏**，将 SSE 实时到达的 SC / 上船事件以宽胶囊按金额降序置顶展示，各胶囊按其悬停时长倒计时消失。**点击胶囊**可滚动定位信息流到该 SC/上船对应记录并使其**闪光**提示。纯前端展示，不改变信息流内容与既有交互；仅需契约侧暴露 SC 悬停时长 `time`（秒）。

### 3.2 功能列表

#### F1 悬停胶囊栏

**描述**: 在弹幕 / 弹幕混排栏的内容区顶部（栏头与信息流之间）新增一个悬停栏容器：

- 高度 3–4rem（约 48px），宽度铺满栏内容区；位于 `FeedColumn` 栏头之下、`FeedSection` 信息流之上；
- 无有效胶囊（见 F2/F3）时该悬停栏整体不占可见空间（隐藏），不挤压信息流；
- 有 ≥1 个有效胶囊时显示，胶囊横向排列，**按礼物金额 `price` 降序**（金额相同按到达时间新者优先）。

**验收标准**:

- [ ] 弹幕栏内容区顶部出现约 48px 高悬停栏；无 SC/上船胶囊时悬停栏不占位、信息流顶格；
- [ ] 多个胶囊并存时按金额降序排列；金额相同新到达者靠前；
- [ ] 悬停栏不遮挡信息流内容、不影响虚拟化滚动。

#### F2 SC 胶囊

**描述**: SC（super_chat）实时事件到达后，在其所在栏的悬停栏内生成一个宽胶囊：

- **展示内容**: `用户头像 + "醒目留言" 四字 + 价格`，例如 `[头像] 醒目留言 ￥30`——头像取 `sender.face`（缺失时按既有 `Sender` 兜底首字）；「醒目留言」为固定四字文案；价格用 `formatPrice(price)`；
- **配色**: 使用 SC 的 `background` 开头相关属性——即 `scColors.backgroundStart → backgroundEnd` 线性渐变作为胶囊底色，`fontColor` 作为文字色（沿用 `SuperChatItem` 同款取色，`scColors` 缺失时按现有回退）；
- **悬停时长**: 取该 SC 事件的 `time` 属性（秒）。该属性来自上游 payload（当前服务端归一化未透传，见提案 §3，需经契约暴露）；`time` 缺失或非法时回退固定默认时长（见 §3.4 边界）；
- **到期消失**: 悬停时长倒计时归零后胶囊从悬停栏移除。

**验收标准**:

- [ ] SC 胶囊正确展示「头像 + 醒目留言 + 价格」，价格为对应 SC 金额；
- [ ] SC 胶囊底色为对应 SC 的 `background` 渐变（`backgroundStart→backgroundEnd`），文字色为 `fontColor`；
- [ ] SC 胶囊悬停时长等于该事件 `time`（秒），到期自动消失；
- [ ] `scColors`/`time` 缺失的 SC 不报错，按现有回退渲染、回退默认时长。

#### F3 上船胶囊

**描述**: 上船（guard_buy）实时事件到达后，在其所在栏的悬停栏内生成一个宽胶囊：

- **展示内容**: `用户头像 + 上船类型`——头像取 `sender.face`（guard_buy 上游无头像为 null，按 `Sender` 兜底首字）；上船类型用 `guardLevelName`（3=舰长 / 2=提督 / 1=总督），未知等级回退上游 `guard.name`；
- **配色**: 上船胶囊颜色沿用「上船」面板/组件渲染色——即 `guardLevelTone(level)`：舰长蓝（eye）/ 提督紫（flower）/ 总督红（crimson）；
- **悬停时长（固定）**: 舰长 60 秒、提督 5 分钟（300s）、总督 1 小时（3600s）；未知等级按舰长档（60s）；
- **到期消失**: 时长倒计时归零后从悬停栏移除。

**验收标准**:

- [ ] 上船胶囊正确展示「头像 + 上船类型」；
- [ ] 上船胶囊配色为对应船型强调色（舰长蓝/提督紫/总督红）；
- [ ] 悬停时长 舰长 60s / 提督 5min / 总督 1h，到期自动消失；
- [ ] `guard` 字段缺失/未知等级的 guard_buy 不报错，按回退处理。

#### F4 点击胶囊定位并闪光

**描述**: 点击任一 SC/上船胶囊，信息流定位到该胶囊对应的那条记录，并让该记录播放一次闪光视觉提示：

- **定位**: 点击胶囊后，将该胶囊对应 `eventId` 的记录滚动至信息流可视区内（居中或就近对齐）；若该记录已不在已加载列表（如被虚拟化回收或来自历史分页未加载），则同样按 `eventId` 在对应栏内做可见性处理，无法定位时静默不报错；
- **闪光**: 定位到目标记录后，给该行挂一个**一次性闪光**的视觉状态（醒目但不遮挡内容、不改变布局），闪光结束后自动复位，避免持续高亮干扰；
- **交互反馈**: 胶囊可点击（cursor 提示）；点击不改变已读状态、不触发其它副作用；对已经位于可视区的记录再次点击可重新触发一次闪光。

**验收标准**:

- [ ] 点击 SC/上船胶囊，信息流自动滚动定位到对应该 `eventId` 的记录；
- [ ] 目标记录播放一次闪光视觉提示，结束后自动复位、不遮挡内容、不改变布局（无跳动）；
- [ ] 目标记录位于信息流任意位置（顶部/中部/底部）都能被准确定位；
- [ ] 目标记录不在已加载列表时静默处理，不报错、不产生空白定位；
- [ ] 点击胶囊不影响已读状态、New 标记与既有滚动能力。

### 3.3 页面/界面描述

| 页面 | 描述 | 关键元素 |
|------|------|----------|
| `/backdoor/danmaku`（弹幕看板） | 弹幕及弹幕混排栏内容区顶部的悬停胶囊栏 | 约 48px 悬停带；SC 胶囊（渐变底色 + 头像 + 醒目留言 + 价格）、上船胶囊（船型强调色 + 头像 + 船型）；按金额降序；倒计时消失；点击胶囊定位对应记录并闪光 |

### 3.4 异常与边界情况

| 情况 | 预期行为 |
|------|----------|
| 无 SC/上船实时事件 | 悬停栏不可见、不占位 |
| SC `time` 缺失/非法 | 回退固定默认时长（缺省 60s），胶囊正常展示、不报错 |
| SC `scColors` 缺失 | 回退 `SuperChatItem` 既有缺省样式（中性底色 + 默认文字色） |
| guard_buy 无头像（face null） | 按 `Sender` 兜底渲染首字头像 |
| guard_buy `guard` 字段缺失/未知等级 | 展示上游 `guard.name`（无则仅头像），悬停时长按舰长档 60s |
| 多个 SC/上船并存 | 按金额降序排；相同金额新者优先 |
| 金额字段 `price` 缺失 | SC/上船胶囊按价格 0 参与排序（排末），不影响展示与计时 |
| 悬停栏与虚拟化/回顶/已读叠加 | 悬停栏为栏头定高区，不与信息流滚动争用；已读/New、滚动力、回到顶部不受影响 |
| 混排栏（既有上船+SC、礼物+…） | 悬停栏作用于**包含 SC 或上船类型的栏**，展示该栏 SSE 到达的 SC/上船 |
| 点击胶囊但目标记录不在已加载列表 | 静默处理，不报错、不留空白定位（记录可能被虚拟化回收或历史分页未加载） |
| 点击胶囊的闪光与滚动定位叠加 | 定位先滚动到可视区，再触发一次性闪光；闪光不改变布局、不跳动 |
| 点击胶囊后悬停栏已清空/该胶囊已到期 | 目标记录仍按 `eventId` 定位并闪光（胶囊清除不影响定位动作） |

## 四、非功能需求

### 4.1 性能

- 悬停胶囊为内存计时集合驱动，胶囊数量有限（同刻并存 SC/上船通常较少），倒计时用单一 interval 统一扫描，不逐胶囊设置 timer，避免定时器堆积；
- 不引入额外网络请求，不影响虚拟化滚动帧率（≥30fps），不动信息流数据。

### 4.2 安全性

- 无新增写接口；仅契约暴露 SC `time` 字段（沿用既有 `live-events` 检索/SSE 口径），不新增权限面。

### 4.3 兼容性

- 同既有口径：桌面现代浏览器最近两个大版本；静态导出（GitHub Pages）全部客户端行为；视口自适应断点不变（<640 / 640–1023 / ≥1024）。

## 五、依赖与约束

### 5.1 依赖

- 弹幕看板既有全部能力：栏位配置（`columns.ts`）、SSE 实时流（`useLiveEventStream`）、信息流渲染（`FeedColumn`/`FeedSection`）、SC 取色（`scColors`）、上船取色（`guardLevelTone`/`guardLevelName`）；
- SC 悬停时长 `time`（秒）为上游 `SUPER_CHAT_MESSAGE` payload 属性，需服务端归一化透传并经契约 `contract/live-events.openapi.yaml` 暴露（当前未透传）。

### 5.2 约束

- 路由 `/backdoor/danmaku` 不变；不改变信息流内容、已读语义与栏位配置；
- 「未上线的功能不得在 UI 中显示占位入口」；
- 视觉严格按 `docs/design/03-backdoor-design.md`：仅用 `@theme` token 色（SC 渐变/船型色为事件数据色，属内容色例外），后台不使用氛围动效，控件过渡 ≤200ms 且尊重 `prefers-reduced-motion`。

## 六、需求澄清（评审确认）

- **悬停栏作用范围**：初版需求写作「弹幕或弹幕混排栏」。现态看板栏位可自定义；本 PRD 落地为「**包含 SC 或上船类型的栏**」的内容区顶部都挂载悬停栏（默认三栏中 SC 独占中栏、上船在「礼物+上船」混排栏），并按该栏 SSE 到达的 SC/上船展示。如评审要求仅限弹幕/弹幕混排栏，请评审时提出。
- **SC 悬停时长 `time` 口径**：初版需求要求 SC 使用 `time` 属性（秒）。服务端归一化当前透传 `scColors`/`price` 但**未透传 `time`**；本 PRD 与提案约定新增契约可选字段 `time`（仅 super_chat）透传上游对应值，缺失时前端回退固定默认（60s）。`time` 的实际上游取值路径（`payload.data.time`）经调研为 B 站 SUPER_CHAT_MESSAGE 标准字段，见提案 §3。
- **上船无头像**：guard_buy 上游本就无头像（`face: null`），胶囊按 `Sender` 兜底首字渲染，属既有口径复用，不视为缺陷。
