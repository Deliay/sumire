# 弹幕看板「已读功能优化」

**功能名称**: 弹幕看板已读功能优化（Danmaku Read Interaction Optimization）
**PRD 版本**: v1.0
**创建日期**: 2026-08-23
**作者**: sumire workflow

## 一、背景与目标

### 1.1 背景

弹幕看板（`/backdoor/danmaku`）已上线已读管理若干期，现况以 `docs/product/spec/danmaku.md` 的「已读管理（admin+）」节为准：

- **已读切换方式**：双击 SC / 礼物 / 上船条目切换已读状态，乐观更新、失败回滚；member 无任何已读交互。
- **SC 文字区域**：SC 留言正文（含罗马音）可鼠标拖选复制；留言文本上的选择 / 双击不触发已读切换，条目其余区域的双击已读行为不变。
- **礼物已读**：产品 Spec 早已声明「双击 SC / 礼物 / 上船条目切换已读」，但实现中 `GiftItem` 从未接收 `onToggleRead`，**礼物已读实为缺失**（见 `docs/product/spec/danmaku.md` 已读节与 `FeedSection.renderItem`）；且顶部「标记已读」按钮组的「全部已读」仅支持 SC 与上船两类，礼物没有全部已读。

持续的交互体感诉求叠加为四点改进：

1. **礼物已读缺失**：礼物与 SC/上船同为「待答谢 / 待核对」类事件，应纳入同一套已读管理（含单条已读与「礼物全部已读」）；
2. **双击切换过重**：看板条目密集、滚动频繁，双击切换误触少但对运营的手势负担高，希望改为更轻的单击切换；
3. **SC 文字区域不可点击已读**：SC 留言目前仅点击条目非文字区才能已读，文字区被「可复制」隔离，已读操作需点中很小且固定的非文字区域，命中率低；希望 SC 留言文字区也响应单击已读，同时**不得破坏 SC 内嵌 B 站视频链接的点击 / hover 预览，以及用户头像 / 昵称跳转 B 站空间**这一既有能力（这些位置点击须「穿透」到 B 站，不触发已读）。

### 1.2 目标

- 礼物条目纳入已读管理：`GiftItem` 支持单条已读切换（乐观更新、失败回滚口径与 SC/上船一致），并支持「礼物全部已读」；
- SC / 礼物 / 上船条目的已读切换由**双击**统一改为**单击**；
- SC 留言文字区域（含罗马音）也支持单击已读——但 SC 内嵌 B 站**视频链接的点击与 hover 预览**、以及**用户头像 / 昵称跳转 B 站空间**必须正常穿透，不被单击已读吞掉；
- 既有能力（New 标记、隐藏钢镚、虚拟化滚动、栏位配置、SSE）零回归。

### 1.3 成功标准

- [ ] 礼物条目在 admin+ 下可单击切换已读，未读/已读置灰表现与 SC/上船一致；乐观更新、失败回滚提示对礼物同样生效；
- [ ] 顶部「标记已读」按钮组提供「礼物 全部已读」入口（admin+，二次确认语义与 SC/上船一致），清空礼物的已读；与 SC/上船全部已读并存、空间不足折叠为 dropdown；
- [ ] SC / 礼物 / 上船条目单击即切换已读（不再需要双击）；member 无任何已读交互不变；
- [ ] SC 留言文字区域（含罗马音）单击即可切换 SC 已读；
- [ ] SC 留言内嵌 B 站视频链接（BV 号）单击仍新开 B 站视频页、hover 仍触发视频预览卡片，均不被已读开关吞掉；
- [ ] SC 各处的用户头像 / 昵称点击仍新开 B 站用户空间（`space.bilibili.com/{uid}`），不被已读开关吞掉；
- [ ] 既有 New 标记、隐藏钢镚、虚拟化、栏位配置、SSE 零回归；`pnpm lint && pnpm test && pnpm build` 全绿。

## 二、用户分析

### 2.1 目标用户

- 后台管理员（admin / superadmin）：直播盯屏与答谢处理的主要使用者，需对 SC / 礼物 / 上船统一做已读管理；
- member 角色：只读查看，无已读交互（与后端 403 口径一致）。

### 2.2 用户场景

| 场景 | 用户角色 | 目标 | 痛点（现状） |
|------|----------|------|--------------|
| 礼物答谢核对 | admin | 礼物也能标记已读 | 礼物没有任何已读能力，答谢后无法归零未读状态 |
| 快速扫读标已读 | admin | 轻量、低误触地切换已读 | 双击切换手势重、且 SC 文字区不可点，需细瞄非文字区 |
| SC 已读 | admin | 点击 SC 留言即可已读 | 留言文字区被复制隔离，只能点上下窄条区域，命中率低 |
| SC 内超链跳转 | admin / member | 点 SC 里的 B 站视频 / 查看用户 | 若已读吞掉这些点击将无法跳转（必须穿透） |

## 三、功能需求

### 3.1 功能概述

已读交互改造 + 补齐礼物已读（单条与全部），含契约/服务端扩展：

- 已读切换交互由「双击」统一改为「单击」；
- 礼物纳入单条已读切换（沿用 admin+ 口径与乐观更新、失败回滚）；
- 新增「礼物全部已读」：契约 `read-all` 的 `type` 枚举加入 `gift`，后端 `READ_ALL_TYPES` 与前端 `ReadAllType`/「标记已读」按钮组同步支持，清空礼物类型已读（水位线口径与 SC/上船一致）；
- SC 留言文字区域加入单击已读响应域；
- 在所有会触发单击已读的条目中，**B 站视频链接（点击打开 / hover 预览）与用户头像 / 昵称（跳转空间）作为穿透元素**，其点击不得冒泡触发已读。

### 3.2 功能列表

#### F1 礼物条目已读管理

**描述**: 礼物条目（`GiftItem`）纳入与 SC/上船一致的已读管理：

- admin+ 下礼物条目可**单击**切换已读；`read=true` 时置灰（`opacity-60`），与 SC/上船已读表现一致；
- 切换为乐观更新、失败回滚并提示（复用 `DanmakuDashboard.toggleRead`）；
- member 不渲染任何已读交互（与后端 403 口径一致）。

**验收标准**:

- [ ] admin+ 下单击礼物条目即切换已读；`read=true` 置灰、再次单击取消已读；
- [ ] 礼物已读切换成功后刷新保持（服务端持久化）；失败时回滚并 toast 提示；
- [ ] member 下礼物条目不可点击已读。

#### F1b 礼物全部已读

**描述**: 顶部「标记已读」按钮组新增「礼物 全部已读」入口：

- 入口位于既有「标记已读」按钮组（上船全部已读 / SC 全部已读 / 隐藏钢镚）之列，admin+ 可见；二次确认语义与既有「全部已读」一致（点击进入确认态、超时复位）；
- 触发 `read-all`（`type=gift`），按礼物类型最新事件写入水位线，清空礼物的已读与未读展示；
- 后端 `READ_ALL_TYPES` 支持 `gift`，契约 `read-all` 的 `type` 枚举加入 `gift`；礼物上游类型为 `gift`+`gift_v2`，全部已读须展开为上游类型检索最新事件（`toUpstreamTypes` 口径，与检索/SSE 一致，避免仅查 `gift` 漏掉 `gift_v2` 的最高水位）；
- 与 SC/上船全部已读一致：水位线只前进不后退；该类型当前无事件时不写水位线、返回 `marked=0`。

**验收标准**:

- [ ] admin+ 在「标记已读」按钮组点击「礼物 全部已读」经二次确认后，礼物类型事件全部转为已读、New/未读清零；刷新保持；
- [ ] 空间不足时「礼物 全部已读」随按钮组折叠为 dropdown 可操作；
- [ ] 礼物类型上游同时存在 `gift` 与 `gift_v2` 时，全部已读按两者并集的最新事件写入水位线（不漏 `gift_v2` 高水位）；
- [ ] member 看不到「礼物 全部已读」入口；
- [ ] `read-all` 传入非法 `type`（不含 gift 的白名单之外）仍返回 400。

#### F2 已读切换方式改为单击

**描述**: SC / 礼物 / 上船条目的已读切换统一由**双击**改为**单击**：

- 交互入口 `title` 文案由「双击切换已读」改为「单击切换已读」，跳转类提示文案（如有）同步；
- 触发方式从 `onDoubleClick` 改为 `onClick`；
- 单击已读的视觉光标提示（`cursor-pointer`）沿用。

对 SC 条目需特别处理 SC 留言文字区（见 F3）与内嵌穿透元素（见 F4），保证「SC 各处单击」与「内嵌 B 站链接穿透」语义不冲突。

**验收标准**:

- [ ] admin+ 下单击 SC / 礼物 / 上船条目任意非穿透区域即切换已读；
- [ ] 双击不再触发已读切换（或双击的两次单击依次触发两次切换，行为等价且可接受，由实现取一致口径）；
- [ ] `title` 提示文案更新为「单击切换已读」。

#### F3 SC 留言文字区域支持单击已读

**描述**: SC 留言正文（含罗马音）区域纳入单击已读响应域：

- admin+ 单击 SC 留言文字（含罗马音行）即切换该 SC 已读；
- **文字可复制能力尽量保留**：按下拖动选中文本（`selectstart` 产生选区）时不得触发已读切换，仅「干净单击」（按下与抬起不发生文本拖选）触发已读；实现通过检测点击事件是否伴随选中文本 / 鼠标位移超过拖动阈值加以区分；
- SC 内嵌 B 站视频链接与用户头像 / 昵称作为穿透元素，单击须透传到 B 站（见 F4）。

**验收标准**:

- [ ] admin+ 单击 SC 留言正文（不含链接 / 头像 / 昵称文本）即切换已读；
- [ ] 拖选 SC 留言文本用于复制时不触发已读切换；
- [ ] SC 留言内容若为 B 站视频链接，单击链接打开 B 站视频、hover 出预览，均不触发已读（见 F4）。

#### F4 B 站链接 / 用户头像昵称穿透

**描述**: 在所有参与单击已读的 SC 条目内，以下元素单击须**穿透**到 B 站，不得被已读开关吞掉：

- **B 站视频链接（虚拟人 SC 常见 BV 号）**：单击新开 `https://www.bilibili.com/video/{bvId}/`，hover 仍显示 `BiliVideoLink` 的视频预览卡片；
- **用户头像 / 昵称**（`Sender` 锚点）：单击新开 `space.bilibili.com/{uid}`；
- 上述元素对单击已读事件必做 `stopPropagation`（并维持既有 hover / dblclick 隔离），保证其自身动作正常且不触发条目已读。

**验收标准**:

- [ ] 单击 SC 内 B 站视频链接新开视频页、hover 出预览卡片，二者均不触发 SC 已读切换；
- [ ] 单击 SC 内用户头像或昵称新开 B 站用户空间，不触发 SC 已读切换；
- [ ] 以上穿透行为在能勾选 SC 的任意栏（单类型 / 混排 / 弹幕混排）均一致。

### 3.3 页面/界面描述

| 页面 | 描述 | 关键元素 |
|------|------|----------|
| `/backdoor/danmaku`（弹幕看板） | 已读交互由双击改为单击；礼物可已读；SC 留言文字区可单击已读；SC 内 B 站链接点击/hover 与头像昵称跳转穿透 | SC / 礼物 / 上船条目（admin+ 单击已读置灰）、SC 留言内 `BiliVideoLink`（点击打开 / hover 预览）、`Sender`（头像昵称跳转空间） |

### 3.4 异常与边界情况

| 情况 | 预期行为 |
|------|----------|
| SC 留言为纯文本（无 BV 链接） | 单击文字区直接切换 SC 已读 |
| SC 留言含 BV 链接 | 单击链接穿透打开视频、hover 预览；单击链接外文字切换已读 |
| SC 内头像/昵称 | 单击穿透打开用户空间，不切换已读 |
| 拖选 SC 文本（复制） | 不触发已读切换；单击（无拖选）才触发 |
| member 角色 | 无任何已读交互（单击不切换、无 title 提示），但 B 站链接/头像昵称穿透不受影响 |
| 礼物无金额/无 gift 字段 | 不影响已读交互（仅渲染层面），单击已读照常 |
| 已读失败（网络/401/403） | 乐观更新回滚 + toast「操作失败，请重试」；不改变实际已读 |
| 双击 SC | 语义等价为两次单击（第一次已读→第二次未读），最终回到初始状态；或由实现决定单击口径，二者均可接受（见提案） |
| 隐藏钢镚/礼物筛选叠加 | 已读交互与展示过滤正交：被过滤隐藏的条目无法被点击，已读不受影响 |

## 四、非功能需求

### 4.1 性能

- 已读切换仅前端事件处理 + 既有已读 API（`/mark`、`/unmark`），无新增请求面；单击取代双击反而减少每条目的事件频度；
- 拖选/单击判定为轻量事件属性判断，无额外监听与重渲染开销。

### 4.2 安全性

- 无新增写接口；沿用既有 admin+（已读）与 member+（检索）鉴权口径；穿透跳转均为静态外链，无新增权限面。

### 4.3 兼容性

- 同既有口径：桌面现代浏览器最近两个大版本；静态导出（GitHub Pages）全部客户端行为；视口自适应断点不变（<640 / 640–1023 / ≥1024）；`prefers-reduced-motion` 不新增动效，无影响。

## 五、依赖与约束

### 5.1 依赖

- 弹幕看板既有已读管理（`DanmakuDashboard.toggleRead`、`markLiveEventRead/Unread`、`markAllLiveEventsRead`）、顶部「标记已读」按钮组（`MarkReadButtonGroup`）、`BiliVideoLink`（点击打开 + hover 预览）、`Sender`（头像昵称跳转空间）、`GiftItem`/`SuperChatItem`/`GuardItem` 条目组件、`FeedSection.renderItem` 分发表；
- 礼物单条已读复用既有 type 无关的读写接口（`markLiveEventRead/Unread` 按 `eventId`，不区分类型）；
- 「礼物全部已读」需扩展：后端 `READ_ALL_TYPES` 加入 `gift` 且 `read-all` 对 gift 走 `toUpstreamTypes` 展开（`["gift","gift_v2"]`）；契约 `read-all` 的 `type` 枚举与前端 `ReadAllType`/按钮组同步。礼物水位线数据模型已然支持（`db/liveEventReads.ts` 按任意 `type` 写 `watermark:{type}`，`typeFromEventId` 含 `gift`）。

### 5.2 约束

- 路由 `/backdoor/danmaku` 不变；「礼物全部已读」仅扩展既有 `read-all`（type 枚举加入 gift），不新增端点；已读语义（乐观更新、失败回滚、New 清除、水位线只前进）零回归；
- 「未上线的功能不得在 UI 中显示占位入口」；
- 视觉严格按 `docs/design/03-backdoor-design.md`：仅用 `@theme` token 色，后台不使用氛围动效，控件过渡 ≤200ms 且尊重 `prefers-reduced-motion`；
- SC 内 B 站链接 / 头像昵称的点击与 hover 穿透为**必须保留**的既有能力，不得因改单击已读而回归。

## 六、需求澄清（评审确认）

- **SC 文字可复制 vs 单击已读**：初版需求要求「SC 文字区域支持点击已读」。现态 SC 留言可拖选复制。两者冲突的处理：**未产生文本拖选（干净单击）→ 切换已读；产生拖选（`selectstart`/选区非空/位移超阈值）→ 不切换已读、保留复制**。若评审认为可复制已非必要，可放宽为「SC 文字区不再可选中、单击即已读」，请在评审时明确。
- **双击语义**：改为单击后，双击不再作为独立手势。对双击的两次单击是否依次触发两次已读切换（回到原状态）由实现取一致口径；本 PRD 不强制，提案给出建议。
- **礼物全部已读纳入**：`read-all` 的 `type` 目前仅 `super_chat`/`guard_buy`。本期按评审意见将礼物纳入「全部已读」，需契约枚举加 `gift`、后端 `READ_ALL_TYPES` 同步、前端按钮组新增孤儿项；实现亲礼物水位线触发须对上游 `gift`+`gift_v2` 并集取最新（见提案）。「礼物全部已读」与「礼物单条已读」一同落地。
- **共鸣于 hover 栏**：SC 呈现于悬停胶囊栏为纯展示，不涉及已读交互，不受本期影响。
