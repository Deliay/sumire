# 周表图片自定义

**功能名称**: 周表图片自定义（Weekly Image Customization）
**PRD 版本**: v1.0
**创建日期**: 2026-08-24
**作者**: sumire workflow

## 一、背景与目标

### 1.1 背景

后台「直播计划」页的「生成周表图片」功能（现态见 `docs/product/spec/schedule-admin.md`）已上线：将一周计划以固定样式（左对齐、40px 字号、深色文字 `#342a40`）绘制到官方底图上导出 PNG。投入使用后发现样式固化，无法满足不同传播场景的排版需求：

1. 文字固定左对齐，无法右对齐 / 居中对齐；
2. 字号与颜色固定，无法自定义（粉丝常用的应援色 `#b4a6bf` 需硬改代码才能使用）；
3. 样式只能全局统一，无法对某一天做差异化定制；
4. 每日文案只能由计划数据自动生成，无法插入自定义前缀/说明文字；
5. 样式配置无法按周留存，调整后会影响所有周，无法为不同周维持不同方案。

### 1.2 目标

- 在「生成周表图片」弹层中提供样式与内容配置能力：对齐方式（左/中/右）、字号、颜色；
- 配置区分「全局设置」与「按天设置」：全局作为所有天的默认，单天可单独覆盖；
- 支持按天编辑具体内容，支持插入 `{schedules}` 变量（其值为当前代码直接渲染的拼接文案）；
- 配置按周保存为「方案」：某周无专属方案时回退到默认方案；对本周任一设置的编辑会自动「新建为本周方案」。

### 1.3 成功标准

- [ ] 对齐方式可在左对齐 / 居中对齐 / 右对齐间切换，导出图文字按所选方式摆放；
- [ ] 可设置字号（数值）与颜色（色值选择），默认颜色为 `#5b4b68`；
- [ ] 全局设置对未单独覆盖的天生效；对某一天单独设置后仅该天受影响；
- [ ] 按天可编辑文案，支持插入 `{schedules}` 变量，默认文案为 `{schedules}`，未选周时用默认方案渲染；
- [ ] 方案按 ISO 周保存：本周无方案时用默认方案；任一天或全局被编辑后自动生成/更新本周方案，不影响其他周与默认方案。

## 二、用户分析

### 2.1 目标用户

- 后台管理员（admin / superadmin）：生成并发布周表图的生产者，是本功能的主要用户；
- member 角色：可生成周表图（既有只读口径），改动样式/内容若超出其权限则被判定为「预览本方案」，不落库（见 5.4）。

### 2.2 用户场景

| 场景 | 用户角色 | 目标 | 痛点（现状） |
|------|----------|------|------|
| 制作应援周图 | admin | 用应援色与居中排版生成周图 | 颜色/对齐固定，无法用 `#b4a6bf` 与居中 |
| 突出一日重点 | admin | 某天加前缀文案或换色强调 | 样式只能全局统一，无法按天定制 |
| 复用一个月的版式 | admin | 每周沿用相近版式但有微调 | 无方案概念，改一次影响全部周 |
| 生成并发布 | admin | 快速导出 PNG | 需在代码里改样式后重建才可用 |

## 三、功能需求

### 3.1 功能概述

对「生成周表图片」弹层进行迭代：新增「样式与内容配置」能力，引入「方案」概念（默认方案 + 按周方案），配置按 ISO 周留存。整体仍在既有弹层内完成，纯前端实现，不新增后端接口与契约变更（存储见 5.4 决策）。

### 3.2 功能列表

#### F1 对齐方式

**描述**: 「生成周表图片」弹层提供对齐方式设置，可选 **左对齐 / 居中对齐 / 右对齐**，默认左对齐（与现态一致）。对齐作用于单日文字在其当日区域内（固定的每行区域 715×70，见素材 AGENTS.md）的水平摆放。

**验收标准**:

- [ ] 三个对齐选项可切换，切换后预览即时更新；
- [ ] 左对齐：文字从左边界 `x=365` 起排（现态行为）；
- [ ] 居中对齐：文字在区域内水平居中；
- [ ] 右对齐：文字右边界对齐区域右边界 `x=365+715`；
- [ ] 文字过长触发 shrink-to-fit / 截断时，对齐仍以截断后的实际宽度计算，不发生越界。

#### F2 字号与颜色

**描述**: 可设置**字号**（数值，px）与**颜色**（色值选择器），默认颜色为 `#5b4b68`；默认字号沿用现版基准 40px。字号设置替换既有「自动从 40px 起 shrink-to-fit」的基准值；颜色用于单日文字绘制。

**验收标准**:

- [ ] 字号可调（建议范围 16–60px，含输入与增减控件），默认 40px；
- [ ] 颜色可调（色板 + 输入），默认 `#5b4b68`；
- [ ] 字号调大但超出区域宽度时仍触发 shrink-to-fit 防溢出（下限 22px），颜色不因字号变化改变；
- [ ] 预览即时反映字号与颜色。

#### F3 全局设置与按天设置

**描述**: 配置区分**全局设置**与**按天设置**。全局设置（对齐 / 字号 / 颜色）作为全部 7 天的默认值；任意一天可在「按天设置」中单独覆盖对齐、字号、颜色（三项可部分覆盖，未覆盖项沿用全局）。按天内容编辑（F4）本身即是按天维度。

**验收标准**:

- [ ] 全局设置变更对未覆盖的天生效；
- [ ] 单天覆盖后，仅该天使用覆盖值，其余天仍随全局；
- [ ] 单天可仅覆盖其中一项（如只改颜色），其余沿用全局；
- [ ] 清除某天的某项覆盖后回退到全局值。

#### F4 按天编辑内容与变量插入

**描述**: 支持按天编辑每日文案。每日文案为一段文本，可插入唯一变量 `{schedules}`；渲染时 `{schedules}` 替换为「该日计划自动拼接的文案」（即现态 `layout` 生成的内容：同日多场按开始时间升序以 ` / ` 连接为 `HH:mm 标题`）。默认每日文案为 `{schedules}`。文案中除 `{schedules}` 外的文字原样绘制。若某天没有计划，`{schedules}` 替换为空字符串。当日文案为空字符串则该日不绘制。

**验收标准**:

- [ ] 提供每日常规编辑框，默认值 `{schedules}`；
- [ ] 提供「插入变量」操作，可选择插入 `{schedules}` 到光标处（技术上仅一个变量，界面呈现为单按钮插入）；
- [ ] `{schedules}` 替换为计划自动拼接文案，其余文字原样绘制（如 `今日直播：{schedules}` → `今日直播：20:00 歌回 / 21:00 杂谈`）；
- [ ] 某日计划为空时，`{schedules}` 替换为空串，文案剩余文字仍绘制（空串则整日不绘制）；
- [ ] 文字长度变化后 shrink-to-fit / 截断正常触发，不越界。

#### F5 方案（默认方案 + 按周方案）

**描述**: 引入「方案」概念以留存配置。

- **默认方案**：全局基准配置（含 F1–F4 全部设置项），所有未建立专属方案的周均使用它；
- **按周方案**：针对某个 ISO 周保存的专属方案，是该周「生效方案」的快照 + 后续编辑；
- **生效方案解析**：查看某周时，`有效方案 = 该周方案（若存在） ?? 默认方案`；
- **自动新建**：用户在查看某周时，对**任一设置/内容**做出编辑，即触发「为该周新建方案」——以当前生效方案为基础复制一份作为该周方案，并应用本次编辑；之后该周的后续编辑都落入这一周方案；
- **默认方案编辑**：提供编辑默认方案的入口（在不建立周方案的前提下调整基准）。

**验收标准**:

- [ ] 周没有专属方案时，按默认方案渲染；
- [ ] 对某周任一设置/内容编辑（含对齐、字号、颜色、某日文案）后，自动创建该周方案且仅该周生效，默认方案与其他周不变；
- [ ] 已建立周方案的周再编辑时，更新的是该周方案而非默认方案；
- [ ] 可在弹层内识别当前周是「默认方案」还是「第 N 周方案」，并能切换到编辑默认方案；
- [ ] 删除某周的方案后，该周回退到默认方案（若提供删除）。

#### F6 持久化与回显

**描述**: 方案（默认 + 按周）需持久化，关闭弹层/刷新页面后保留；再次打开时按当前周回显对应方案，切周时按各周方案分别渲染。

**验收标准**:

- [ ] 关闭弹层或刷新页面后，默认方案与已保存的周方案不丢失；
- [ ] 重新打开默认落在"本周"，按本周生效方案渲染；
- [ ] 切换周时分别按各周生效方案渲染，互不串扰；
- [ ] 数据非法/缺失时安全回退到内置默认方案（左对齐、40px、`#5b4b68`、每日 `{schedules}`）。

### 3.3 页面/界面描述

「生成周表图片」弹层（后台 `/backdoor/schedule` 页）在既有周切换 + 预览 `<img>` 基础上，新增：

| 区域 | 描述 | 关键元素 |
|------|------|----------|
| 方案标识 | 弹层内显示当前周生效方案的来源 | 「默认方案」/「2026 年第 N 周方案」徽标 + 「编辑默认方案」入口 |
| 全局设置 | 作用于所有天的默认样式 | 对齐方式（左/中/右）、字号（数值）、颜色（色板） |
| 按天设置 | 单日差异化 | 七日折叠面板：内容编辑框 + 插入 `{schedules}` + 覆盖对齐/字号/颜色（可留空=沿用全局） |
| 预览区 | 实时渲染生效方案 | 底图预览 `<img>`，随设置即时刷新 |

### 3.4 异常与边界情况

| 情况 | 预期行为 |
|------|----------|
| 文案过长超出区域 | 沿用 shrink-to-fit + 截断「…」，对齐按截断后宽度计算 |
| 某日无计划 | `{schedules}` 替换为空串；文案仅余自定义文字；全空则该日不绘制 |
| 本地存储损坏/非法 | 校验后回退内置默认方案，不崩溃 |
| 周方案被编辑前查看 | 按默认方案渲染，界面显式提示当前为默认方案 |
| 某日覆盖留空项 | 该项沿用全局值 |
| 浏览器不支持 Canvas | 沿用现态「素材加载失败」兜底，不进入渲染 |

## 四、非功能需求

### 4.1 性能

- 设置编辑触发的重绘为一次 Canvas 渲染 + 底图预加载（复用既有 `Promise.all` 并行预加载），无可感知延迟；
- 存储读写仅 `localStorage`，量级 < 数 KB，同步操作无压力。

### 4.2 安全性

- 无新增接口与权限变更；渲染与存储均发生在客户端；
- 颜色/对齐/字号经 Zod 白名单校验，防非法值注入。

### 4.3 兼容性

- 桌面现代浏览器（Chrome/Firefox/Safari 最近两个大版本）；导出尺寸仍为 1665×1080 不变；
- `localStorage` 不可用（隐私模式等）时降级为「仅本次会话有效，可生成但不持久」。

## 五、依赖与约束

### 5.1 依赖

- 既有周表图生成能力（`features/schedule/weeklyImage/` 的 `layout` / `renderer` / `WeeklyImageDialog`）；
- 周计算纯函数（`weekUtils.ts`）；计划数据（`listPlans`）不变。

### 5.2 约束

- 导出尺寸 1665×1080、底图与每日常规区域坐标不变（`public/assets/original/AGENTS.md`）；
- 现版「同日多场以 ` / ` 拼接」「shrink-to-fit + 截断」作为 `{schedules}` 的数据来源与安全性保留；
- 视觉严格按 `docs/design/03-backdoor-design.md`：仅用 `@theme` token，后台控件过渡 ≤200ms；
- 分支 `<type>/<slug>` 约定；未上线功能不得在 UI 显占位入口。

### 5.3 存储口径（决策）

方案持久化采用**客户端 `localStorage`**（与后台既有本地偏好 `danmaku-backdoor.columns` 等一致），不新增后端接口、契约与数据模型。理由与权衡见技术提案 §6。多管理员跨设备共享方案属后续可选项（本期不做）。

## 六、后续可能（本期不做）

- 方案多端同步 / 服务端持久化（多管理员共享、设备间同步）；
- `{schedules}` 之外的更多变量（如日期、周数、主播名）与自定义分隔符；
- 每日多行 / 富文本排版；导出分辨率可配置；
- 方案模板库（预设配色/版式一键套用）。
