# 周表图片日期渲染

**功能名称**: 周表图片日期渲染（Weekly Image Date Render）
**PRD 版本**: v1.0
**创建日期**: 2026-08-24
**作者**: sumire workflow

## 一、背景与目标

### 1.1 背景

后台「直播计划」页的「生成周表图片」功能（现态见 `docs/product/spec/schedule-admin.md`，样式/内容自定义见 `docs/product/requirements/draft/2026-08-24-weekly-image-customization-prd.md`）已支持将对齐/字号/颜色与按天内容绘制到官方底图并导出 PNG。但当前导出图**不标注该周对应的日期范围**：

1. 生成周表图时按 ISO 周渲染 7 天内容，但图上没有「这是 2026.8.31 ~ 9.6」之类的日期信息；
2. 传播/存档时仅凭内容难以判断周表对应哪一周，需要人工补充日期。

官方底图顶部预留有日期绘制区域（见 `public/assets/original/AGENTS.md`：`weekly-schedules-raw.jpg` 1665×1080，日期区域左上角 640,80，可用 451×40，相关区域坐标已在 `feat/weekly-image-date-area` 分支确定），本功能将该区域投入使用。

### 1.2 目标

- 生成周表图片时，将本月的开始/结束日期渲染到底图顶部日期区域上；
- 日期**格式**可配置（支持年/月/日相关变量）；
- 日期**内容**可配置（呈现「开始日期 ~ 结束日期」，开始/结束可用上一阶段的格式化串）；
- 日期区域独立支持字号、对齐、颜色设置，因区域较小采用更小的默认字号；
- 日期配置随既有「默认方案 + 按周方案」机制持久化，与内容/样式设置一致。

### 1.3 成功标准

- [ ] 生成的周表图顶部日期区域渲染出该周的日期范围；
- [ ] 默认渲染 `{yyyy}年{mm}月{dd}日 ~ {yyyy}年{mm}月{dd}日`（开始与结束各按默认日期格式格式化）；
- [ ] 日期格式变量 `{yyyy}`/`{yy}`/`{mm}`/`{m}`/`{dd}`/`{d}` 按需求定义替换；
- [ ] 日期内容变量 `{开始日期}`/`{结束日期}` 替换为格式化后的开始/结束日期字符串；
- [ ] 日期区域可独立设置字号（更小默认值）、对齐、颜色，预览即时更新；
- [ ] 日期配置随方案按周保存，刷新/切周回显正确，与内容/样式配置一致（默认 + 按周）。

## 二、用户分析

### 2.1 目标用户

- 后台管理员（admin / superadmin）：生成并发布周表图的生产者，是本功能的主要用户；
- member 角色：可生成周表图（既有只读口径），日期配置改动同样被视为「预览本方案」，不落库（沿用既有口径）。

### 2.2 用户场景

| 场景 | 用户角色 | 目标 | 痛点（现状） |
|------|----------|------|------|
| 发布周表 | admin | 导出含日期范围的周图，方便传播/归档 | 图上无日期，难以判断对应周 |
| 定制日期版式 | admin | 调整日期格式/字号/颜色/对齐，配合应援图排版 | 无日期渲染，更无定制能力 |
| 复用每周版式 | admin | 每周沿用相近日期版式但有微调 | 无方案概念 |

## 三、功能需求

### 3.1 功能概述

在既有「生成周表图片」弹层方案体系中，新增**日期方案配置**。整体仍在既有弹层内完成，纯前端实现，不新增后端接口与契约变更。日期配置作为方案结构的一部分，随「默认方案 + 按周方案」持久化与回显。

### 3.2 功能列表

#### F1 日期范围渲染

**描述**: 生成周表图片时，在当前周的**日期绘制区域**（`public/assets/original/AGENTS.md`：左上角 640,80，可用 451×40）内渲染该周的日期范围。日期范围为 ISO 周的开始日期（周一）与结束日期（周日）。

**验收标准**:

- [ ] 日期区域渲染出该周「开始日期 ~ 结束日期」的文本；
- [ ] 切换周后日期范围随之更新（周一~周日）；
- [ ] 日期渲染不依赖当周是否有计划（无计划周也渲染日期）；
- [ ] 日期文本过长时按区域宽度 shrink-to-fit / 截断兜底，不越界。

#### F2 日期格式配置

**描述**: 提供「日期格式」模板配置。格式模板用于将单个日期（YYYY-MM-DD）格式化为字符串，默认 `{yyyy}年{mm}月{dd}日`。

支持以下变量（替换为对应日期的数值）：

| 变量 | 含义 | 示例（2026-08-31） |
|------|------|------|
| `{yyyy}` | 四位年份 | `2026` |
| `{yy}` | 两位年份（取后两位） | `26` |
| `{mm}` | 月份，至少两位（补零） | `08` |
| `{m}` | 月份，一位或多位 | `8` |
| `{dd}` | 日期，至少两位（补零） | `31` |
| `{d}` | 日期，一位或多位 | `31` |

模板中除这些变量外的文字原样保留。无变量（纯静态文案）或部分变量均可。

**验收标准**:

- [ ] 默认格式 `{yyyy}年{mm}月{dd}日`，对 2026-08-31 输出 `2026年08月31日`；
- [ ] `{yy}` 对 2026 输出 `26`；`{m}` 对 8 月输出 `8`，`{mm}` 输出 `08`；`{d}`/`{dd}` 同理；
- [ ] 跨月/跨年周的开始与结束日期分别按其真实日期格式化；
- [ ] 模板内任意位置均可放置变量，非变量文字原样保留。

#### F3 日期内容配置

**描述**: 提供「日期内容」模板配置。内容模板用于拼装实际绘制到图上的文本，默认 `{开始日期} ~ {结束日期}`。

支持如下变量：

| 变量 | 含义 |
|------|------|
| `{开始日期}` | 周开始日期（周一）经**日期格式**（F2）格式化后的字符串 |
| `{结束日期}` | 周结束日期（周日）经**日期格式**（F2）格式化后的字符串 |

内容模板中其他文字原样保留。日期内容模板为空字符串时，该日期区域不绘制。

**验收标准**:

- [ ] 默认内容 `{开始日期} ~ {结束日期}`；
- [ ] `{开始日期}`/`{结束日期}` 替换为各自的格式化日期字符串（示例：某周为 2026-08-31~09-06 时，默认输出 `2026年08月31日 ~ 2026年09月06日`）；
- [ ] 内容模板可自由定制（如 `{开始日期}～{结束日期}`、`{开始日期}/{结束日期}` 或仅 `{开始日期}`）；
- [ ] 内容模板为空字符串时日期区域不绘制。

#### F4 日期区域样式（字号 / 对齐 / 颜色）

**描述**: 日期区域独立支持**字号**、**对齐**与**颜色**设置。因日期区域（451×40）比每天内容区域（715×70）更小，默认字号选取更小的值（本期默认为 **20px**）；对齐与颜色默认与全局一致（默认对齐沿用全局、默认颜色沿用全局默认 `#5b4b68`），但可独立覆盖。

**验收标准**:

- [ ] 日期区域可独立设置字号，默认 **20px**（比内容区域默认 40px 更小）；
- [ ] 日期区域可设置对齐（左 / 居中 / 右），预览即时更新，文本不越界；
- [ ] 日期区域可设置颜色，默认沿用全局默认色（`#5b4b68`），可独立覆盖；
- [ ] 字号/对齐/颜色对导出图生效；文字过长仍 shrink-to-fit / 截断兜底。

#### F5 日期方案持久化与回显

**描述**: 日期配置作为方案（`DefaultScheme` 的 `date` 字段）的一部分，随既有「默认方案 + 按周方案」机制持久化到 `localStorage`。对日期的任一编辑，在非默认方案模式下同样自动新建/更新本周方案。

**验收标准**:

- [ ] 日期格式/内容/字号/对齐/颜色随默认方案保存，随按周方案分周保存；
- [ ] 关闭弹层 / 刷新后回显正确的日期配置；
- [ ] 切换周时按各周方案分别渲染日期配置，互不串扰；
- [ ] 对某周做日期配置编辑自动新建该周方案（沿用「默认 + 按周」既有规则），不影响默认与其他周；
- [ ] 数据非法/缺失（尤其旧版本 scheme 无 `date` 字段）时安全回退内置日期默认值，不崩溃。

### 3.3 页面/界面描述

「生成周表图片」弹层（后台 `/backdoor/schedule` 页）在既有方案设置面板基础上，新增「日期设置」区块：

| 区域 | 描述 | 关键元素 |
|------|------|----------|
| 日期设置 | 作用于日期绘制区域 | 日期格式模板输入框（默认 `{yyyy}年{mm}月{dd}日`）、日期内容模板输入框（默认 `{开始日期} ~ {结束日期}`）、字号、对齐、颜色 |

### 3.4 异常与边界情况

| 情况 | 预期行为 |
|------|----------|
| 日期文字过长超出日期区域 | 沿用 shrink-to-fit + 截断「…」，对齐按截断后宽度计算 |
| 日期内容模板为空串 | 日期区域不绘制 |
| 旧版本 scheme（无 `date` 字段） | 解析时回退内置日期默认值，不崩溃、不清空其他设置 |
| 本地存储损坏/非法 | 校验后回退内置默认方案（含日期默认），不崩溃 |
| 周切换跨年（如 52/53 周、1 周） | 开始/结束日期取该 ISO 周真实周一/周日，正常格式化 |
| 浏览器不支持 Canvas | 沿用现态「素材加载失败」兜底，不进入渲染 |

## 四、非功能需求

### 4.1 性能

- 日期区域渲染合并进既有单次 Canvas 绘制（额外生成 1 条绘制指令），无可感知开销；
- 存储读写沿用既有 `localStorage` 方案，量级无压力。

### 4.2 安全性

- 无新增接口与权限变更；渲染与存储均在客户端；
- 日期模板/颜色/字号经 Zod 白名单校验，防非法值注入。

### 4.3 兼容性

- 桌面现代浏览器（Chrome/Firefox/Safari 最近两个大版本）；导出尺寸仍为 1665×1080 不变；
- `localStorage` 不可用（隐私模式等）时降级为「仅本次会话有效」。

## 五、依赖与约束

### 5.1 依赖

- 既有周表图生成与自定义能力（`features/schedule/weeklyImage/` 的 `scheme`/`layout`/`renderer`/`WeeklyImageDialog`）；
- ISO 周计算纯函数（`weekUtils.ts` 的 `getWeekRange`）；计划数据（`listPlans`）不变。

### 5.2 约束

- 导出尺寸 1665×1080 与底图各区域坐标不变；日期区域坐标按 `public/assets/original/AGENTS.md`（左上角 640,80，可用 451×40）；
- 视觉严格按 `docs/design/03-backdoor-design.md`：仅用 `@theme` token，后台控件过渡 ≤200ms；
- 沿用「shrink-to-fit + 截断」兜底机制确保不越界；
- 分支 `<type>/<slug>` 约定；未上线功能不得在 UI 显占位入口。

### 5.3 存储口径（决策）

日期配置作为 `DefaultScheme.date` 字段纳入既有 `localStorage` 方案体系（默认 + 按周），不新增后端接口、契约与数据模型。为保证向后兼容，`date` 字段在 schema 中为**可选**，缺失时由解析层回退内置日期默认值（见技术提案 §6）。理由与权衡见技术提案 §6。
