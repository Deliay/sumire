# 弹幕投票（弹幕工具一期）

**功能名称**: 弹幕投票（Danmaku Vote）
**PRD 版本**: v1.0
**创建日期**: 2026-08-28
**作者**: sumire workflow

## 一、背景与目标

### 1.1 背景

「后台」目前已有弹幕看板、弹幕检索等直播运营工具，均直接挂在左侧导航栏。随着工具增多，需要一个「弹幕工具」聚合入口：以卡片形式陈列工具，点击进入各工具页面。

首个落地工具为「弹幕投票」：直播互动中主播/运营常需要让观众用弹幕投票（如「1 = 唱歌、2 = 游戏」）。现态无此能力，只能人工心算弹幕。本工具为**纯前端工具**：复用既有 `/api/live-events/stream` 实时弹幕 SSE 接口抓取弹幕，在浏览器内完成匹配与统计，不引入任何新后端端点。

### 1.2 目标

- 后台左侧导航新增「弹幕工具」入口，进入卡片式工具列表页，点击卡片进入对应工具页；
- 提供「弹幕投票」工具：配置选项后开始抓取弹幕计票，实时展示统计与比例；
- 投票数据持久化于浏览器 localStorage，刷新不丢失，可二次确认后清空。

### 1.3 成功标准

- [ ] 左侧导航出现「弹幕工具」入口（member 及以上可见），点击进入工具列表页，列表页含「弹幕投票」卡片，点击进入投票工具页；
- [ ] 可添加/删除选项（名称 + 匹配关键字），互斥校验生效：任一选项的关键字与另一选项的关键字互为子串时拒绝保存（如已有 A 则不能再设 AA）；
- [ ] 点击「开始投票」后经 SSE 实时抓取弹幕并按规则计票；按钮变为「停止投票」且颜色变化；点击「停止投票」断开 SSE 及处理；
- [ ] 计票规则正确：一条弹幕恰好只命中一个选项的关键字时才计票；同一弹幕发送者全场只计一次；
- [ ] 投票中展示「已处理 x 条弹幕，其中 y 条匹配」与实时更新的投票比例 table；
- [ ] 刷新页面后投票数据（选项、统计、已投票记录）保留；「清空投票」经弹窗确认后清空全部投票数据。

## 二、用户分析

### 2.1 目标用户

- 后台管理员（admin / superadmin）：直播互动投票的发起与统计者；
- member 角色：可使用本工具（只读弹幕流，与弹幕看板鉴权口径一致）。

### 2.2 用户场景

| 场景 | 用户角色 | 目标 | 痛点（现况） |
|------|----------|------|------|
| 直播弹幕投票 | admin | 让观众发弹幕投票并实时看到各选项比例 | 人工心算弹幕，无法统计 |
| 投票结果留存 | admin | 刷新/误关页面后投票数据不丢失 | 纯内存统计会丢失 |

## 三、功能需求

### 3.1 功能概述

本期新增后台「弹幕工具」聚合区：导航入口 + 卡片式工具列表页 + 首个工具「弹幕投票」。弹幕投票为纯前端工具：选项配置（名称 + 匹配关键字，互斥校验）→ 开始投票（EventSource 订阅 `/api/live-events/stream?type=danmaku`）→ 弹幕匹配计票（恰好单选项命中 + 发送者唯一）→ 实时展示统计与比例 table → 停止投票（断开 SSE）→ 结果持久化 localStorage / 二次确认清空。无后端变更、无契约变更、无数据库变更。

### 3.2 功能列表

#### F1 「弹幕工具」导航入口与工具列表页

**描述**:

- 后台左侧导航（SideNav）新增「弹幕工具」入口，href 为 `/backdoor/danmaku-tools`，member 及以上全角色可见；选中态沿用既有最长前缀匹配口径；
- `/backdoor/danmaku-tools` 为工具列表页：以**卡片**形式陈列工具，本期仅含「弹幕投票」一张卡片；
- 卡片展示工具名称与一句话简介，点击卡片整卡跳转至对应工具页（本期为 `/backdoor/danmaku-tools/vote`）；
- 列表页复用 `(dashboard)/layout.tsx` 会话守卫与后台设计口径；未配置 API（`API_CONFIGURED === false`）时按后台既有构建时守卫口径处理，不展示占位入口。

**验收标准**:

- [ ] 左侧导航出现「弹幕工具」，点击或直达 `/backdoor/danmaku-tools` 展示工具列表页；
- [ ] 列表页含「弹幕投票」卡片（名称 + 简介），点击卡片跳转 `/backdoor/danmaku-tools/vote`；
- [ ] 处于 `/backdoor/danmaku-tools/*` 路径时导航「弹幕工具」为选中态，不误中「弹幕看板」。

#### F2 投票选项管理

**描述**:

- 投票工具页左侧为选项配置区：选项列表 + 新增选项表单；
- 每个选项含两个属性：**名称**（展示用）与**匹配关键字**（弹幕匹配用）；新增时两者**同时必填**，任一空（trim 后为空）拒绝添加；
- 匹配规则为**包含匹配**：弹幕文本包含关键字即视为命中该选项；
- **互斥校验**：任意两个选项的关键字不得互为子串（双向判定）——如已有关键字 `A`，则不允许再添加 `AA`（`A` 会匹配 `AA`），也不允许添加使既有选项失义的更短关键字（如已有 `AA` 时添加 `A`）；完全相同的关键字视为互为子串，同样拒绝；
- 选项可删除；投票进行中选项列表**只读**（不可增删改），停止投票后恢复可编辑；
- 选项列表随投票数据一并持久化（见 F6）。

**验收标准**:

- [ ] 名称或匹配关键字为空（含纯空白）时无法添加选项，并给出提示；
- [ ] 新关键字与任一既有关键字互为子串（含完全相同）时无法添加，并给出提示；
- [ ] 合法选项添加成功并即时出现在选项列表；可删除选项；
- [ ] 投票进行中选项列表只读，停止后恢复可编辑。

#### F3 投票流程（开始 / 停止）

**描述**:

- 「开始投票」按钮初始可用；点击前需至少存在 1 个选项，否则给出提示且不开始；
- 点击「开始投票」后：建立 EventSource 连接 `/api/live-events/stream?type=danmaku`（`withCredentials`，复用后台既有鉴权口径），开始抓取实时弹幕并计票；
- 投票进行中：按钮文案变为「停止投票」且**颜色变化**（明显区分的视觉态），选项列表只读；
- 点击「停止投票」：断开 SSE 连接（`EventSource.close()`）并停止一切匹配处理，按钮恢复「开始投票」；已有统计数据保留不清空；
- 停止后可再次点击「开始投票」继续计票（统计在既有数据上累计，已投票发送者记录保留——同一发送者跨场次仍只计一次）；
- SSE 断线由 EventSource 内建自动重连兜底，重连期间不重复计票；离开页面（路由切换）自动断开连接。

**验收标准**:

- [ ] 无选项时点击「开始投票」不建立连接并提示；
- [ ] 投票进行中按钮显示「停止投票」且颜色与开始态明显不同；点击后 SSE 断开、按钮恢复；
- [ ] 停止后再次开始，统计在既有数据上继续累计；
- [ ] 离开投票工具页后不再产生 SSE 连接与处理。

#### F4 弹幕匹配与计票规则

**描述**:

- 仅处理 `danmaku` 类型事件的弹幕文本（`content`）；表情弹幕（`emote`）无文本内容，不计入匹配（仍计入已处理数）；
- **单选项命中才计票**：对每条弹幕，逐一检查各选项关键字，命中选项数**恰好为 1** 时该弹幕计入该选项 1 票；命中 0 个或 ≥2 个选项时不计票（≥2 的情形理论上被互斥校验排除，仍按规则防御处理）；
- **发送者唯一**：同一弹幕发送者（以 `sender.uid` 判定）全场投票只计 1 票——其第一条恰好单选项命中的弹幕计票后，后续弹幕不再计票（仍计入已处理数）；命中 0 个或 ≥2 个选项的弹幕不消费该发送者的投票机会；
- 计数口径：「已处理」= 投票期间收到的弹幕事件总数（含不计票的）；「已匹配」= 实际计票的弹幕总数。

**验收标准**:

- [ ] 弹幕恰好命中 1 个选项关键字时该选项票数 +1；
- [ ] 弹幕命中 0 个或多个选项时不计任何票，但已处理数 +1；
- [ ] 同一 uid 第二次及以后命中选项的弹幕不计票；其首次弹幕未命中任何选项时，后续命中仍可计票；
- [ ] 已处理/已匹配计数与上述口径一致。

#### F5 投票中实时展示

**描述**:

- 投票工具页右侧为统计区，包含：
  - 统计文案：「已处理 x 条弹幕，其中 y 条匹配」（x、y 为 F4 口径的实时计数）；
  - 投票比例 table：每行一个选项，列为「名称 / 票数 / 占比」；占比 = 该选项票数 ÷ 全部选项票数之和，以百分比展示（保留 1 位小数；总票数为 0 时各选项占比显示 0%）；
- table 随每条计票弹幕**实时计算与展示**，无需手动刷新；
- 投票未开始时统计区同样展示（反映已持久化的历史数据）。

**验收标准**:

- [ ] 投票中统计文案与 table 随弹幕到达实时更新，数值与 F4 口径一致；
- [ ] 占比列合计为 100%（±0.1% 舍入误差），总票数为 0 时显示 0%；
- [ ] 非投票状态下页面展示的统计与 localStorage 中数据一致。

#### F6 数据持久化与清空

**描述**:

- 投票数据（选项列表、各选项票数、已处理/已匹配计数、已投票发送者 uid 集合）实时写入 localStorage，刷新页面后完整恢复；
- 「清空投票」按钮位于「开始投票」按钮旁；点击后**弹窗提示**：说明该操作会清空当前所有投票数据（选项、统计与已投票记录），询问用户是否确认；确认后清空 localStorage 中的投票数据并将界面恢复至初始空态；取消则不做任何变更；
- 投票进行中点击「清空投票」：先弹窗确认，确认后同时断开 SSE 并回到初始空态（即清空蕴含停止）；
- localStorage 数据损坏（非法 JSON / 结构不符）时回退初始空态，不报错崩溃。

**验收标准**:

- [ ] 投票产生数据后刷新页面，选项、统计文案、比例 table 与已投票记录完整恢复；
- [ ] 点击「清空投票」出现确认弹窗，文案明确操作后果；确认后数据清空、界面恢复初始空态；
- [ ] 取消确认弹窗后数据与界面无任何变化；
- [ ] 投票进行中确认清空后 SSE 断开且数据清空；
- [ ] localStorage 数据损坏时页面以初始空态正常加载。

| 页面 | 描述 | 关键元素 |
|------|------|----------|
| `/backdoor/danmaku-tools` | 弹幕工具列表页 | 工具卡片（名称 + 简介），点击整卡跳转 |
| `/backdoor/danmaku-tools/vote` | 弹幕投票工具页 | 左侧：选项列表 + 新增选项表单（名称 + 匹配关键字）；操作区：「开始投票/停止投票」「清空投票」按钮；右侧：统计文案 + 投票比例 table；清空确认弹窗 |

### 3.4 异常与边界情况

| 情况 | 预期行为 |
|------|----------|
| 未配置 API（`API_CONFIGURED === false`） | 按后台既有构建时守卫渲染 404，不展示工具入口占位 |
| 未登录 / 会话失效 | 沿用 `(dashboard)/layout.tsx` 会话守卫口径 |
| SSE 连接失败 / 断线 | EventSource 内建自动重连；重连期间不丢已统计数据，不重复计票 |
| 无选项点击「开始投票」 | 不建立连接，提示需先添加选项 |
| 弹幕命中 0 个或 ≥2 个选项 | 不计票，已处理数 +1 |
| 同一发送者重复命中 | 仅首条恰好单选项命中的弹幕计票 |
| 表情弹幕（无文本） | 不参与匹配，已处理数 +1 |
| 选项关键字互斥冲突 | 拒绝添加并提示 |
| localStorage 数据损坏 | 回退初始空态 |
| 窄屏视口 | 左右分区允许纵向堆叠，不破坏布局 |

## 四、非功能需求

### 4.1 性能

- 匹配为纯内存字符串包含判断，选项数为个位数量级，无性能压力；
- 弹幕高频到达时 UI 更新跟随 React 状态批处理即可，无需虚拟化（仅展示聚合数值，不渲染弹幕列表）。

### 4.2 安全性

- 弹幕数据经既有服务端 SSE 代理获取，前端不直连内网上游；复用 `withCredentials` cookie 鉴权（member 及以上）；
- 投票数据仅存于用户浏览器 localStorage，不上送服务端、不含敏感信息（uid 为公开标识）。

### 4.3 兼容性

- 同后台既有口径：桌面现代浏览器最近两个大版本；EventSource 为目标浏览器原生能力。

### 4.4 可访问性

- 比例 table 使用语义化 `<table>`；清空确认弹窗遵循既有弹层口径（焦点管理、Esc 关闭）。

## 五、依赖与约束

### 5.1 依赖

- 既有 `/api/live-events/stream` SSE 端点（`type=danmaku`，member 及以上），已交付，无契约变更；
- 后台既有会话守卫、SideNav、`features/backdoor/api.ts` 基础设施。

### 5.2 约束

- 纯前端实现：不新增后端端点、不改契约、不改数据库；
- Tailwind v4 `@theme` token 色，禁止硬编码色值；视觉按 `docs/design/03-backdoor-design.md`；
- 分支命名 `<type>/<slug>`：需求总分支 `prd/danmaku-vote`。
