# 首页视觉效果优化 3 期

**功能名称**: 首页视觉效果优化 3 期（Home Visual FX v3：立绘视差 + 光晕粒子 + 日历跨月日程补全）
**PRD 版本**: v1.0
**创建日期**: 2026-08-31
**作者**: sumire workflow

## 一、背景与目标

### 1.1 背景

首页视觉效果优化（封面页重构，见 `docs/engineering/proposals/2026-08-31-home-visual-overhaul-proposal.md`）已上线：首页为 `100svh` 不可滚动封面页，立绘作为衬底铺于右半（移动端全宽），背景有两团缓慢漂移的雾气。本期（3 期）在此基础上增加两层**互动氛围**，并修复日历页一个取数口径问题：

1. **立绘静止**：立绘层不随访客任何输入产生反馈，首屏缺少「活」的感觉；
2. **背景偏空**：雾气之外无更细的视觉颗粒，鼠标移动没有任何呼应；
3. **日历跨月日程缺失**：`/calendar` 月视图实际展示的是固定 6 行×7 列的日期网格（周一开头，月初/月末以相邻月日期补位），例如 2026 年 8 月实际展示 7 月 27 日 ~ 9 月 6 日；但当前仅按「当月 1 日~月末」区间拉取日程（`CalendarView.goMonth` 上抛 `monthRange`，`CalendarViewPage` 首屏同样按月区间），导致跨月补位格上**明明有日程却显示为空**。

### 1.2 目标

- 首页立绘层增加随鼠标移动的**视差效果**（位移轻微、平滑跟随、松手/移出后回中）；
- 移动端（触屏设备）增加**设备传感器**（陀螺仪/方向）驱动的视差，作为鼠标输入的替代；
- 首页背景增加**随机产生的光晕粒子**，粒子缓慢漂移、明灭；鼠标（或触摸点）周围产生的粒子相对较多；
- `/calendar` 月视图按组件**实际展示的日期网格范围**获取日程，跨月补位格能展示对应日程；
- 全部动效尊重 `prefers-reduced-motion`，不产生布局偏移（CLS = 0），不引入新依赖。

### 1.3 成功标准

- [ ] 桌面端鼠标在首页内移动时，立绘层产生轻微、平滑的视差位移；鼠标移出/停止后平滑回中；
- [ ] 移动端（支持传感器的设备）倾斜设备时立绘层产生视差；iOS 需权限时在首次触摸后静默请求，授权失败/无传感器时无视差且页面无任何异常；
- [ ] 首页背景持续随机产生光晕粒子，粒子漂移明灭；鼠标/触摸位置附近的粒子产生密度明显高于其他区域；
- [ ] 系统开启「减少动态效果」时：粒子不渲染、视差禁用，页面其余表现不变；
- [ ] `/calendar` 月视图展示的网格范围内（含跨月补位格）的日程均可见；翻月后按新网格范围重新拉取；
- [ ] 跨月补位格的弱化样式与不可点击口径不变（仅补齐日程展示）；
- [ ] 移动端周视图（< 640px）取数与展示口径不变；
- [ ] 首页保持 `100svh` 不可滚动、无 CLS；动效在主线程预算内（粒子数有上限，页面隐藏时暂停）。

## 二、用户分析

### 2.1 目标用户

- 站点访客（桌面端为主、移动端次之）：打开首页即感知氛围动效；
- 查看日程的访客：在 `/calendar` 月视图中浏览跨月边界日期的日程。

### 2.2 用户场景

| 场景 | 用户角色 | 目标 | 痛点（现状） |
|------|----------|------|--------------|
| 打开首页 | 访客（桌面） | 感知精致、有呼应的首屏氛围 | 立绘与背景完全静止，鼠标移动无任何反馈 |
| 手机打开首页 | 访客（移动） | 同样有「活」的首屏 | 无鼠标，无任何互动氛围 |
| 查跨月日程 | 访客 | 在月视图补位格看到相邻月的日程 | 补位格有日程也显示为空，需翻月才能看到 |

## 三、功能需求

### 3.1 功能概述

本期为纯前端改动，全部位于公开站点（`apps/bookstore`），**不新增后端接口、不改动 API 契约、不改动后台**：

- F1 / F2：首页立绘层视差（鼠标 + 移动端传感器）；
- F3：首页背景光晕粒子层；
- F4：`/calendar` 月视图按展示网格范围取数。

### 3.2 功能列表

#### F1 立绘鼠标视差（桌面端）

**描述**: 首页立绘层（`app/(site)/page.tsx` 中立绘容器）随鼠标在视口内的位置产生视差位移：鼠标靠近右/下时立绘向相反方向轻微偏移（营造纵深），最大位移小幅（约 ±12px 量级，以实现定稿为准）；移动过程平滑跟随（缓动/插值，非瞬时跳变）；鼠标移出视口或停止输入后平滑回到原位。立绘层保持 `pointer-events-none`、不拦截任何交互，不产生布局偏移（仅 `transform`）。

**验收标准**:

- [ ] 鼠标在首页内移动时立绘平滑偏移，方向与鼠标位置形成视差关系；
- [ ] 位移幅度轻微（不遮挡文案、不露怯），全程仅 `transform`/`opacity` 合成层属性；
- [ ] 鼠标移出视口后立绘平滑回中；
- [ ] 无鼠标设备（触屏笔记本等无 pointermove 场景）不产生异常。

#### F2 移动端传感器视差

**描述**: 移动端（触屏设备）以设备方向传感器（`deviceorientation`）驱动同一套视差：左右/前后倾斜映射为立绘的水平/垂直偏移，倾斜角做钳制与归一化，避免日常握持抖动导致大幅晃动。iOS 13+ 需要 `DeviceOrientationEvent.requestPermission()` 授权：在首次用户触摸后静默尝试请求；用户拒绝、设备无传感器、或 API 不存在时**静默降级为无视差**，页面不出现任何权限提示 UI 或占位入口。

**验收标准**:

- [ ] 支持传感器的 Android 设备倾斜时立绘产生视差；
- [ ] iOS 设备首次触摸后按规范请求权限，授权后视差生效；
- [ ] 拒绝授权/无传感器/API 不存在时静默无视差，无错误、无提示 UI；
- [ ] 传感器输入经钳制/平滑处理，轻微晃动不产生剧烈抖动。

#### F3 背景光晕粒子

**描述**: 首页背景（雾气层之上、内容层之下）新增一层光晕粒子：粒子**随机产生**于画面中，缓慢漂移、明灭（淡入淡出），视觉为「紫花微光」语言（色值取自 `@theme` token，如 `flower`/`primary`/`eye` 系，低透明度 + 柔光）。**鼠标（或触摸点）周围产生的粒子相对较多**：粒子生成位置按概率分布——较大概率生成在最后已知指针位置附近的一定半径内，其余均匀随机分布于全屏；指针尚未出现前全部均匀随机。粒子不响应指针交互（不吸附、不躲避），仅生成密度相关。

**验收标准**:

- [ ] 首页可见随机产生的光晕粒子，缓慢漂移并明灭，风格与既有雾气/紫花微光一致；
- [ ] 鼠标移动后，指针附近区域的粒子产生密度明显高于其他区域；
- [ ] 移动端以最后触摸点作为「指针位置」；
- [ ] 粒子层 `pointer-events-none`，不遮挡/不拦截任何内容与交互；
- [ ] 粒子总数有上限（按视口面积缩放），页面隐藏（`document.hidden`）时暂停产生与绘制；
- [ ] 仅使用 `@theme` token 色（运行时读取 CSS 变量），无硬编码色值。

#### F4 日历月视图按展示网格范围取数

**描述**: `/calendar` 月视图实际展示固定 6 行×7 列的日期网格（周一开头，月初/月末以相邻月日期补位），但当前按「当月 1 日~月末」拉取日程。改为按**网格实际展示范围**（首格日期 ~ 末格日期）拉取：例如 2026 年 8 月的展示网格为 2026-07-27 ~ 2026-09-06，则按该区间请求 `GET /api/stream-plans?from=…&to=…`。首屏（当前月）与翻月均按此口径。跨月补位格由此可展示日程摘要（沿用月视图「至多 2 条 + +N」收口），其**弱化样式（`opacity-35`）与不可点击口径不变**。历史直播记录为全量一次拉取、本地归并，不受本变更影响。

**验收标准**:

- [ ] 月视图首屏按「当前月展示网格首格~末格」拉取日程（例：2026-08 → 2026-07-27 ~ 2026-09-06）；
- [ ] 翻月（上月/下月）按新月展示网格范围重新拉取；
- [ ] 跨月补位格上有日程时展示摘要（弱化样式、至多 2 条 +N 收口），无日程时不渲染「—」占位（现口径不变）；
- [ ] 跨月补位格保持不可点击（不弹当日详情）；当月日期点击行为不变；
- [ ] 移动端周视图（< 640px）取数范围（周一~周日）与展示不变；
- [ ] 后台 `/backdoor/schedule` 月视图取数口径一并修正（同一 `CalendarView` 组件，行为一致）。

### 3.3 页面/界面描述

| 页面 | 变更 | 关键元素 |
|------|------|----------|
| 首页 `/` | 立绘容器接入视差；背景新增粒子画布层 | 粒子 `<canvas>`（`absolute inset-0`、`pointer-events-none`、z 序在雾气之上内容之下）；立绘容器 `transform` 由视差驱动 |
| 公开日历 `/calendar` | 取数范围改为展示网格范围 | 无 UI 结构变化；跨月补位格可显示日程摘要 |
| 后台直播计划 `/backdoor/schedule` | 同组件口径同步 | 无 UI 结构变化 |

### 3.4 异常与边界情况

| 情况 | 预期行为 |
|------|----------|
| `prefers-reduced-motion: reduce` | 粒子层不渲染；视差禁用（立绘静止）；页面其余不变 |
| iOS 传感器权限被拒/无传感器 | 静默降级为无视差，无任何 UI 提示或报错 |
| 指针从未出现（加载后无任何移动） | 粒子全屏均匀随机产生；立绘无偏移 |
| 窗口尺寸变化 | 粒子画布随视口重建尺寸，密度按新面积收敛 |
| 页面切后台（`document.hidden`） | 粒子暂停产生与绘制，回前台恢复 |
| 跨月补位格日程拉取失败 | 沿用现口径：失败置「加载失败」/静默，不单独为补位格做特殊处理 |
| 跨年/跨月边界（1 月/12 月网格） | 网格范围按真实日期计算（如 2027-01 网格含 2026-12 末日期），正常拉取 |
| 低配设备 | 粒子数按视口面积设上限，仅 `transform`/`opacity`，不引入新依赖 |

## 四、非功能需求

### 4.1 性能

- 视差与粒子仅使用合成层属性（`transform`/`opacity`）与 Canvas 2D 绘制，不触发布局；粒子数设上限（按视口面积缩放，桌面约 ≤ 70 个量级，以实现定稿为准）；
- 动画循环用 `requestAnimationFrame`，页面隐藏时暂停；组件卸载时完整清理监听器与 rAF；
- 首页保持 `100svh` 不可滚动，动效不得引起 CLS；
- 不新增任何运行时依赖。

### 4.2 可访问性

- 全部氛围动效尊重 `prefers-reduced-motion`（粒子不渲染、视差禁用）；
- 粒子与视差均为纯装饰（`aria-hidden`），不影响读屏与键盘操作。

### 4.3 兼容性

- 桌面现代浏览器（Chrome/Firefox/Safari 最近两个大版本）；移动端 Safari（含 iOS 权限流）与 Android Chrome；
- 传感器 API 全部做特性检测，缺失时静默降级；
- 站点为纯静态导出（`output: "export"`），全部动效仅在客户端 hydration 后生效，SSG 产物不含任何粒子/视差初始状态（防 hydration 不一致）。

## 五、依赖与约束

### 5.1 依赖

- 既有首页封面页结构（`app/(site)/page.tsx`：雾气层、立绘容器、左列内容、`Footer floating`）；
- 既有 `@theme` token（`globals.css`：粒子取色、雾气层参照）；既有 `lib/useMediaQuery.ts`（断点/媒体查询 hook）；
- 既有日程接口 `GET /api/stream-plans`（`from`/`to` 区间查询，公开读）——本需求不改动契约；
- 既有日历组件 `CalendarView`/`CalendarViewPage` 与日期纯函数 `dateUtils.ts`（`monthGrid` 等）。

### 5.2 约束

- 视觉严格按 `docs/design/01-visual-identity.md` / `02-page-design.md`：仅用 `@theme` token 色，禁硬编码色值（Canvas 绘制色运行时读 CSS 变量）；
- 氛围动效必须尊重 `prefers-reduced-motion`（`docs/engineering/frontend-rules.md`）；
- 未上线功能不得在 UI 显占位入口；传感器权限失败静默降级，不做提示 UI；
- 分支 `<type>/<slug>`（`prd/` 文档、`feat/` 开发），禁止 rebase/squash，只 merge；遵循 TDD；
- spec 与设计文档随实现 PR 同步（本期涉及 `docs/product/spec/site-pages.md`、`docs/product/spec/calendar.md`、`docs/design/02-page-design.md`、`apps/bookstore/AGENTS.md`）。

- 视差幅度/粒子密度的用户偏好设置；
