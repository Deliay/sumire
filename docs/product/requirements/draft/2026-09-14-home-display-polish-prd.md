# 首页展示优化

**功能名称**: 首页展示优化（Home Display Polish）
**PRD 版本**: v1.0
**创建日期**: 2026-09-14
**作者**: sumire workflow

## 一、背景与目标

### 1.1 背景

首页采用整页翻页（deck）形态（`apps/bookstore/features/home/FullpageDeck.tsx` + `useFullpageScroll.ts`），其中档案各站（`SplitSection.tsx`，挂 `data-fullpage-scrollable`）与日历站（`CalendarSection.tsx`）内容可滚动。当前移动端存在三类体验问题，另有一项内容维护需求：

1. **滚动交接缺失**：移动端在设定页（档案第 2 站 Story）等内容产生滚动条的页面，内容滑到最底部后继续下滑，无法翻到下一页。根因是触摸/滚轮手势只要起点在可滚动容器内就被整段豁免（`useFullpageScroll.ts` 中 `isInsideScrollable` 只判断目标是否在可滚动容器内，不判断滚动边界），导致触底后手势既无法继续滚动也无法翻页。
2. **日历页与导航栏重叠**：移动端日历站顶部仅有 `py-3`（12px）内边距，独立 `/calendar` 页顶部为 `py-14`（56px），均未为 `fixed` 顶部导航栏（NavBar，高 64px，`NavBar.tsx:144`）留足空间，日历内容与导航栏重叠。
3. **导航栏透明压字**：移动端 NavBar 默认透明（仅滚动 >24px 或菜单展开后才出现 `bg-night/85 backdrop-blur-md`），透明态下导航文字直接压在页面内容上，可读性差，需要背景模糊。
4. **内容更新**：素材库（`content/assets.yaml`，当前仅 5 条）与档案内容（`content/profile.yaml`）需依据萌娘百科条目（`https://zh.moegirl.org.cn/枝堇`）与 B 站个人空间/动态（`https://space.bilibili.com/1150976664`）的官方公开信息更新。

### 1.2 目标

- 移动端可滚动站在滚动到顶/到底后，继续同向滑动可正常交接给 deck 翻到上/下一页；
- 日历站与独立日历页在移动端与固定导航栏之间有足够间距，不再重叠；
- 移动端导航栏默认即带背景模糊，文字与页面内容有清晰分层；
- 素材库与档案内容同步官方公开信息（萌娘百科、B 站主页/动态），保持「所有内容以官方公开信息为准，禁止二次设定」。

### 1.3 成功标准

- [ ] 移动端在设定站（档案 Story）内容滑到底后继续下滑翻到下一站；滑到顶后继续上滑翻回上一站；日历站同样生效；
- [ ] 内容未滑到边界时，滚动容器内的手势仍表现为原生滚动，不误触发翻页；
- [ ] 桌面端滚轮在可滚动列内触底/触顶后继续同向滚动同样交接翻页；
- [ ] 移动端日历站与独立 `/calendar` 页内容顶部与 NavBar 无重叠（顶部留白 ≥ NavBar 高度 64px）；
- [ ] 移动端任意页面（含未滚动态）NavBar 均带背景模糊与底色，导航文字清晰可读；桌面端 NavBar 现有行为（透明 → 滚动后雾化）不变；
- [ ] 素材库与档案内容完成一次以官方信息源为准的核对与更新；新增素材图片入库且缩略图生成正常，素材页正常展示。

## 二、用户分析

### 2.1 目标用户

- 移动端访客：占粉丝站移动流量主体，在手机上浏览首页 deck、档案与日历；
- 桌面端访客：使用滚轮在首页 deck 中浏览；
- 内容维护者：维护素材库与档案 YAML 内容。

### 2.2 用户场景

| 场景 | 用户角色 | 目标 | 痛点（现况） |
|------|----------|------|------|
| 移动端读完设定翻页 | 移动端访客 | 设定文字滑到底后继续下滑进入下一站 | 滑到底后手势失效，无法翻页，只能点导航或位置指示器 |
| 移动端看日历 | 移动端访客 | 打开日历查看日程 | 日历顶部与导航栏重叠，首行内容被压住 |
| 移动端浏览任意页 | 移动端访客 | 清晰看到导航入口 | 导航栏透明，文字压在页面内容上难以辨认 |
| 浏览素材/档案 | 访客 | 看到最新官方素材与档案信息 | 素材库仅 5 条，档案信息未随官方动态更新 |

## 三、功能需求

### 3.1 功能概述

本期为首页展示打磨：F1/F2/F3 为移动端（F1 兼桌面滚轮）交互与样式修复，纯前端变更；F4 为构建期 YAML 内容与静态素材更新。无 API、无契约、无数据库变更。

### 3.2 功能列表

#### F1 可滚动站滚动边界交接翻页

**描述**:

- 在挂 `data-fullpage-scrollable` 的可滚动站（档案各站内容列、日历站）内：
  - 触摸手势起点在可滚动容器内时，手势先交给原生滚动；
  - 当容器已滚动到底部（`scrollTop + clientHeight ≥ scrollHeight`）且手势继续向下滑动时，剩余手势交接给 deck，翻到下一页；
  - 当容器已滚动到顶部（`scrollTop ≤ 0`）且手势继续向上滑动时，交接翻到上一页；
  - 容器未在边界时，手势维持原生滚动，不触发翻页（现状不变）；
- 桌面端滚轮同样适用：指针在可滚动列内且列已到边界时，同向滚轮交接翻页；未到边界时列内滚动（现状不变）；
- 交接判定需与既有手势阈值、冷却（`TOUCH_THRESHOLD`/`WHEEL_THRESHOLD`/`COOLDOWN`）兼容，不产生连翻、回弹误翻。

**验收标准**:

- [ ] 移动端设定站（档案 Story）内容滑到底后，继续下滑触发翻页到下一站；
- [ ] 移动端设定站内容滑到顶后，继续上滑翻回上一站；
- [ ] 移动端日历站整页可滚动区同样支持触底/触顶交接翻页；
- [ ] 内容未滑到边界时，容器内手势只滚动内容，不翻页；
- [ ] 桌面端滚轮在可滚动列内未到底时列内滚动，到底后继续同向滚动翻页；
- [ ] 交接翻页仍受翻页冷却约束，单次手势不连翻多页；
- [ ] 桌面端不可滚站（hero、素材架等）的翻页行为零回归。

#### F2 日历页顶部间距

**描述**:

- deck 内日历站（`CalendarSection.tsx`）顶部内边距调整为 ≥ NavBar 高度（64px）加视觉余量，移动端与桌面端均不与固定导航栏重叠；
- 独立 `/calendar` 页（`CalendarViewPage.tsx` 非 compact 形态）顶部内边距同步调整，与 `/about` 等独立内容页（`pt-28`）的导航留位口径一致；
- 仅调整顶部间距，不改变日历布局、周/月视图断点行为。

**验收标准**:

- [ ] 移动端首页 deck 滑到日历站时，日历内容顶部与 NavBar 无重叠；
- [ ] 移动端独立 `/calendar` 页首屏页头/日历不被 NavBar 压住；
- [ ] 桌面端日历站与 `/calendar` 页同样无重叠且视觉上不产生过大空白；
- [ ] 日历周/月视图切换、拖拽等既有交互零回归。

#### F3 移动端导航栏背景模糊

**描述**:

- 移动端（< md 断点）下 NavBar 默认态（未滚动、菜单未展开）即带底色与背景模糊（与现滚动态 `bg-night/85 backdrop-blur-md` 视觉一致）；
- 桌面端（≥ md）保持现状：默认透明，滚动或菜单展开后雾化；
- 移动端菜单展开态、滚动态样式不变（已有雾化）。

**验收标准**:

- [ ] 移动端任意路由首屏（未滚动）NavBar 即带背景模糊与底色；
- [ ] 移动端滚动、菜单展开/收起过程中 NavBar 样式无闪烁、无样式断层；
- [ ] 桌面端 NavBar 透明 → 滚动雾化的现有行为不变；
- [ ] 导航链接、汉堡按钮在雾化背景上对比度可读。

#### F4 素材库与档案内容更新

**描述**:

- 以萌娘百科条目与 B 站个人空间/动态的官方公开信息为准，核对并更新：
  - `content/profile.yaml`：档案字段、里程碑（milestones）、轶事（anecdotes）等，补充官方新增的公开信息，修正与官方口径不一致的内容；
  - `content/assets.yaml`：新增官方公开的素材（立绘/插画/宣传图等），图片文件入 `public/assets/original/`，经既有 `pnpm thumbnails` 流程生成缩略图；
- 全部内容遵循站点原则：所有内容以官方公开信息为准，禁止二次设定；素材版权归主播及所属社团所有；
- 每条新增内容可溯源到官方信息源（萌娘百科条目或 B 站动态/投稿）。

**验收标准**:

- [ ] `profile.yaml` 与官方公开信息完成一次核对，差异项已更新（无差异则记录核对结论）；
- [ ] `assets.yaml` 新增素材条目字段完整（id/title/category/file/width/height/note），图片文件存在于 `public/assets/original/` 且缩略图已生成；
- [ ] 素材页（首页素材架与 `/assets`）正常展示新增素材，分类筛选、Lightbox 零回归；
- [ ] 新增内容均可溯源至官方信息源，无二设内容。

### 3.3 页面/界面描述

- F1 无视觉变化，纯手势行为修复；
- F2 日历顶部留白与 `/about` 独立页口径一致（视觉评审可微调具体间距值）；
- F3 移动端 NavBar 默认态视觉与现滚动态一致（`bg-night/85` + `backdrop-blur-md`），不引入新视觉样式；
- F4 素材卡片沿用素材架既有网格与 Lightbox，无新增 UI。

### 3.4 异常与边界情况

| 情况 | 预期行为 |
|------|----------|
| 可滚动容器内容刚好不溢出 | 不视为可滚动站，手势直接翻页（现状 `scrollHeight > clientHeight` 判断不变） |
| 手势在边界处斜向滑动 | 以既有位移阈值与方向判定为准，不额外引入方向锁 |
| 交接后容器仍处边界且用户持续按住滑动 | 单次手势只交接一次翻页，受冷却约束不连翻 |
| 移动端浏览器自身回弹（overscroll） | 交接翻页与原生回弹不叠加出双重位移；必要时以 `overscroll-behavior` 约束容器 |
| F4 官方信息源不可访问 | 以最近一次可访问的官方信息为准并在 PR 中说明，不编造内容 |
| 新增素材图片尺寸/格式异常 | 不入库；保持 `assets.yaml` 与实际文件一致 |

## 四、非功能需求

### 4.1 性能

- F1 仅在既有手势监听链路中增加边界判断，不新增监听器、不引入 `preventDefault`（保持被动监听与滚动性能）；
- F3 复用既有 Tailwind 类，无新增运行时开销；
- F4 为构建期内容，新增素材需压缩至合理体积（沿用既有素材入库惯例）。

### 4.2 安全性

- 无新增输入面；F4 图片为静态资源，构建期入库。

### 4.3 兼容性

- F1 兼容既有点按、拖拽日历等触摸交互（日历拖拽交互区不受影响）；
- F2/F3 不改变断点体系（沿用 `md`/`lg`）；
- 全部变更不影响 SSG 输出结构。

## 五、依赖与约束

### 5.1 依赖

- F4 依赖官方信息源可访问性：萌娘百科条目、B 站个人空间/动态；
- F4 依赖既有缩略图生成脚本 `pnpm thumbnails`。

### 5.2 约束

- 仅改动 `apps/bookstore` 前端与 `content/`、`public/assets/` 内容；不动 API、契约与编排；
- 遵循 `docs/engineering/frontend-rules.md` 与 TDD（手势交接逻辑先补失败用例再实现）；
- 分支命名 `prd/<slug>` 需求总分支，禁 rebase/squash；
- 内容更新遵循「以官方公开信息为准，禁止二次设定」。
