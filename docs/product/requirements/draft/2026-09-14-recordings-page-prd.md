# 录播页（Recordings Page）

**功能名称**: 录播页（Recordings Page）
**PRD 版本**: v1.0
**创建日期**: 2026-09-14
**作者**: sumire workflow

## 一、背景与目标

### 1.1 背景

录播服务（内网 `http://vtuber.internal.fffdan.com`，外网 `https://recordings.vtuber.fffdan.com`）已对本社主播直播间进行自动录制，并提供录制状态、录播文件列表、单场录播文件与实时直播音频流四组 API。本站（堇色书屋）目前没有任何录播相关内容入口，访客无法获知录制状态，也无法回听录播。

经实测，上游服务响应无 CORS 头（`OPTIONS` 预检 405、无 `Access-Control-Allow-Origin`），浏览器无法从前端源站直接跨域调用，需由本站 API（`servers/api`）按既有「上游代理 + 短缓存 + 静默降级」模式（参照 live-status / live-history）进行中转。

导航现态以 `docs/product/spec/site-pages.md` 与 `apps/bookstore/components/NavBar.tsx` 为准：导航末尾现有「小密室」外链项（`https://sumire.icu`，2026-09-13 上线）。本期将其从导航下架，移至 Footer 外链区，腾出导航位置给「录播」。

### 1.2 目标

- 新增 `/recordings` 「录播」独立页面，包含：实时录制状态列表、听直播、按直播间展开的录播列表、FLV 在线预览与下载；
- 顶部导航栏新增「录播」入口，桌面端与移动端折叠菜单均展示；
- 导航栏下架「小密室」，在 Footer 外链区新增「小密室」链接（保持可访问性不丢失）。

### 1.3 成功标准

- [ ] `/recordings` 路由可访问，渲染实时录制状态列表、录播列表与播放区；
- [ ] 录制中的直播间展示「听直播」入口，点击后可播放实时音频；
- [ ] 点击录播文件可在线播放，也可下载到本地；
- [ ] 桌面端与移动端导航均出现「录播」，点击跳转 `/recordings`，且在 `/recordings` 下呈现选中态；
- [ ] 导航中不再出现「小密室」；Footer 外链区出现「小密室」（`https://sumire.icu`，新窗口打开）；
- [ ] 上游不可用 / 未配置 API 时页面静默降级（空态提示），不产生报错页。

## 二、用户分析

### 2.1 目标用户

- 站点访客（未登录）：错过直播、希望回听录播或实时旁听的主播观众。

### 2.2 用户场景

| 场景 | 用户角色 | 目标 | 痛点（现况） |
|------|----------|------|------|
| 查看谁在录制/直播 | 访客 | 一眼看到当前哪些直播间正在录制 | 站内无入口，需自行访问录播服务 |
| 实时旁听直播 | 访客 | 不看画面只听声音 | 无音频-only 的收听入口 |
| 回听历史录播 | 访客 | 按直播间找到某场录播并在线听或下载 | 无录播列表与播放能力 |

## 三、功能需求

### 3.1 功能概述

本期新增公开页 `/recordings`（置于 `(site)/(content)` 路由组，自动获得 NavBar + Footer 外壳），数据全部来自录播服务四组 API（经本站 API 代理，详见技术提案）；同步调整导航与 Footer。登录态无关：全部功能面向匿名访客。

上游 API（单一事实源为录播服务，本站不存储任何录播数据）：

| 上游端点 | 用途 | 实测响应要点 |
|----------|------|--------------|
| `GET /api/b/live/recording-status` | 正在录制列表 | `{items: [{mid, roomId, state, sessionTitle, files, updatedAt, streamer: {name}}]}`，`state` 已观测值：`recording` / `not_live` |
| `GET /api/b/live/:roomId/recordings` | 某直播间录播列表 | `{files: [{name, size, createdAt}]}` |
| `GET /api/b/live/:roomId/recordings/:fileName` | 单场录播文件 | FLV 字节流，`Content-Disposition: attachment` |
| `GET /api/b/live/:roomId/live-stream/audio` | 实时直播音频流 | 长连接 FLV 流（`Content-Type: video/x-flv`） |

### 3.2 功能列表

#### F1 导航「录播」入口与「小密室」迁移

**描述**:

- 导航栏新增「录播」站内路由项，指向 `/recordings`，位置在「日历/棉花糖」之后、工具项之前（与既有独立路由项同组）；
- 该项在 `/recordings` 路由下呈现选中态高亮；首页内点击不触发 deck 翻页（独立路由跳转，与「棉花糖」一致）；
- 仅 `NEXT_PUBLIC_API_BASE_URL` 已配置（`API_CONFIGURED`）时显示（与「日历」「棉花糖」的门控一致）；未配置时不渲染该入口；
- 导航移除「小密室」外链项；Footer 外链区（B 站空间 / 直播间 / 萌娘百科之后）新增「小密室」，指向 `https://sumire.icu`，`target="_blank"` + `rel="noopener noreferrer"`，样式与既有 Footer 外链一致。

**验收标准**:

- [ ] 桌面端导航与移动端折叠菜单均含「录播」，点击跳转 `/recordings`；
- [ ] `/recordings` 下「录播」项有 `aria-current` 选中态；其他路由下无；
- [ ] 导航（桌面 + 移动）不再渲染「小密室」；
- [ ] Footer 渲染「小密室」外链，`href="https://sumire.icu"`、`target="_blank"`、`rel` 含 `noopener` 与 `noreferrer`；
- [ ] 未配置 API 时「录播」入口不显示，Footer「小密室」仍显示（Footer 为纯静态）；
- [ ] 既有导航项（主页/档案/素材/日历/棉花糖/工具项）行为零回归。

#### F2 实时录制状态列表

**描述**:

- 页面顶部区块展示当前录制状态列表，数据来源 `recording-status`；
- 每项只展示必要信息：主播名、录制状态（录制中 / 未在直播）、当前场次标题（`sessionTitle`，可空）、状态更新时间；
- 客户端定时轮询刷新（建议 30s，页面不可见时暂停），无需手动刷新；
- 列表为空或上游不可用时展示空态文案（如「暂无录制中的直播间」/「录播服务暂时不可用」），不报错。

**验收标准**:

- [ ] 列表正确渲染各直播间的名称与状态，录制中状态有明确视觉标识；
- [ ] 轮询间隔约 30s，页面隐藏（`document.hidden`）时暂停、恢复可见时立即刷新一次；
- [ ] 上游 5xx / 网络错误时展示降级空态，页面其余区块可正常使用。

#### F3 听直播

**描述**:

- 录制状态列表中，状态为「录制中」的直播间展示「听直播」按钮；
- 点击后播放该直播间的实时音频流（`live-stream/audio`），页面内播放不跳转；
- 同时只允许一路播放：点击另一间的「听直播」时停止当前播放；
- 播放中按钮变为「停止」态，可手动停止；流中断时给出提示并复位按钮；
- 状态为「未在直播」的直播间不展示该按钮。

**验收标准**:

- [ ] 录制中直播间出现「听直播」，点击后开始出声（音频流播放）；
- [ ] 播放中点击「停止」或切换到另一直播间，原流停止；
- [ ] 流加载失败 / 中途断开时按钮复位并展示失败提示；
- [ ] 离开 `/recordings` 页面后播放停止（组件卸载即断流）。

#### F4 录播列表（按直播间折叠展开 + 前端分页）

**描述**:

- 页面中部为录播列表区：以直播间为单位的分组列表（直播间名单来自 `recording-status` 的 items，含未在直播的直播间），默认折叠；
- 点击某个直播间展开（穿透进入），拉取并展示该直播间的录播文件列表（`recordings`），再次点击折叠；
- 文件项展示必要信息：文件名（或解析出的录制时间 + 场次标题）、文件大小（人性化单位）、创建时间；
- 单直播间文件较多时前端分页（建议每页 20 条），纯客户端分页，不重复请求；
- 列表按创建时间倒序展示；
- 展开后加载失败展示该分组内的错误态与「重试」，不影响其他分组。

**验收标准**:

- [ ] 默认仅展示直播间分组头（名称 + 文件数或折叠指示），点击展开后加载文件列表；
- [ ] 文件列表按 `createdAt` 倒序，超过一页时展示分页控件且翻页不重新请求；
- [ ] 展开中的分组可再次折叠；同时允许展开多个分组；
- [ ] 某分组加载失败时仅该分组显示错误与重试入口。

#### F5 FLV 在线预览与下载

**描述**:

- 录播文件列表中，点击某个文件即选中并在页面内播放区在线预览（FLV 流式播放，边下边播）；
- 播放区包含：播放/暂停、音量、播放进度展示（如上游不支持拖动定位则只允许顺序播放，进度条可只读）、关闭播放区；
- 每个文件项同时提供「下载」入口，点击后浏览器下载该 FLV 文件（文件名保持上游原始命名）；
- 在线预览与下载针对同一文件 URL，不额外生成链接；
- 同时只允许一路预览：选中另一文件时停止当前播放并切换。

**验收标准**:

- [ ] 点击文件项后播放区出现并开始流式播放对应 FLV；
- [ ] 播放区可暂停/继续、调节音量、关闭；
- [ ] 点击「下载」触发浏览器下载，保存文件名与上游一致；
- [ ] 切换文件时旧流停止；离开页面后播放停止；
- [ ] 播放失败（文件已删除/网络错误）时展示错误提示，不影响列表操作。

### 3.3 页面/界面描述

- 整体遵循 `docs/design/02-page-design.md`：内容区 `max-w-6xl` 居中，深色雨夜书屋基调，卡片用 `PaperCard` / 深色卡片风格，录制中状态用药丸形标识（参照 `LiveStatus` 的 eye 色呼吸点语义），交互元素键盘可达、焦点环用 `--color-flower`；
- 页面结构自上而下：页面标题「录播」+ 简介 → 实时录制状态（F2/F3）→ 录播列表（F4）→ 播放区（F5，可为列表下方的固定区块或选中项附近展开，实现时以设计评审为准）；
- 移动端单列布局，播放区宽度自适应，按钮可触达；
- 空态、加载中、错误态均有文案，风格与站内既有空态一致。

### 3.4 异常与边界情况

| 情况 | 预期行为 |
|------|----------|
| 未配置 API（`API_CONFIGURED=false`） | 导航无「录播」入口；直接访问 `/recordings` 展示「服务未配置」空态，不发起请求 |
| 上游录播服务不可用 | 各区块静默降级为空态/错误态，页面不白屏、无 5xx 传导 |
| `recording-status` 中直播间无任何录播文件 | 分组可展开，展示「暂无录播」 |
| 录播文件在播放/下载途中被上游删除 | 播放区/下载报错提示，列表下次刷新后该项消失 |
| 文件名含中文与特殊字符 | 正确编码请求路径，下载文件名保持原样 |
| 录制中的当前场次文件出现在列表中 | 照常展示；若上游不允许下载未完结文件，播放/下载失败时按失败提示处理 |
| 多直播间同时录制中 | 各自展示「听直播」，但同时只播一路 |

## 四、非功能需求

### 4.1 性能

- 站点为静态导出（SSG），本页动态数据全部客户端按需拉取；录制状态 30s 轮询，录播文件列表仅展开时拉取一次；
- 音频流与 FLV 预览为流式传输，前端不做整文件缓冲；大文件（实测单场可达数 GB）下载交给浏览器原生下载；
- 代理层对媒体流不做缓存（`no-store`），对元数据接口做短 TTL 缓存（对齐 live-status 30s 模式）。

### 4.2 安全性

- 全部端点公开只读，不涉及登录态与用户数据；
- 代理仅放行白名单化的上游路径（roomId 数字校验、fileName 防路径穿越），不开放任意 URL 转发；
- 页面渲染文件名、场次标题等上游文本时按纯文本处理，不注入 HTML。

### 4.3 兼容性

- 在线播放依赖 MSE（Media Source Extensions）：覆盖现代桌面与 Android Chrome；iOS Safari 对 MSE 支持受限，其降级表现为「可下载、不可在线预览」，需在播放区给出提示（具体降级方案以技术提案与实现评审为准）；
- 桌面与移动端断点表现遵循 `docs/design/02-page-design.md`。
