# 录播文件项操作按钮组（播放优化）

**功能名称**: 录播文件项操作按钮组（Recording File Actions）
**PRD 版本**: v1.0
**创建日期**: 2026-09-15
**作者**: sumire workflow

## 一、背景与目标

### 1.1 背景

录播页 `/recordings` 已上线（2026-09-14 需求），单场录播文件项的现态为：左侧文件名（点击内联展开/折叠播放器）、中间文件大小与创建时间、右侧一个「下载」文字链（`<a href download>`，实现见 `apps/bookstore/features/recordings/RoomRecordingsGroup.tsx`，现态行为见 `docs/product/spec/site-pages.md` F5 节）。

现态问题：

- 「下载」作为文件项唯一的常驻操作按钮占据了最显眼的位置，但回听录播的**主路径是在线播放**，下载是次要路径；
- 文件名的「点击即播放」是隐式交互，新访客不易发现可以在线听；
- 单场录播文件可达数 GB，常驻「下载」按钮也增加了误触下载的概率。

### 1.2 目标

- 将单场录播右侧的「下载」按钮改为**按钮组（split button）**：默认主按钮为「播放」，右侧为下拉开关；
- 点击下拉开关才展开菜单，菜单中提供「下载」入口；
- 「播放」与点击文件项等效（内联展开/折叠该文件的播放器），下载行为与现态完全一致。

### 1.3 成功标准

- [ ] 录播文件项右侧不再直接展示「下载」链接，而是「播放 ▾」按钮组；
- [ ] 点击「播放」内联展开该文件的播放器，再次点击（或展开其他文件）后复位；
- [ ] 点击下拉开关展开菜单，菜单中有且仅有「下载」入口，点击触发浏览器原生下载；
- [ ] 菜单可通过点击外部 / Esc 关闭，键盘可达；
- [ ] 既有录播列表行为（折叠分组、分页、单例播放、MSE 降级）零回归。

## 二、用户分析

### 2.1 目标用户

- 站点访客（未登录）：回听录播的主播观众，主路径是在线试听，少数情况下需要下载到本地。

### 2.2 用户场景

| 场景 | 用户角色 | 目标 | 痛点（现况） |
|------|----------|------|------|
| 在线回听某场录播 | 访客 | 找到文件直接在线听 | 唯一的常驻按钮是「下载」，不知道点文件名可以在线播放 |
| 下载录播到本地 | 访客 | 保存某场录播 | 无痛点，但下载不应是最显眼的默认操作 |
| 移动端浏览录播 | 访客 | 单手触达操作 | 「下载」文字链热区小，且误触即触发大文件下载 |

## 三、功能需求

### 3.1 功能概述

本期仅改动录播页文件项的操作区（`RoomRecordingsGroup` 文件行右侧）：将单个「下载」文字链替换为「播放 + 下拉」按钮组。不涉及导航、分组折叠、分页、播放器本体（时间跳转/全屏属另一并行需求）、`FlvPlayerPanel` 内部的 MSE 降级下载按钮，均为纯前端变更。

### 3.2 功能列表

#### F1 文件项操作按钮组（播放 / 下拉 / 下载）

**描述**:

- 录播文件项右侧的「下载」文字链移除，替换为按钮组：
  - **主按钮「播放」**：点击后与点击该文件项等效——内联展开该文件的播放器（手风琴式，全局单例：展开其他文件或再次点击即折叠）；该文件播放器处于展开态时，主按钮变为「收起」态（或等价的高亮激活态，以实现评审为准），点击折叠播放器；
  - **下拉开关**：主按钮右侧的 `▾` 开关按钮，点击展开下拉菜单，再次点击、点击菜单外区域或按 Esc 关闭；
  - **下拉菜单**：仅含「下载」一项，为 `<a href={recordingFileUrl(roomId, file.name)} download>`，与现态下载行为完全一致（同源 URL，命中上游 `Content-Disposition: attachment` 原生下载，文件名保持上游原始命名）；点击「下载」后菜单关闭；
- 文件项文件名的「点击展开/折叠播放器」既有行为**保持不变**（与「播放」按钮等效，双入口）；
- 按钮组在桌面端与移动端均展示，移动端热区可触达（最小触控尺寸遵循设计规范）。

**验收标准**:

- [ ] 文件项右侧渲染「播放 ▾」按钮组，不再直接渲染裸「下载」链接；
- [ ] 点击「播放」后该文件下方内联出现播放器，按钮呈现展开态；点击「收起」/其他文件的「播放」/关闭播放器后按钮复位为「播放」；
- [ ] 同时只有一个文件的按钮组处于展开态（与全局单例播放一致）；
- [ ] 默认不展示「下载」；点击 `▾` 后菜单出现且包含「下载」，其 `href` 与现态下载链接一致并带 `download` 属性；
- [ ] 点击「下载」触发浏览器下载且菜单关闭；点击菜单外或按 Esc 菜单关闭且不触发任何操作；
- [ ] 下拉开关带 `aria-haspopup` / `aria-expanded`，菜单项键盘可达，焦点环遵循 `--color-flower`；
- [ ] 未配置录播服务地址 / 上游不可用等既有降级形态不受影响；
- [ ] 既有用例零回归（分组折叠、分页、听直播、播放器、MSE 降级提示）。

### 3.3 页面/界面描述

- 按钮组视觉遵循 `docs/design/02-page-design.md` 与录播页现态：深色卡片上的小尺寸文字按钮，主按钮与下拉开关视觉上连为一体（同一描边容器内分段），悬停 `hover:text-flower`，焦点环 `--color-flower`；
- 下拉菜单为小型深色浮层（对齐站内既有弹层/菜单风格），定位于按钮组下方右侧对齐，不遮挡相邻文件项的主要信息；
- 移动端按钮组保持单行内可触达，文件行其余信息（文件名/大小/时间）布局不因按钮组换行而破坏。

### 3.4 异常与边界情况

| 情况 | 预期行为 |
|------|----------|
| 展开下载菜单后切换到其他文件播放 | 原文件的菜单保持原状或关闭均可（以实现简单为准），其按钮组复位为「播放」 |
| 菜单展开中翻页 / 折叠分组 | 菜单随该文件项卸载而消失，无残留浮层 |
| iOS Safari（MSE 不支持）点击「播放」 | 展开区展示既有的「不支持在线播放，请下载后收听」降级提示（`FlvPlayerPanel` 既有行为），按钮组本身不变 |
| 播放失败 / 播放器被关闭 | 按钮复位为「播放」态 |
| 菜单展开时按 Esc | 仅关闭菜单，不折叠已展开的播放器 |
| 快速连续点击「播放」 | 由既有单例播放器逻辑串行化，不产生多个播放器实例 |

## 四、非功能需求

### 4.1 性能

- 纯前端交互变更，无新增请求；菜单为组件内 state，不引入全局状态；
- 不新增运行时依赖（图标沿用既有 `lucide-react`）。

### 4.2 安全性

- 「下载」仍为指向录播服务的静态 `<a href download>`，`fileName` 路径编码沿用既有 `recordingFileUrl()`，不引入新的输入面。

### 4.3 兼容性

- 按钮组与菜单仅使用既有浏览器能力，桌面与移动端断点表现遵循 `docs/design/02-page-design.md`；
- 键盘操作（Tab 聚焦、Enter/Space 触发、Esc 关闭）可用。

## 五、依赖与约束

### 5.1 依赖

- 录播页与播放器现态（`docs/product/spec/site-pages.md` F4/F5）保持不变，本需求仅叠加于文件项操作区；
- 录播服务四组端点行为不变（本期不新增消费）。

### 5.2 约束

- 仅改动 `apps/bookstore` 前端（含单测/e2e），不动 `servers/api`、契约与编排资源配置；
- 遵循 `docs/engineering/frontend-rules.md` 与 TDD（先测试后实现）；
- 分支命名 `<type>/<slug>`：`prd/recordings-play-actions` 需求总分支，禁 rebase/squash；
- 与并行的「录播时间跳转 + 全屏」需求（`prd/recordings-seek-fullscreen`，PR #134/#135）变更面不同（本需求只动文件项操作区，不动 `FlvPlayerPanel`），实现时如有文件级冲突以后合入者为准做 merge；
- 实现 PR 内同步 `docs/product/spec/site-pages.md` 与 `docs/engineering/spec/frontend-bookstore.md`。
