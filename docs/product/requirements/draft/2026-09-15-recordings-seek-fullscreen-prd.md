# 录播播放优化一期（时间跳转修复 + 全屏）

**功能名称**: 录播播放优化一期（时间跳转修复 + 全屏）
**PRD 版本**: v1.0
**创建日期**: 2026-09-15
**作者**: sumire workflow

## 一、背景与目标

### 1.1 背景

录播页（`/recordings`，2026-09-14 上线）F5 提供 FLV 在线预览，现态见 `docs/product/spec/site-pages.md`「录播页 `/recordings`」节：因当时上游不支持 Range（经 dev 代理实测返回 200、无 `Accept-Ranges`），进度条按「不可拖动 + 明示提示」降级，seek 由 `probeSeekable()` 探测门控。

**上游现已支持 Range**（2026-09-15 实测外网地址：`Range: bytes=0-1023` 返回 `206`、`Accept-Ranges: bytes`、正确的 `Content-Range`，且 CDN 已缓存分片）。探测门控随之放开，但暴露出新问题：**在录播播放界面点击/拖动时间轴跳转，整个播放界面卡死**——画面冻结、进度不再推进、控件失去响应。

根因初判（源码级，详见技术提案）：上游 FLV 由录制端直接 dump（`encoder: Lavf60.16.100`，实测 `onMetaData` 仅含 `duration`/`width` 等基础字段，**不含 `keyframes` 关键帧索引**）；mpegts.js 对未缓冲位置的 seek 依赖关键帧索引做「时间 → 字节偏移」映射，`MediaInfo.isSeekable() === false` 时 `transmuxer.seek()` 静默 return，而播放器侧的未缓冲 seek 校正逻辑以 50ms 间隔无限重试，表现为整体卡死。上游文件为 GB 级只读产物，前端无法为其注入索引。

第二项需求：播放控件需支持**全屏**（浏览器 Fullscreen API）与**网页全屏**（播放器铺满视口、页面其余内容隐藏的"剧场模式"），便于长时间回听。

### 1.2 目标

- 修复时间轴跳转卡死：进度条可拖动/点击跳转到任意时间点，跳转后正常续播，任何情况下不卡死；
- 播放控件新增「全屏」与「网页全屏」能力，全屏态下控件可用、可退出；
- 保持既有降级语义：上游不支持 Range 时进度条仍禁用并明示；iOS 等无 MSE 环境维持「下载后收听」降级。

### 1.3 成功标准

- [ ] 拖动/点击进度条跳转到已缓冲区间，即时续播；
- [ ] 跳转到未缓冲区间，播放器重新拉流并在可接受等待（秒级）后续播，期间有明确缓冲/加载反馈，页面与控件不卡死；
- [ ] 连续多次拖动、拖动途中切换文件/关闭播放区/离开页面，均不卡死、不错乱；
- [ ] 播放控件提供「全屏」「网页全屏」入口，进入后控件可操作，ESC 或按钮可退出并还原布局；
- [ ] 上游 Range 不可用的环境（如本地代理未透传）进度条禁用并明示，不静默失败；
- [ ] 既有听直播、折叠列表、下载、MSE 降级行为零回归。

## 二、用户分析

### 2.1 目标用户

- 站点访客（未登录）：回听录播的主播观众。单场录播普遍数小时、数 GB（实测单场可达 5 GB），顺序听完不现实，拖动定位是刚需。

### 2.2 用户场景

| 场景 | 用户角色 | 目标 | 痛点（现况） |
|------|----------|------|------|
| 定位到精彩片段 | 访客 | 拖动时间轴跳到想听的时间点 | 一点就整体卡死，只能从头听 |
| 长时回听 | 访客 | 大屏/沉浸观看画面 | 播放器尺寸固定，无全屏能力 |

## 三、功能需求

### 3.1 功能概述

本期仅改动录播页 F5 在线预览播放区（`features/recordings/FlvPlayerPanel.tsx` + `player.ts`），为纯前端变更：不改 `servers/api`、不改契约、不改编排资源。数据通路与配置降级口径（`RECORDINGS_CONFIGURED` / `probeSeekable`）沿用现态。

### 3.2 功能列表

#### F1 时间轴跳转修复

**描述**:

- 进度条保持可拖动（`probeSeekable` 探测上游 Range 支持的现有门控保留）；
- 跳转到**已缓冲**区间：直接定位，即时续播；
- 跳转到**未缓冲**区间：播放器以 Range 请求从跳转点附近重新拉流，demux 后从最近可解码位置续播；期间展示明确的缓冲中反馈（如进度条/按钮 loading 态），**不得出现画面冻结且无反馈的"卡死"态**；
- 无关键帧索引导致的落点误差为用户可接受形态：续播起点为目标时间附近的近似位置（以实际续播时间刷新进度条与时间显示），不要求帧级精确；
- 跳转失败（网络错误、上游异常）展示既有播放失败提示，可重试，不影响列表其它操作；
- 连续快速拖动以最后一次落点为准，不堆积过期请求。

**验收标准**:

- [ ] 已缓冲区间内拖动，松手即续播，无额外请求；
- [ ] 未缓冲区间拖动，进度条展示缓冲反馈，数秒内从新位置出声/出画面，页面其它区域（列表、导航）始终可交互；
- [ ] 拖动到接近文件末尾、文件开头（0 附近）均能正确处理；
- [ ] 快速连续拖动 N 次，仅最后一次生效，无死循环与内存泄漏（player 实例仍全局唯一）；
- [ ] 拖动途中切换文件、关闭播放区、离开 `/recordings`，旧流正确销毁；
- [ ] 上游 Range 探测失败时进度条禁用并展示「当前上游不支持拖动进度」（现态语义不变）。

#### F2 播放控件全屏与网页全屏

**描述**:

- 播放区控制条新增两个入口：「全屏」「网页全屏」；
- **全屏**：整个播放区（画面 + 控制条）经 Fullscreen API 进入系统全屏；控制条在全屏态保持可用（播放/暂停、进度、音量、退出）；按 ESC 或点击「退出全屏」还原；
- **网页全屏**：播放区铺满浏览器视口（页面其余内容不可见、背景滚动锁定），同样保持控件可用与可退出；与系统全屏互斥（进入一种时退出另一种）；
- 全屏状态随系统事件同步（如用户按 ESC 触发 `fullscreenchange`，按钮态随之复位）；
- 浏览器不支持 Fullscreen API 时隐藏「全屏」入口（「网页全屏」为纯 CSS 实现，不依赖该 API）。

**验收标准**:

- [ ] 点击「全屏」进入系统全屏，画面与控制条占满屏幕，控件可正常操作；
- [ ] 全屏态 ESC 或点击退出按钮还原为页内布局，按钮态正确复位；
- [ ] 点击「网页全屏」播放器铺满视口、页面背景不可滚动，退出后还原滚动与布局；
- [ ] 两种全屏互斥切换不叠加；全屏中切换文件/关闭播放区时先退出全屏再执行；
- [ ] 移动端视口下「网页全屏」可用、按钮可触达。

### 3.3 页面/界面描述

- 播放区视觉沿用现态（16:9 黑底画面 + 控制条），新增按钮置于控制条右侧（音量之后），图标风格与既有 `lucide-react` 图标一致；
- 网页全屏态背景为纯黑/深色，播放器居中，控制条位置与页内态一致，焦点环沿用 `--color-flower`；
- 缓冲中反馈与空态/错误态文案风格与站内既有语义一致；
- 键盘可达：新增按钮可 Tab 聚焦、Enter/Space 触发。

### 3.4 异常与边界情况

| 情况 | 预期行为 |
|------|----------|
| 无关键帧索引导致 seek 落点偏差 | 允许近似落点，以实际续播位置刷新 UI，不卡死 |
| 跳转到未缓冲区间后网络失败 | 展示播放失败提示，可重试或下载 |
| 快速连续拖动 | 仅最后一次生效，过期加载被丢弃 |
| seek 目标超过总时长 | 钳制到末尾附近，不报错 |
| 全屏中播放失败/切换文件 | 先退出全屏再走既有失败/切换语义 |
| 浏览器无 Fullscreen API（部分旧浏览器/WebView） | 隐藏「全屏」入口，「网页全屏」不受影响 |
| iOS Safari（无 MSE） | 维持现态降级：不创建播放器，仅提示 + 下载按钮 |
| 本地 dev 代理不透传 Range | 探测失败按「不支持拖动进度」降级并明示（实现期需复验代理透传行为） |

## 四、非功能需求

### 4.1 性能

- seek 不得触发整文件从头缓冲：未缓冲跳转必须基于 Range 从目标偏移附近重新拉流；
- 连续拖动不并发堆积请求（单例 player + 代次丢弃语义沿用）；
- 全屏切换为纯布局/合成层变化，不重载媒体流。

### 4.2 安全性

- 无新增网络面与数据面；对第三方依赖的本地补丁（如采用）必须锁定版本、内容可评审，并随依赖升级复核。

### 4.3 兼容性

- seek 修复不改变 MSE 依赖面：支持范围与现态一致（现代桌面与 Android Chrome；iOS Safari 降级）；
- Fullscreen API 按能力检测渐进增强；「网页全屏」纯 CSS 全覆盖现代浏览器。

## 五、依赖与约束

### 5.1 依赖

- 上游录播服务保持 Range 支持（`206` + `Accept-Ranges: bytes`，2026-09-15 实测通过 CDN 与源站均可）；
- 上游 FLV 元数据维持现状（`onMetaData` 含 `duration`、无关键帧索引）；录播列表 API 继续提供文件 `size`（seek 偏移估算依赖 size 与 duration）。

### 5.2 约束

- 仅改动 `apps/bookstore`（允许新增依赖补丁文件），不动 `servers/api`、契约与编排资源；
- 遵循 `docs/engineering/frontend-rules.md` 与 TDD（先测试后实现）；
- 分支命名 `<type>/<slug>`：`prd/recordings-seek-fullscreen` 需求总分支，禁 rebase/squash；
- 实现 PR 内同步 `docs/product/spec/site-pages.md`（F5 节）与 `docs/engineering/spec/frontend-bookstore.md`（录播节）。

## 六、后续可能（本期不做）

- 推动上游在录制完成后为 FLV 注入关键帧索引（如 flvmeta/yamdi post-process），届时前端可切换为精确 seek 并简化兜底逻辑；
- 键盘快捷键（←/→ 微调、空格播放暂停、F 全屏）；
- 倍速播放、画质/音轨选择；
- 记住上次播放位置。
