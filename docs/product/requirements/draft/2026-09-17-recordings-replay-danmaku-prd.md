# 录播回放弹幕支持（Recordings Replay Danmaku）

**功能名称**: 录播回放弹幕支持（Recordings Replay Danmaku）
**PRD 版本**: v1.0
**创建日期**: 2026-09-17
**作者**: sumire workflow

## 一、背景与目标

### 1.1 背景

录播页 `/recordings` 已上线并历经两期优化（2026-09-14 录播页、2026-09-15 播放优化一期），现态见 `docs/product/spec/site-pages.md`「录播页 `/recordings`」节：点击文件项（或「播放」按钮）在文件项下方**内联展开** FLV 播放器，支持进度跳转、全屏与网页全屏，但只有纯视频画面——直播当时的弹幕、醒目留言、礼物、上船等互动事件全部丢失，回看体验与直播氛围脱节。

站内已具备弹幕事件的完整数据通路：后台弹幕看板经 `GET /api/live-events` 代理内网事件服务，归一化为稳定 `LiveEvent` 模型（契约 `contract/live-events.openapi.yaml`），事件携带 `occurredAt`（发生时间），可与录播文件的时间轴对齐。

### 1.2 目标

- 录播「播放」从内联展开改为**打开独立回放页** `/recordings/replay`，专注单场次回看；
- 回放页呈现「左视频 + 右事件列表 + 视频漂浮弹幕」三要素：16:9 视频在左，弹幕事件在右侧竖向滚动并随播放进度同步，弹幕类事件以浮层形式飘过视频画面；
- 支持**网页全屏**（视频 + 浮层弹幕 + 竖向事件列表整体铺满视口）与**全屏**（仅视频 + 浮层弹幕进入系统全屏）；
- 弹幕事件对匿名访客可见（与录播页一致的公开定位）。

### 1.3 成功标准

- [ ] 录播列表点击「播放」/文件名不再内联展开播放器，而是打开 `/recordings/replay` 回放页回看该场录播；
- [ ] 回放页左侧播放 16:9 视频，右侧弹幕事件列表竖向滚动并随播放进度自动定位，视频画面上有与播放进度同步的漂浮弹幕；
- [ ] 网页全屏将视频、浮层弹幕、事件列表整体铺满视口；全屏仅保留视频与浮层弹幕；两种模式互斥且可退出还原；
- [ ] 未登录访客可正常回看并看到弹幕事件；
- [ ] 既有录播列表、下载、听直播、seek 与降级行为零回归。

## 二、用户分析

### 2.1 目标用户

- 站点访客（未登录）：错过直播、希望「补档」的主播观众。弹幕互动是直播体验的核心部分，纯视频回看丢失了大量上下文（主播在读哪条弹幕、当时的名场面反应）。

### 2.2 用户场景

| 场景 | 用户角色 | 目标 | 痛点（现况） |
|------|----------|------|------|
| 补档整场直播 | 访客 | 像看直播一样回看，弹幕随画面飘过 | 只有纯视频，主播对着空气说话 |
| 定位名场面 | 访客 | 通过弹幕/SC 事件找到精彩片段 | 无任何事件线索，只能盲拖进度条 |
| 大屏沉浸回看 | 访客 | 全屏看画面与弹幕，或网页全屏同时看事件列表 | 现态全屏只有画面，无弹幕无事件 |

## 三、功能需求

### 3.1 功能概述

本期包含前后端两侧变更：

- **前端**：新增公开回放页 `/recordings/replay`（独立路由，参数携带直播间与文件名）；改造录播列表「播放」入口指向回放页；回放页含视频播放区（复用既有 mpegts.js 播放与近似 seek 能力）、漂浮弹幕层、事件列表与全屏控制；
- **后端**：`live-events` 域新增**公开**回放事件检索端点，按时间区间返回归一化事件（不含已读状态、不含罗马音），供回放页按播放进度增量取数；契约 `contract/live-events.openapi.yaml` 同步更新。

> **评审决策点（公开性）**：现态弹幕事件仅登录 member 及以上可见（弹幕看板为后台功能）。本需求将历史弹幕事件以「回放配套数据」形态对匿名访客公开（不含已读状态等后台语义），与录播页本身的公开定位一致。如评审认为弹幕发送者信息不宜公开，则降级为「回放页事件区仅登录可见」，其余功能不变——请在评审时确认。

### 3.2 功能列表

#### F1 回放页路由与列表入口改造

**描述**:

- 新增独立路由页 `/recordings/replay`（置于 `(site)/(content)` 路由组，获得 NavBar + Footer 外壳），查询参数：`roomId`（直播间 ID）与 `file`（录播文件名），两者缺失/非法时展示「参数无效」空态并给回录播页链接，不报错；
- 录播列表的播放入口行为变更：点击「播放」主按钮或文件项文件名，**不再内联展开播放器**，而是打开回放页回看该文件（`target="_blank"` 新标签页打开，保留列表上下文；`rel="noopener noreferrer"`）；
- 文件项下方内联手风琴播放器整体退场（含其内联展开/折叠、单例互斥逻辑）；「下载」下拉菜单与行为完全不变；
- 录播服务未配置（`RECORDINGS_CONFIGURED` 为 false）时导航无「录播」入口、回放页展示「服务未配置」空态，与现态口径一致。

**验收标准**:

- [ ] 点击「播放」/文件名在新标签页打开 `/recordings/replay?roomId=:roomId&file=:fileName`，回放页加载并播放对应录播；
- [ ] 录播列表不再出现内联展开的播放器；「下载」入口与行为不变；
- [ ] 缺 `roomId`/`file`、文件不存在（列表中查不到）时回放页展示明确空态与返回链接；
- [ ] 既有用例零回归（分组折叠、分页、听直播、下载）。

#### F2 回放页布局：视频 + 事件列表 + 漂浮弹幕

**描述**:

- 页面主体为回放舞台：左侧 16:9 视频播放区（黑底），右侧为弹幕事件竖向滚动列表；桌面端左右并排（视频约占 2/3 宽），移动端上下堆叠（视频在上、事件列表在下）；
- 视频播放区控制条沿用现态能力：播放/暂停、音量、进度条（近似 seek 语义不变）、当前时间/总时长、全屏入口（见 F4）；播放失败、MSE 降级（iOS 等）、上游 Range 不可用的降级口径与现态一致；
- **漂浮弹幕**：弹幕（danmaku）类事件按其发生时间映射到视频时间轴，在播放到达对应时间点时从画面右侧向左侧飘过（参照 B 站滚动弹幕形态）；播放/暂停/跳转时弹幕调度同步（暂停即悬停、跳转即重建当前窗口弹幕）；浮层不遮挡控制条操作；
- **事件列表**：展示该场录播时间区间内的全部四类事件（弹幕/SC/礼物/上船），按发生时间**升序**排列，条目视觉复用弹幕看板既有样式（发送者、牌子、内容、SC 配色、礼物/上船信息），但不展示已读状态与已读操作（公开页无登录态语义）；
- 列表随播放进度**自动滚动**定位到当前时间点附近的事件（当前事件高亮）；用户手动滚动后暂停自动跟随，提供「回到当前进度」入口恢复跟随；点击列表中某条事件，视频跳转到该事件对应的时间点附近续播；
- 事件数据按播放位置附近的时间窗口增量加载（详见技术提案），加载失败时事件区展示错误态与「重试」，不影响视频播放。

**验收标准**:

- [ ] 桌面端左视频右列表、移动端上视频下列表，视频保持 16:9 比例；
- [ ] 播放时弹幕从右向左飘过画面，暂停时弹幕悬停，拖动进度条后弹幕与画面时间点一致；
- [ ] 事件列表按时间升序展示四类事件，播放中自动滚动跟随并高亮当前事件；手动滚动后停止跟随，点击「回到当前进度」恢复；
- [ ] 点击事件条目，视频跳转到对应时间点附近播放（走既有近似 seek 路径）；
- [ ] 弹幕表情（emote）在浮层与列表中均以图片渲染；
- [ ] 事件加载失败仅事件区展示错误与重试，视频播放不受影响；
- [ ] 该场录播时间区间内无事件时，事件区展示「本场直播暂无弹幕事件」空态，浮层无弹幕，视频正常播放。

#### F3 回放事件公开 API

**描述**:

- `live-events` 域新增公开端点 `GET /api/live-events/replay`（无需登录），按时间区间检索归一化直播事件：
  - 参数：`start`/`end`（必填，ISO 时间戳，`end > start`，区间长度上限 12 小时）、`type`（可重复，仅 danmaku/super_chat/gift/guard_buy 四类，缺省全部）、`page`/`pageSize`（分页，pageSize 上限 100）；
  - 响应：分页信封，`items` 为归一化事件，按 `occurredAt` **升序**；条目**不含** `read`（无已读语义）、**不含**罗马音字段（公开页不需要，避免标注开销）；online_rank_count 不属于本端点（非法 type 400）；
  - 上游不可达/超时/返回非法时 502；参数非法（缺 start/end、格式错误、end ≤ start、区间超上限、type 非法、分页非法）400；
- 服务端可对该端点做短 TTL 缓存（时间区间 + 类型 + 页码为键），历史区间数据不可变，缓存安全；
- 契约 `contract/live-events.openapi.yaml` 为单一事实源，实现与 `tests/api` 集成测试以其为准。

**验收标准**:

- [ ] 匿名调用 `GET /api/live-events/replay?start=…&end=…` 返回 200，items 按 occurredAt 升序且全部落在区间内；
- [ ] 条目无 `read`/`nameRomaji`/`contentRomaji` 字段，其余归一化字段（eventId/sender/content/emote/price/scColors/gift/guard 等）与既有口径一致；
- [ ] 参数非法返回 400，上游失败返回 502；区间超过 12 小时返回 400；
- [ ] `tests/api` 覆盖 200/400/502 与字段裁剪断言。

#### F4 网页全屏与全屏

**描述**:

- 回放舞台提供两个入口：「网页全屏」「全屏」，置于视频控制条右侧（沿用现态位置与图标风格）；
- **网页全屏**：整个回放舞台（视频 + 浮层弹幕 + 竖向事件列表）铺满浏览器视口，页面其余内容不可见、背景滚动锁定；事件列表在网页全屏下保持可滚动、可点击跳转；
- **全屏**：经 Fullscreen API 仅将「视频 + 浮层弹幕」容器进入系统全屏，事件列表不进入；控制条在全屏态保持可用；
- 两种模式互斥（进入其一先退出另一个）；ESC/按钮退出并还原布局；`fullscreenchange` 系统事件同步按钮态；浏览器不支持 Fullscreen API 时隐藏「全屏」入口（网页全屏为纯 CSS 实现，不受影响）；
- 全屏/网页全屏中弹幕浮层与事件列表的同步行为不间断。

**验收标准**:

- [ ] 点击「网页全屏」后视频、浮层弹幕、事件列表整体铺满视口，背景不可滚动，退出后还原；
- [ ] 点击「全屏」后仅视频与浮层弹幕占满屏幕，控件可操作，ESC 或退出按钮还原且按钮态复位；
- [ ] 两种模式互斥切换不叠加；网页全屏下事件列表可滚动、可点击跳转；
- [ ] 无 Fullscreen API 的环境隐藏「全屏」入口；移动端视口下「网页全屏」可用。

### 3.3 页面/界面描述

- 整体遵循 `docs/design/02-page-design.md`：深色雨夜书屋基调，内容区居中，焦点环 `--color-flower`，交互元素键盘可达；
- 页面结构自上而下：页面标题「录播回放」+ 场次信息（文件名/直播间/创建时间）→ 回放舞台（视频 + 事件列表）→ 操作区（下载该场录播、返回录播列表）；
- 漂浮弹幕视觉：白色描边文字（参照 B 站滚动弹幕），匀速从右向左，多轨道避免重叠，同屏密度有上限；SC/礼物/上船事件**不**进入浮层，仅出现在事件列表；
- 事件列表为深色卡片流，当前进度事件以 `--color-flower` 高亮描边；空态、加载中、错误态文案风格与站内既有语义一致。

### 3.4 异常与边界情况

| 情况 | 预期行为 |
|------|----------|
| `roomId`/`file` 参数缺失或非法 | 回放页展示「参数无效」空态 + 返回录播页链接，不发请求 |
| 文件在录播列表中不存在（已删除/参数伪造） | 回放页展示「录播不存在或已删除」空态 |
| 事件 API 502 / 网络失败 | 事件区错误态 + 重试；视频播放与浮层（已加载部分）不受影响 |
| 录播时间区间内无任何事件 | 事件区空态文案，浮层无弹幕，视频正常播放 |
| 播放头领先于已加载事件窗口 | 浮层仅展示已加载部分，后台继续按窗口加载；不出现「弹幕突然全部消失/闪现」 |
| seek 到未加载事件的区间 | 立即清空浮层弹幕并加载目标区间事件，加载完成后弹幕按新时间点出现 |
| 录制文件时间锚点与事件时间存在秒级漂移 | 可接受（文件创建时间 ≈ 录制开始时间）；不做跨文件级精校准 |
| iOS Safari（无 MSE） | 回放页播放区降级为「不支持在线播放，请下载后收听」+ 下载按钮；事件列表仍正常展示（纯文本数据不依赖 MSE） |
| 单场弹幕量极大（数万条） | 按时间窗口增量加载 + 列表随窗口渲染，不一次性拉全量 |
| 快速连续拖动进度条 | 浮层调度与事件窗口加载均以最后一次落点为准（last-wins），不堆积过期请求 |
| 离开回放页 | 播放器销毁断流、事件加载中止，无残留请求 |

## 四、非功能需求

### 4.1 性能

- 事件按时间窗口增量取数（默认窗口 ≤ 10 分钟），单次请求 pageSize ≤ 100 并分页，禁止整场次一次性拉取；
- 漂浮弹幕渲染用 canvas（避免大量 DOM 节点动画），同屏弹幕数设上限（如 50 条），超出丢弃最早批次；
- 事件窗口数据客户端缓存（Map，key 为窗口起点），seek 往返不重复请求；
- 服务端对 replay 端点做短 TTL 缓存，避免同一区间被多访客重复回源上游。

### 4.2 安全性

- 回放事件端点公开只读，但响应剔除 `read`/罗马音等后台语义字段；上游地址仍收敛在服务端，不出现在客户端；
- `start`/`end`/`type`/分页参数服务端严格校验（区间上限 12 小时，防大范围扫库拉取）；`roomId`/`file` 前端仅作路径编码拼接；
- 事件内容（弹幕文本、昵称）渲染按纯文本/图片 URL 处理，不注入 HTML。

### 4.3 兼容性

- 视频播放依赖 MSE，支持范围与现态一致（现代桌面与 Android Chrome；iOS Safari 降级但事件列表可用）；
- canvas 弹幕渲染与 Fullscreen API 按能力检测渐进增强；桌面与移动端断点遵循 `docs/design/02-page-design.md`。

## 五、依赖与约束

### 5.1 依赖

- 录播服务四组端点行为不变；录播文件列表 API 继续提供 `createdAt` 与 `size`（时间锚点与 seek 估算依赖）；
- 内网事件服务 `event/range` 持续可用且事件携带 `occurredAt`；其是否支持时间区间参数由实现期实测（不支持时服务端分页扫描 + 区间内过滤兜底，见技术提案）；
- 录播文件时间锚点 = 文件 `createdAt`（≈ 录制开始时间），与事件 `occurredAt` 同上游时钟。

- 遵循 `docs/engineering/frontend-rules.md` / `backend-rules.md` 与 TDD（先测试后实现）；
