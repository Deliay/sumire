# 录播播放优化

**功能名称**: 录播播放优化（Recording Playback Optimization）
**PRD 版本**: v1.0
**创建日期**: 2026-09-18
**作者**: sumire workflow

## 一、背景与目标

### 1.1 背景

回放页 `/recordings/replay` 已上线（2026-09-17 录播回放弹幕需求），播放器（`FlvPlayerPanel`）现态为**挂载即自动播放**（mpegts.js 创建后立即 `play()`，带声音），页面布局为 `max-w-7xl` 容器 + 桌面端左视频 3/4 宽、右弹幕事件列 1/4 宽且固定 `70vh` 高（现态行为见 `docs/product/spec/site-pages.md` 回放页节、`docs/engineering/spec/frontend-bookstore.md` 录播节）。

现态问题：

- 浏览器自动播放策略限制：在用户与页面发生首次交互前，**带声音的自动播放会被拦截**，播放器进入失败/卡住状态，用户看到的是一个没有反应的画面，必须手动点控制条的播放按钮才能恢复；
- 即便自动播放成功，用户打开回放页时未必希望立即出声，默认播放是侵略性体验；
- 视频画面本身不可点击，播放/暂停只能在控制条的小按钮上完成，热区小、不符合视频站直觉；
- 回放页左右仍各有一层留白（`px-2.5 lg:px-5`），视频实际可用宽度被进一步压缩；
- 弹幕事件列固定 `70vh` 高，与播放器（16:9 推导高度 + 控制条，约 600px）不齐高，视觉上右列明显长出一截，播放器在页面中的占比偏小。

### 1.2 目标

- 回放页播放器**默认暂停态**：加载完成后画面就绪但不播放，不再尝试带声音的自动播放；
- 视频画面叠加**播放按钮 overlay**：暂停时画面中央展示播放按钮，点击画面任意区域即可播放/暂停；
- 回放页**左右留白进一步收窄**，**弹幕事件列高度与播放器相同**，并**适度增大播放器占整体页面的面积**。

### 1.3 成功标准

- [ ] 打开回放页后播放器加载完成但处于暂停态，画面中央展示播放按钮 overlay，浏览器控制台无自动播放拦截错误；
- [ ] 点击视频画面（含 overlay）在播放/暂停间切换，与控制条播放按钮状态始终一致；
- [ ] 桌面端弹幕事件列与播放器（含控制条）等高，页面左右留白小于现态；
- [ ] 桌面端视频宽度占比大于现态 3/4，移动端布局零回归；
- [ ] 既有回放页行为（漂浮弹幕、事件列表跟随/seek、双全屏、进度条 seek、MSE 降级）零回归。

## 二、用户分析

### 2.1 目标用户

- 站点访客（未登录）：回听/回看录播的主播观众。

### 2.2 用户场景

| 场景 | 用户角色 | 目标 | 痛点（现况） |
|------|----------|------|------|
| 打开回放页开始观看 | 访客 | 画面就绪后自己决定何时播放 | 自动播放被浏览器拦截，画面卡住或突然出声 |
| 播放中临时暂停 | 访客 | 随手点一下画面暂停 | 只能瞄准控制条小按钮，热区小 |
| 桌面端边看的弹幕边回顾事件 | 访客 | 视频与事件列表视觉对齐 | 事件列比播放器高一截，页面留白多、视频偏小 |
| 移动端观看回放 | 访客 | 单手点击画面控制播放 | 画面不可点击，控制条按钮触控困难 |

## 三、功能需求

### 3.1 功能概述

本期仅改动回放页 `/recordings/replay` 的播放器面板与页面布局（`FlvPlayerPanel` / `ReplayStage` / `ReplayApp` / `player.ts`）：F1 将播放器从「挂载即自动播放」改为「默认暂停 + 画面 overlay 点击播放/暂停」；F2 调整页面留白、列宽比与事件列高度。不涉及录播列表页、弹幕浮层逻辑、事件取数、seek、全屏状态机、API 与契约，均为纯前端变更。

### 3.2 功能列表

#### F1 播放器默认暂停与画面点击播放/暂停

**描述**:

- 播放器初始化完成后**不再自动播放**：流加载、画面就绪，但保持暂停态（`paused`），不出声、不消耗解码资源；不再触发浏览器的自动播放拦截；
- 视频画面上叠加**播放按钮 overlay**：
  - 播放器处于暂停态（含初始就绪态）时，画面中央展示一个醒目的播放按钮（三角形播放图标，带半透明深色圆形底板，样式遵循设计规范 token 色）；
  - 播放器处于播放态时 overlay 隐藏（或仅在 hover/暂停时重现，以实现评审为准），不遮挡画面内容；
  - 播放失败、MSE 不支持降级等既有异常态的展示不受影响（overlay 不与错误提示叠加冲突）；
- **点击视频画面任意区域**（含 overlay 本身，但不含控制条与弹幕浮层）在播放/暂停间切换，行为与控制条播放/暂停按钮完全等效（同一状态通路）；
- 弹幕浮层（canvas）保持 `pointer-events-none`，画面点击事件落在视频容器上，不受浮层遮挡影响；
- 全屏（web 全屏与 native 全屏）下点击画面播放/暂停与 overlay 行为保持一致。

**验收标准**:

- [ ] 打开回放页（带合法 `roomId`/`file` 参数）后，视频加载完成但处于暂停态，画面中央展示播放按钮 overlay；
- [ ] 首次交互前无自动播放行为，不出现浏览器自动播放拦截导致的失败提示；
- [ ] 点击画面（含 overlay）开始播放，overlay 隐藏；再次点击画面暂停，overlay 重现；
- [ ] 控制条播放/暂停按钮与画面点击共享同一状态：任一入口操作后，另一入口的图标/aria-label 同步；
- [ ] 播放中点击弹幕浮层区域（canvas）同样触发暂停（浮层不吞事件）；
- [ ] 点击控制条、进度条、音量、全屏按钮等区域不触发画面点击的播放/暂停切换；
- [ ] web 全屏与 native 全屏下，画面点击播放/暂停与暂停态 overlay 均可用；
- [ ] MSE 不支持（iOS Safari）时仍展示既有下载降级提示，不展示播放 overlay；
- [ ] 既有用例零回归（seek、音量、全屏三态、事件列表联动、漂浮弹幕暂停跟随）。

#### F2 回放页布局优化（留白收窄 / 事件列等高 / 播放器占比增大）

**描述**:

- 回放页容器**左右留白进一步收窄**（现态 `px-2.5 lg:px-5`，收窄幅度以设计评审为准，移动端保持最小可用留白）；
- 桌面端**弹幕事件列高度与播放器相同**：事件列不再使用固定 `70vh` 高度，改为与播放器列（视频 16:9 画面 + 控制条）等高，列表内容超出时在列内滚动（沿用既有虚拟化滚动容器）；
- 桌面端**播放器占用面积适度增大**：视频列宽度占比在现态 3/4 的基础上小幅提升（事件列相应收窄但保持可读，具体比例以设计评审为准）；
- 移动端（窄屏堆叠布局）行为不变：视频全宽在上，事件列在下；
- 全屏（web/native）布局不受本期改动影响。

**验收标准**:

- [ ] 桌面端（`lg` 断点）回放页左右 padding 小于现态 `lg:px-5`，页面内容不触碰视口边缘（保留最小留白）；
- [ ] 桌面端事件列可视高度与播放器列（画面 + 控制条）一致，事件列表在列内滚动且跟随/seek 行为不变；
- [ ] 桌面端视频宽度占比大于现态 `lg:w-3/4`，事件列文字（时间、内容、礼物/SC 金额）不换行错乱、不被截断；
- [ ] 移动端（`<lg` 断点）布局与现态一致：视频全宽、事件列纵向排布；
- [ ] web 全屏下舞台铺满、事件列在侧可命中（既有 e2e 断言零回归）；
- [ ] 空态/加载态/错误态容器与正常态留白口径一致。

### 3.3 页面/界面描述

- 播放按钮 overlay：居中于视频画面，半透明深色圆形底板 + 播放三角图标（`lucide-react` 既有依赖），色值使用 `app/globals.css` 既有 token（`--color-flower` 等），禁止硬编码色值；暂停时展示、播放时隐藏；氛围动效尊重 `prefers-reduced-motion`；
- overlay 之上仍叠加既有弹幕浮层（canvas，`pointer-events-none`），两者层级互不遮挡：弹幕永远可见，播放按钮在其下方居中；
- 布局调整后的回放页遵循 `docs/design/02-page-design.md` 与现态深色视觉：页面容器、舞台、事件列的描边/圆角/背景不变，仅尺寸与留白变化。

### 3.4 异常与边界情况

| 情况 | 预期行为 |
|------|----------|
| 浏览器完全不支持 MSE | 既有「不支持在线播放，请下载后收听」降级，不展示 overlay |
| 流加载失败 | 既有失败提示，不展示 overlay；重试后回到默认暂停态 |
| 用户点击画面后立即切换文件/离开页面 | 全局单例播放器既有销毁逻辑不变，无残留播放 |
| 播放中进入 web 全屏 | 保持播放，overlay 不闪现；全屏内点击画面可暂停 |
| 暂停态进入/退出全屏 | 保持暂停态，overlay 正常展示 |
| 窗口从桌面宽度缩至移动端断点 | 事件列回归纵向排布，无固定高度约束破坏 |
| 事件数量极少（不足一屏） | 事件列仍与播放器等高，列表顶部对齐，不拉伸条目 |
| 键盘操作 | 控制条按钮键盘可达不变；画面点击为指针增强交互，不作为唯一通路 |

## 四、非功能需求

### 4.1 性能

- 默认暂停态下不启动解码播放，首屏资源消耗不高于现态；
- 布局调整仅为 Tailwind 类与 flex 约束变更，无新增运行时依赖与请求。

### 4.2 安全性

- 无新输入面；回放页参数校验、事件取数等既有安全面不变。

### 4.3 兼容性

- overlay 与点击交互仅使用既有浏览器能力；桌面与移动端断点表现遵循 `docs/design/02-page-design.md`；
- 键盘与屏幕阅读器通路不受影响（控制条按钮保持 `aria-label` 与焦点环 `--color-flower`）。

## 五、依赖与约束

### 5.1 依赖

- 回放页现态（`docs/product/spec/site-pages.md` 回放页节）与录播服务四组端点行为不变；
- 全局单例播放器（`features/recordings/player.ts`）的 `pausePlayer`/`resumePlayer`/归属订阅机制既有可用。

### 5.2 约束

- 仅改动 `apps/bookstore` 前端（含单测/e2e），不动 `servers/api`、契约与编排资源配置；
- 遵循 `docs/engineering/frontend-rules.md` 与 TDD（先测试后实现）；
- 分支命名 `<type>/<slug>`：`prd/recordings-play-optimization` 需求总分支，禁 rebase/squash；
- 实现 PR 内同步 `docs/product/spec/site-pages.md` 与 `docs/engineering/spec/frontend-bookstore.md`（`site-pages.md` 回放页布局描述与代码的既有脱节一并修正）。
