# 棉花糖编辑器工具栏精简与默认实时预览

**功能名称**: 棉花糖编辑器工具栏精简与默认实时预览（Marshmallow Editor Toolbar Trim & Default Live Preview）
**PRD 版本**: v1.0
**创建日期**: 2026-11-01
**作者**: sumire workflow

## 一、背景与目标

### 1.1 背景

棉花糖（提问箱）域使用统一的 Markdown 编辑器组件（`apps/bookstore/features/markdown/MarkdownEditor.tsx`，基于 `@uiw/react-md-editor`），在两处挂载：

1. **公开收集页**（`/topics?id={topicId}`）：访客投递棉花糖（提问/留言）；
2. **后台主题表单**（`/backdoor/topics` 新建/修改主题弹窗）：管理员撰写主题描述。

编辑器当前使用库的默认工具栏，包含「代码块」「图片」「代码」「link（链接）」四个按钮（及对应键盘快捷键）。对提问箱场景而言这四类能力并不合适：

- 提问箱定位是**匿名文字投递**（提问/祝福/留言），代码与代码块不是目标表达形式；
- 「图片」依赖外部图床链接，匿名场景下是不良内容与跟踪像素的注入面，也超出 AI 文本审核的覆盖面；
- 「link」按钮易被用于引流与垃圾信息（匿名限速仅控制频率，不控制内容形态）；
- 工具栏按钮越多，访客（多数只输入一句提问）的认知负担越大。

此外，编辑器当前默认进入「Edit code」纯编辑模式，输入 Markdown 时看不到排版效果，访客与管理员都需要手动切换才能边写边看（追加需求）：**默认预览模式改为「Live code」**（编辑 + 预览分屏实时预览）。

### 1.2 目标

- 编辑器工具栏中不再出现「代码块」「图片」「代码」「link」四个按钮；
- 四个按钮对应的键盘快捷键（Ctrl/Cmd+J、Ctrl/Cmd+Shift+J、Ctrl/Cmd+L、Ctrl/Cmd+K）同步失效；
- 编辑器默认预览模式改为「Live code」（编辑 + 预览分屏实时预览），用户仍可手动切换 Edit code / Live code / Preview code 三种模式；
- 其余工具栏按钮（加粗/斜体/删除线/标题/引用/列表/表格等）与编辑、预览行为零回归；
- 后台主题描述与公开投递两处编辑器口径保持一致（同一共享组件）。

### 1.3 成功标准

- [ ] 公开收集页编辑器工具栏不含「代码块」「图片」「代码」「link」四个按钮（按按钮 `aria-label` 断言）；
- [ ] 后台主题表单编辑器工具栏同样不含该四个按钮；
- [ ] 四个按钮对应的快捷键不再插入对应 Markdown 语法，其余快捷键（如 Ctrl/Cmd+B 加粗）不受影响；
- [ ] 两处编辑器默认以「Live code」模式打开（编辑区 + 预览区分屏实时渲染）；
- [ ] 视图切换按钮（Edit code / Live code / Preview code）仍可手动切换模式，切换行为不变；
- [ ] 只读态（提交中/主题未开始/已结束）仍为纯预览（Preview code），行为不变；
- [ ] 其余工具栏按钮功能不变（加粗/斜体/删除线/标题/引用/列表/表格/帮助等）；
- [ ] 既有含链接/图片/代码的历史内容渲染零回归（`MarkdownView` 不变）。

## 二、用户分析

### 2.1 目标用户

- 站点访客（未登录）：在公开收集页投递棉花糖的用户；
- 后台管理员（admin）：新建/修改主题描述的用户。

### 2.2 用户场景

| 场景 | 用户角色 | 目标 | 痛点（现况） |
|------|----------|------|------|
| 投递棉花糖 | 访客 | 快速输入一段文字提问/留言 | 工具栏中代码/图片/链接按钮与文字提问无关，徒增干扰 |
| 撰写主题描述 | 管理员 | 用文本排版描述主题 | 不需要代码块与图片/链接能力，多余按钮增加表单复杂度 |
| 边写边看排版 | 访客 / 管理员 | 输入 Markdown 时直观看到渲染效果 | 默认「Edit code」纯编辑模式看不到排版效果，需手动切换模式 |

## 三、功能需求

### 3.1 功能概述

本期包含两项变更，均在共享的 `MarkdownEditor` 组件一处收敛，两处使用点（后台主题描述、公开投递）口径一致：

1. **F1 工具栏精简**：把编辑器工具栏中的「代码块」「图片」「代码」「link」四个按钮移除（含对应键盘快捷键），其余按钮、编辑与预览行为不变；
2. **F2 默认实时预览**：编辑器默认预览模式从「Edit code」（纯编辑）改为「Live code」（编辑 + 预览分屏实时预览）。

纯前端变更：无 API、无契约、无数据库变更。

### 3.2 功能列表

#### F1 移除「代码块」「图片」「代码」「link」工具栏按钮

**描述**:

- 编辑器工具栏不再渲染以下四个按钮（`@uiw/react-md-editor` 默认命令）：
  - 「代码」（行内代码，`code`，快捷键 Ctrl/Cmd+J）；
  - 「代码块」（`codeBlock`，快捷键 Ctrl/Cmd+Shift+J）；
  - 「link」（插入链接，`link`，快捷键 Ctrl/Cmd+L）；
  - 「图片」（插入图片，`image`，快捷键 Ctrl/Cmd+K）；
- 四个命令的键盘快捷键与工具栏按钮同源移除（按钮消失后快捷键也不再插入对应语法）；
- 其余工具栏按钮保持默认顺序与样式，不做增删与重排；
- 公开收集页与后台主题表单两处编辑器行为一致（共享组件统一生效）。

**验收标准**:

- [ ] 公开收集页（form 态）编辑器工具栏不含上述四个按钮；
- [ ] 后台主题表单（新建/修改）编辑器工具栏不含上述四个按钮；
- [ ] 在编辑器内按 Ctrl/Cmd+J、Ctrl/Cmd+Shift+J、Ctrl/Cmd+L、Ctrl/Cmd+K 不插入任何语法；
- [ ] 其余按钮（加粗/斜体/删除线/标题/引用/列表/表格/帮助等）仍渲染且点击行为不变；
- [ ] 只读态（提交中/未开始/已结束）沿用既有「隐藏工具栏」口径，不受影响。

#### F2 默认预览模式改为 Live code

**描述**:

- 编辑器（非只读态）默认以「Live code」模式打开：左侧编辑区 + 右侧预览区分屏，输入即时渲染（`@uiw/react-md-editor` 的 `live` 视图，即工具栏「Live code」按钮对应的模式）；
- 当前默认为「Edit code」（纯编辑），本期仅改默认值；
- 视图切换按钮（Edit code / Live code / Preview code）与快捷键（Ctrl/Cmd+7 / 8 / 9）保留，用户仍可手动切换三种模式；
- 只读态（提交中/主题未开始/已结束）维持纯预览（Preview code）不变；
- 公开收集页与后台主题表单两处编辑器默认模式一致（共享组件统一生效）。

**验收标准**:

- [ ] 公开收集页（form 态）编辑器默认为 Live code 分屏（编辑区 + 预览区同时可见，输入即时渲染）；
- [ ] 后台主题表单（新建/修改）编辑器默认为 Live code 分屏；
- [ ] 手动点击 Edit code / Live code / Preview code（或 Ctrl/Cmd+7/8/9）可正常切换模式；
- [ ] 只读态仍为纯预览（无编辑区），不受影响。

### 3.3 页面/界面描述

- 工具栏仅减少四个按钮，按钮样式、间距、移动端横向滚动口径均不变；
- 移除后若出现相邻分隔符连排等视觉瑕疵，允许在实现评审中微调收敛（不引入新视觉规范）；
- 默认 Live code 模式下编辑区与预览区分屏展示（分屏布局沿用库默认），编辑器高度口径（编辑区最小高 10rem/12rem）与拖拽调高、字数提示等既有元素不变；
- 预览区实时渲染 Markdown（与 `MarkdownView` 展示口径一致的常规排版）。

### 3.4 异常与边界情况

| 情况 | 预期行为 |
|------|----------|
| 历史内容含链接/图片/代码 | 仍按现态正常渲染（本期不动 `MarkdownView` 渲染层） |
| 用户手工键入 Markdown 语法（如 `![](url)`） | 仍可输入并渲染（本期仅移除工具栏入口与快捷键，不做语法级封锁） |
| 粘贴含链接/图片的文本 | 保持原样粘贴（同上，不做内容过滤） |
| 快捷键与其他命令冲突 | 仅上述四个快捷键失效；其余命令快捷键（加粗、模式切换等）不受影响 |
| 用户手动切换视图模式 | 本次编辑会话内保持所选模式；重新打开页面/弹窗回到默认 Live code |
| 只读态（提交中/主题未开始/已结束） | 维持纯预览（Preview code），不因本需求变化 |
| 窄屏（移动端/弹窗内）分屏拥挤 | 沿用库默认分屏表现；如评审认为需要，移动端默认单列策略列入后续（见第六节） |

## 四、非功能需求

### 4.1 性能

- 无新增依赖；命令过滤为渲染期常量比较，无运行时开销；SSG 输出不变。

### 4.2 安全性

- 收窄匿名投递的外链/外链图片注入面（辅助 AI 文本审核），降低引流与跟踪像素滥用的便利性；
- 注意：这是**入口级收敛**而非内容级封锁，不构成安全边界（手输语法仍可插入），安全兜底仍以 AI 审核与内容复核为准。

### 4.3 兼容性

- 依赖 `@uiw/react-md-editor` 4.x 的工具栏命令过滤 API；库升级大版本时需复核过滤口径；
- 两处使用点共用同一组件，行为同步变化，无兼容分支。

## 五、依赖与约束

### 5.1 依赖

- 无新增依赖（`@uiw/react-md-editor` 既有）。

### 5.2 约束

- 仅改动 `apps/bookstore` 前端；不动 API、契约与编排；
- 遵循 `docs/engineering/frontend-rules.md` 与 TDD（先补 `MarkdownEditor` 单元测试再实现）；
- 分支命名 `prd/<slug>` 需求总分支，禁 rebase/squash。

## 六、后续可能（本期不做）

- 移动端/窄屏默认单列策略（Live code 分屏在窄屏的默认形态优化）；
- 语法级内容过滤：粘贴/手输的图片、链接语法不渲染（需评估历史内容兼容与误伤）；
- 工具栏按场景差异化配置（主题描述与投递两处独立口径，如有需要再拆）；
- 「注释（comment）」「表格（table）」等剩余按钮是否按提问箱场景进一步收敛；
- 投递内容的链接自动识别与安全提示。
